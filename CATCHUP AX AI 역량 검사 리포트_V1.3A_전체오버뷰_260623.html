입력 파일, 저장 위치와 시트명 등 작업 조건을 구체적으로 전달해 AI가 데이터를 처리하는 환경을 명확하게 설정했습니다. 파일 경로와 결과 저장 위치를 정확히 지정한 점은 작업 흐름을 안정적으로 유지하는 데 강점으로 작용했습니다. 다만 이상 결과가 발생했을 때 입력값, 조건과 처리 과정으로 원인을 단계적으로 나누어 확인하는 요청은 명확하게 나타나지 않았고, 과제 2에서도 일부 형식 오류와 선택지 누락 가능성이 확인됐습니다.

  • 대화 저장 위치, 시트명 등 작업 환경을 구체적으로 지정하는 요청이 반복적으로 나타남
  • 결과 과제 2에서 일부 컬럼명과 값 형식이 안내 기준과 다르게 작성됐고, 일부 선택지 누락 가능성에 대한 확인이 필요했습니다.
  • 결과 이상 결과 발생 시 원인을 단계별로 구분해 확인하는 요청은 대화에서 명확하게 드러나지 않았습니다.

AI 결과를 검증하는 대표 방식

아래 내용은 행동별 사용 비율을 집계한 통계가 아니라, 우수 대화 사례에서 확인된 대표적인 AI 검증 방식입니다.

실행 전에 접근 방법부터 확인하기

AI에게 바로 결과를 만들도록 맡기지 않고, 어떤 순서와 기준으로 작업할지 먼저 설명하도록 요청하는 방식입니다.

관련 예시: 단계별 승인 통제, 분석 우선 + 확실성 수준 구분
확인된 사실과 추정을 구분하기

AI가 확실하지 않은 내용을 사실처럼 제시하지 않도록, 확정된 내용과 추정 또는 추가 확인이 필요한 내용을 구분하게 합니다.

관련 예시: 분석 우선 + 확실성 수준 구분, 가정 명시 및 검증 요청
예외 상황과 위험 요소 확인하기

정상적인 상황뿐 아니라 오류, 경계 조건과 예상하지 못한 부작용까지 함께 검토하도록 요청하는 방식입니다.

관련 예시: 아키텍처 스트레스 테스트, 사이드이펙트 선제 분석, 교차 영향 분석
제약조건 위반 여부 확인하기

AI가 제안한 방법이 최초 요구사항이나 금지 조건을 어기지 않는지 다시 확인하고, 조건에 맞지 않으면 다른 방법을 요청합니다.

관련 예시: 제약조건 위반 즉시 기각, 구현 계획 비판적 검토
결과가 실제 기준을 충족하는지 재검증하기

작업이 완료됐다는 AI의 답변만 믿지 않고, 테스트 기준과 예외 사례를 기준으로 결과를 다시 검증합니다.

관련 예시: 자기주도 엣지케이스 테스트 설계, 구현 계획 비판적 검토
여기서 배울 점

AI가 만든 결과를 바로 사용하는 것보다 작업 방법, 판단 근거, 예외 상황과 최종 요구사항 충족 여부를 다시 확인하는 과정이 중요합니다.
