# 평가 방식 (evaluation)

> 제출물 2개를 **정답키와 자동 대조**한다. 채점 스크립트는 [`grade.py`](grade.py), 정답키는 [`answer_key/`](answer_key/).
> 결과(문제 해결) 점수만 다룬다. 과정(AI 협업) 점수는 채팅 로그 기반 별도 루브릭.

---

## 1. 제출물 스키마 (정답이 결정되는 형식)

### Part 1 — `reconcile_table_template.xlsx` · 시트 `대사정리`
행 단위 = **거래 1건** = `(발주번호 + 품목코드)`. 발주서의 모든 거래가 한 줄씩(식별칸은 미리 채워져 제공). 정답은 모두 3장부 값에서 나온다. 컬럼 순서: `발주번호,품목코드,발주수량,발주단가,입고수량,청구수량,청구단가,청구금액`.

| 컬럼 | 형식 / 허용값 | 채점유형 |
|---|---|---|
| `발주번호` | 거래 키 — **양식에 미리 주어짐(채점 안 함)** | — |
| `품목코드` | 거래 키 — **양식에 미리 주어짐(채점 안 함)** | — |
| `발주수량` | 정수(발주서 그대로) | Exact |
| `발주단가` | 정수 원(발주서 그대로) | Exact |
| `입고수량` | 정수(입고증). 입고 행이 없으면(입고누락) **빈칸** | Exact |
| `청구수량` | 정수(세금계산서). 계산서 행이 없으면 **빈칸** | Exact |
| `청구단가` | 정수 원(세금계산서). 계산서 행이 없으면 **빈칸** | Exact |
| `청구금액` | 정수 원(세금계산서). 계산서 행이 없으면 **빈칸** | Exact |

> 채점 칸은 6개(`발주수량·발주단가·입고수량·청구수량·청구단가·청구금액`)다. 발주번호·품목코드는 식별 키로 미리 주어지며 채점 대상이 아니다. **누락측 칸은 빈칸이 정답** — 입고수량 `0`(0개 입고)과 입고누락(빈칸)은 **구분**한다(`norm_int`이 빈칸과 `0`을 다르게 본다). 채점은 천단위 콤마·공백·`.0`을 무시한다.

### Part 2 — `exception_template.xlsx` · 시트 `예외목록`
행 단위 = **위반 1건**. 허용오차 규정을 넘는 어긋남·누락만 기록. 정상 거래는 적지 않는다. 한 거래가 복수 규정을 어기면 행도 여러 개. **입력은 분리형으로 제공된 `data/reconcile_table_given.xlsx`(올바른 대사표)** — 1단계 조인을 틀려도 위반 판정엔 영향이 없다.

| 컬럼 | 형식 / 허용값 | 채점유형 |
|---|---|---|
| `발주번호` | 거래 키 | Set |
| `품목코드` | 거래 키 | Set |
| `위반유형` | `수량불일치` \| `단가불일치` \| `금액오류` \| `입고누락` \| `계산서누락` | Set |
| `사유` | 자유 문자열 — **참고용(채점 안 함)** | — |

> 채점은 **`(발주번호, 품목코드, 위반유형)` 튜플의 집합**으로 한다. **행 순서 무관**, 중복 행은 1개로 간주. 양식의 '예시…' 행은 자동 무시한다. 정상 거래를 올리면 오탐(FP), 위반을 빠뜨리면 누락(FN)으로 F1이 자연 처벌한다.

## 2. 채점 로직 (`grade.py` 구성요소)

```
grade.py
├─ load_sheet(path, sheet)            # openpyxl 로드 → dict 행(공백 strip, 빈 행 skip)
├─ grade_part1(sub, ans)             # 대사정리표: 셀 단위 비교
│   • 거래 키 (발주번호, 품목코드) 로 행 조인
│   • RECON_FIELDS = 발주수량·발주단가·입고수량·청구수량·청구단가·청구금액 (모두 norm_int)
│   • 필드별 일치 집계 → 필드별 정확도 + 전체 셀 정확도(정확셀/전체셀)
├─ grade_part2(sub, ans, valid_keys) # 예외목록: 집합 비교
│   • excset(): {(발주번호, 품목코드, 위반유형)} 집합화 (norm_vio로 위반유형 정규화, '예시' 행 제외)
│   • precision / recall / F1
│   • 오탐(FP = 정답 아닌데 올림)·누락(FN = 올려야 하는데 빠짐) 분리 집계
│   • 무결성: 유령 거래(존재하지 않는 발주번호+품목코드) / 허용 외 위반유형(VIOLATIONS 밖) 탐지
├─ score(p1, p2)                     # Part1 셀정확도×40 / Part2 F1×50 / 무결성 10(위반 1건당 -0.5)
└─ main()                            # 콘솔 표 + result.json (영역별 점수·FP/FN 샘플)
```

### 정규화 규칙(채점 관용)
- `norm_int`(6개 수치 칸): 천단위 콤마·공백·`.0` 제거 후 정수 비교. **빈칸 ≠ `0`** (빈칸 = 누락/제약없음, `0` = 0개·0원으로 구분).
- `norm_str`(키): 모든 공백 제거 후 비교. 품목명 표기는 키가 아니므로 채점에 영향 없음(조인은 코드로).
- `norm_vio`(위반유형): 공백 제거 + 동치 표기 흡수 — `수량오류→수량불일치`, `금액불일치→금액오류`, `세금계산서누락→계산서누락`, `입고없음→입고누락` 등.
- 빈 집합(예외 0건을 양쪽 모두 제출)의 F1 = 1로 처리.
- 허용 위반유형은 `{수량불일치, 단가불일치, 금액오류, 입고누락, 계산서누락}` 5종뿐 — 그 밖의 라벨은 무결성 위반으로 잡힌다.

## 3. 배점 (결과 점수 100점 기준)

| 영역 | 배점 | 산정 |
|---|--:|---|
| Part 1 대사정리표 셀 정확도 | 40 | (정확 셀 / 전체 채점 셀) × 40 |
| Part 2 예외목록 F1 (검증이 핵심) | 50 | F1 × 50 |
| Part 2 무결성(유령 거래·허용 외 위반유형 0건) | 10 | 위반 1건당 −0.5 |

> **합격선(1단계 능력)**: 세 장부를 키로 조인해 대사표를 일관 완성. **변별(2단계)**: 단가 ±10·금액 ±1·수량 정확 일치 경계를 모두 통과하고, 정상·표기변형을 오탐하지 않아 Part 2 F1을 끌어올림.

### 흔한 실패 = 의도한 함정 적중
- 단가차를 `> 0`으로 판정 → 허용오차 안(차 ≤ 10) 거래까지 위반으로 올려 **오탐(FP)** 급증.
- 금액 차이를 반올림 핑계로 모두 눈감음 → 2원 이상 어긋난 거래를 놓쳐 **누락(FN)**.
- 품목명으로 조인 → 표기변형 거래를 매칭 실패로 보고 **유령 위반/누락** 동시 발생.
- 누락(행 없음)을 0으로 채워 조인 → 입고수량 칸이 `0`이 되어 Part 1 **셀 오답** + 누락 위반 **놓침**.
- "위반을 찾아야 한다"는 압박으로 정상 222건 중 일부를 예외에 올림 → Part 2 **FP**.

## 4. 정답키 생성·관리

- 정답키(`answer_key/reconcile_table_answer.xlsx`, `answer_key/exception_answer.xlsx`)와 제공 데이터(`../data/`의 3장부·양식·`reconcile_table_given.xlsx`)는 **단일 입력 [`answer_key/cases.csv`](answer_key/cases.csv)** 에서 같은 스크립트로 나온다 → 장부·정답이 항상 정합.
- 거래·허용오차를 바꾸려면 **`cases.csv`만 수정**하고 생성 스크립트를 다시 돌려 **데이터와 정답키를 동시 갱신**한다(생성물 수기 편집 금지). CSV 작성법은 [`answer_key/INPUT_GUIDE.md`](answer_key/INPUT_GUIDE.md).
- 생성기: [`answer_key/build_dataset.py`](answer_key/build_dataset.py) — `cases.csv` 읽기 → 3장부 합성(경계·결함 주입) + 제출양식 + 분리형 대사표 + 정답키를 일괄 산출. **정답은 플래그를 베끼지 않고 `derive_violations`로 규칙 재도출**하며 `cross_check`로 자기검증한다. 기준일 `ASSIGN_DATE = 2026-06-28`·`random.seed(20260628)` 고정(`datetime.now()` 미사용) — 장부일자 합성에만 쓰고 채점·판정에는 쓰지 않는다.
