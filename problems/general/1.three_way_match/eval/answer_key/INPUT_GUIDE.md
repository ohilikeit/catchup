# INPUT_GUIDE — cases.csv 채우는 법 (출제자용)

이 과제의 **모든 데이터·정답은 단일 입력 파일 `cases.csv` 하나에서 생성**된다.
`cases.csv`를 시나리오로 채우고 `build_dataset.py`를 재실행하면, 3장부(발주/입고/세금
계산서)·제출양식·분리형 대사표·정답키가 **항상 정합하게 함께 갱신**된다. 수기로 엑셀을 고치지 말 것.

> ⚠️ **현재 들어 있는 `cases.csv`는 사무용품 구매 거래를 본뜬 샘플 겸 템플릿이다.**
> 컬럼 형식과 결함 주입 구성을 그대로 보여주기 위한 예시이므로, 출제 시 **실제
> 거래 데이터로 행을 교체**해서 쓰면 된다. 헤더(컬럼명)는 절대 바꾸지 말 것.
> 거래 키 = `발주번호 + 품목코드`이며, 한 발주번호에 여러 품목(라인아이템)을 둘 수 있다.

---

## 1. 컬럼 의미 / 형식 (헤더 순서 고정)

| 컬럼 | 의미 | 형식 / 예시 |
|------|------|------------|
| `case_id` | 케이스 식별자(추적용) | `T0001` … (중복 금지) |
| `발주번호` | 발주서 번호 | `PO250001` … (같은 발주에 여러 품목 가능) |
| `품목코드` | 품목 고유코드 — **조인 키** | `A1002` … (발주번호+품목코드 조합이 유일) |
| `품목명` | 품목명(표시용) | 자유 문자열 (쉼표 포함 시 따옴표로 감쌈) |
| `발주수량` | 발주 수량 | 양의 정수 |
| `발주단가` | 발주 단가(원) | 양의 정수 |
| `입고수량차` | 입고수량 − 발주수량 | 정수. `0` = 정확 일치. 예: `1`이면 입고가 1개 더 |
| `청구단가차` | 청구단가 − 발주단가(원) | 정수. `0` = 일치. `±10`까지 정상, 초과면 단가불일치 |
| `금액오류` | 청구금액을 일부러 어긋나게 | `Y`(±1원 초과 주입) \| `N`(허용오차 내) |
| `입고누락` | 입고증에서 행 제외 | `Y`(입고누락) \| `N` |
| `계산서누락` | 세금계산서에서 행 제외 | `Y`(계산서누락) \| `N` |
| `품목명표기변형` | 입고(없으면 계산서) 품목명만 다르게 표기 | `Y`(표기 변형 — 위반 아님, 오탐 함정) \| `N` |

빈 칸은 수치는 `0`, Y/N은 `N`으로 본다. **정상 거래는 모든 차이를 `0`·`N`으로 둔다.**

### ⭐ 정답 = 규칙 (플래그를 베끼지 않는다)
> `build_dataset.py`는 `금액오류=Y` 같은 시나리오 플래그를 **그대로 정답에 적지 않는다.** 플래그로
> 3장부(발주/입고/계산서)를 합성한 뒤, **그 3장부에 허용오차 규칙을 다시 적용해 위반을 도출**
> (`derive_violations`)한다. 그리고 "규칙도출 == 플래그의도"를 거래마다 대조(`cross_check`)해
> 모순(예: `금액오류=N`인데 금액이 어긋남, `입고누락=Y`인데 입고수량차≠0)을 **즉시 중단(fail-loud)**
> 으로 잡는다. 그래서 정답은 규칙에서 유일하게 산출되고 독립 검증이 성립한다 — 플래그는 합성·자기검증 전용이다.

### ⭐ 걸러낼 건 진짜 위반뿐 (오탐 규율 · 거래 키 교집합)
> 허용오차 **안에 든 거래는 정상**이라 예외에 올리면 안 된다(올리면 오탐 FP). 특히 `품목명표기변형=Y`는
> **위반이 아니다** — 장부마다 품목명 표기가 달라도 **조인은 품목코드로** 하기 때문이다(정답 예외목록에 안 들어감).
> 세 장부를 맞대는 키는 `발주번호 + 품목코드` 하나이며, 이 키가 세 장부에 모두 있어야 조인이 성립한다.
> 새 비교 축(예: 납기일 대사)을 추가하려면 `cases.csv`(입력 칸)·`build_dataset.py`(장부 합성·`derive_violations`)·
> `grade.py`(`RECON_FIELDS`/위반유형)에 짝을 **함께** 추가한다 — 칸만 늘리면 판정이 안 된다.

## 2. 허용오차 규칙 (rulebook — 안내시트에도 명시)

| 항목 | 정상(예외 아님) | 위반 | 위반유형 | 경계 예시 |
|------|----------------|------|----------|-----------|
| **수량** | 발주수량 = 입고수량 = 청구수량 (정확 일치) | 하나라도 다름 | `수량불일치` | 입고수량차 `0`=정상 / `1`=위반 |
| **단가** | `\|청구단가 − 발주단가\| ≤ 10` | `> 10` | `단가불일치` | 청구단가차 `10`=정상 / `11`=위반 |
| **금액** | `\|청구금액 − 청구수량×청구단가\| ≤ 1` | `> 1` | `금액오류` | 금액차 `1`=정상 / `2`=위반 |
| **입고 누락** | 입고증에 행 있음 | 행 없음 | `입고누락` | `입고누락=Y` |
| **계산서 누락** | 세금계산서에 행 있음 | 행 없음 | `계산서누락` | `계산서누락=Y` |

- 한 거래가 **복수 위반** 가능(예: 수량불일치 + 단가불일치 → 예외 행 2개).
- 입고/계산서가 누락이면 그 장부의 수량은 비교에서 빠진다(대신 누락 위반). 누락측 대사표 칸은 **빈칸**.
- 입고수량 `0`(0개 입고 → 수량불일치)과 입고누락(행 없음 → 빈칸)은 **다르다**.

## 3. 각 결함 주입법 (한 칸씩)

- **수량불일치**: `입고수량차`에 0이 아닌 값(예: `1`, `-2`). 입고수량 = 발주수량 + 입고수량차.
- **단가불일치**: `청구단가차`를 `11` 이상(또는 `-11` 이하). 청구단가 = 발주단가 + 청구단가차. `±10`까지는 정상(경계 변별용으로 `10`·`-10`도 섞어 둔다).
- **금액오류**: `금액오류=Y` → 생성기가 청구금액을 `청구수량×청구단가`에서 ±1원을 **초과**하게(경계 2 포함) 어긋낸다. `N`이면 0 또는 +1원(허용오차 내, 정상).
- **입고누락**: `입고누락=Y` → 입고증에서 행 제외. (이때 `입고수량차`는 `0`이어야 함 — 행이 없으면 수량차가 무의미, 아니면 fail-loud 중단)
- **계산서누락**: `계산서누락=Y` → 세금계산서에서 행 제외. (이때 `청구단가차=0`·`금액오류=N` — 아니면 중단)
- **표기변형(오탐 함정)**: `품목명표기변형=Y` → 입고(없으면 계산서) 품목명만 다르게 표기. **위반 아님**. (입고·계산서가 모두 누락이면 표기를 둘 장부가 없어 중단)

## 4. 정답 도출 — 날짜 무관, 규칙만 본다

```
위반 = derive_violations(거래)   # 3장부에 허용오차 규칙 재적용 (플래그 직접 안 읽음)
정상이면 예외목록에 올리지 않는다.
```

- 장부 일자(`ASSIGN_DATE` 기준 합성)는 **채점·판정에 쓰지 않는다** — 수량·단가·금액·누락만 본다.
- **고정 기준일 `ASSIGN_DATE = 2026-06-28`**(`build_dataset.py` 상단 상수, `datetime.now()` 미사용)은 장부일자 합성 표시용일 뿐이다.
- 현재 CSV 구성: **거래 314건 — 정상 222건 + 위반 92거래(예외 행 114건: 수량불일치 27 · 단가불일치 23 · 금액오류 24 · 입고누락 20 · 계산서누락 20).** 경계 케이스(단가차 10/11, 금액 1/2, 수량 0/±1)와 표기변형·정상 다수가 섞여 있다.

## 5. 원본 스캔 배치(선택)

- 이 과제는 멀티모달 추출 대신 **정형 엑셀 3표를 직접 제공**한다 — 학생은 이미지가 아니라 `발주_table`·`입고_table`·`계산서_table`을 읽는다.
- 실제 발주서/입고증/세금계산서 스캔(PDF·이미지)을 학생에게 함께 보여주고 싶으면 `data/sources/`에 배치한다. 비어 있어도 데이터 생성·채점은 동작한다(코드는 이 폴더를 만들거나 지우지 않는다).

## 6. 재생성 → 채점 절차

```bash
# 1) cases.csv 를 실제 거래·결함 시나리오로 채운다 (헤더 유지)
# 2) (선택) data/sources/ 에 원본 스캔을 넣는다
# 3) 데이터·정답 동시 생성
python3 eval/answer_key/build_dataset.py
#    → data/발주_table.xlsx · 입고_table.xlsx · 계산서_table.xlsx
#    → data/reconcile_table_template.xlsx · exception_template.xlsx · reconcile_table_given.xlsx
#    → eval/answer_key/reconcile_table_answer.xlsx · exception_answer.xlsx
# 4) 학생 제출물 채점 (P1 셀 비교 + P2 (발주번호,품목코드,위반유형) 집합 F1)
python3 eval/grade.py \
  --part1 data/reconcile_table_template.xlsx \
  --part2 data/exception_template.xlsx \
  --answer-dir eval/answer_key
```

`cases.csv`만 바꾸면 3장부·경계 함정·정답이 새 거래에 맞춰 재생성되므로, 출제자는 거래 데이터와
결함 시나리오만 정확히 입력하면 된다. (입력 모순은 `build_dataset.py`가 fail-loud로 막는다.)
