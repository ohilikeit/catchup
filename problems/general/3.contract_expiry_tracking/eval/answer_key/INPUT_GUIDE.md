# INPUT_GUIDE — 운영자 CSV 작성법 (contracts.csv)

이 과제의 **모든 데이터·정답은 단일 입력 [`contracts.csv`](contracts.csv) 하나에서 생성**된다.
계약서 PDF·계약대장·대상표·정답키는 [`build_dataset.py`](build_dataset.py)가 이 CSV만 읽어 만든다.
**수기로 엑셀·PDF를 고치지 말 것** — CSV를 고치고 재실행한다.

> ⚠️ 현재 `contracts.csv`는 샘플 겸 템플릿(30건)이다. **헤더는 절대 바꾸지 말 것**. 다른 계약
> 세트로 바꾸려면 행만 교체한다.

## §1 컬럼 의미/형식 — 헤더 순서 고정

| 컬럼 | 의미 | 형식 / 예시 |
|---|---|---|
| `case_id` | 시나리오 ID | `T0001`… (중복 금지) |
| `contract_id` | 계약 고유키(=PDF 파일명·계약대장 키) | `CT-2024-001` (중복 금지) |
| `계약명` | 계약 명칭 (Part1 추출 정답) | `본사 사옥 임대차 계약` |
| `거래상대방` | 상대방 (Part1 추출 정답) | `정림산업개발(주)` |
| `계약유형` | 분류 | `임대`\|`용역`\|`구독`\|`유지보수`\|`라이선스` (이 5개만) |
| `계약기간_개월` | 계약 총 기간(개월) → 시작일 역산용 | 양의 정수. 예 `24` |
| `잔여일수` | **기준일로부터 종료일까지 남은 날** (정답의 축) | 정수. 음수=이미 만료. 예 `45`, `-1` |
| `계약금액` | 총액(원). Part1 추출 정답 | 정수. **금액미기재=Y면 비운다** |
| `자동갱신` | 자동갱신 조항 유무 | `Y`\|`N` |
| `갱신통지일` | 만료 N일 전까지 통지(자동갱신=Y만) | 정수. **자동갱신=N이면 0(빈칸)** |
| `금액표기변형` | 계약서 금액을 까다로운 표기로(₩·한글병기) | `Y`\|`N`(기본 N) |
| `날짜표기변형` | 계약서 날짜를 점/슬래시/한글 등으로 | `Y`\|`N`(기본 N) |
| `종료일미명시` | 계약서에 종료일 없이 '시작일+기간'만 | `Y`\|`N`(기본 N) |
| `금액미기재` | 계약서에 총액 조항 없음 → 대장 금액 빈칸 | `Y`\|`N`(기본 N) |

> 빈 칸 = 제약/정보 없음. 금액미기재=Y면 `계약금액`을 **반드시 비운다**(0 아님).

## §2 날짜 결정성 — 잔여일수가 종료일을 정한다

- 기준일 `ASSIGN_DATE = 2026-06-28` (코드 상수). **종료일 = 기준일 + 잔여일수**.
- 시작일 = 종료일 − `계약기간_개월` (말일 보정).
- 그래서 `잔여일수` 하나가 만료 판정(만료경과/만료임박/자동연장주의)을 모두 결정한다.
  같은 CSV는 언제 재생성해도 같은 종료일·대상을 낳는다(`datetime.now()` 미사용).

## §3 만료·갱신 규칙 (대상 만들기) — 날짜·자동갱신만 본다

```
남은날 = 잔여일수
대상 = set()
if 남은날 < 0:          대상.add("만료경과")
else:
    if 남은날 <= 60:    대상.add("만료임박")           # SOON_DAYS=60, 60 포함
    if 자동갱신 == Y:
        통지마감잔여 = 남은날 - 갱신통지일
        if 통지마감잔여 <= 30:  대상.add("자동연장주의")  # NOTICE_SOON=30, 30 포함
```

- **만료 대상으로 만들려면**: `잔여일수`를 0~60(임박) 또는 음수(경과)로.
- **자동연장주의로 만들려면**: `자동갱신=Y` + `갱신통지일`을 크게(또는 잔여일수를 통지일 근처로) →
  통지마감잔여 ≤ 30. 잔여일수가 60 초과여도 자동연장주의만 단독으로 걸 수 있다(좋은 변별 케이스).
- **정상(대상 없음)으로 만들려면**: 잔여일수 > 60 + (자동갱신=N 또는 통지마감잔여 > 30).
- 경계 변별: 잔여 60=임박/61=정상, 통지마감잔여 30=주의/31=정상, 잔여 −1=경과/0=임박.

## §4 입력 검증 (fail-loud — 이 모순은 생성이 중단된다)

- `contract_id` 중복, `계약유형` 허용 외, `계약기간_개월`/`잔여일수` 비정수 → 중단.
- `금액미기재=Y`인데 `계약금액`이 채워짐 → 중단(둘 중 하나만).
- `금액미기재=N`인데 `계약금액`이 빈칸/0 이하 → 중단.
- `자동갱신=N`인데 `갱신통지일≠0` → 중단(자동갱신만 통지 의미).
- `자동갱신=Y`인데 `갱신통지일≤0` → 중단.
- `종료일미명시=Y`인데 종료일(기준일+잔여)의 '일(day)'이 28 초과 → 중단(시작일+개월 계산 시 월말
  보정 모호 방지). → **잔여일수를 조정해 종료일 일자를 1~28로** 둔다.

## §5 계약서 PDF 배치 (멀티모달)

- 계약서 PDF는 `build_dataset.py`가 `데이터/1_계약서/<contract_id>.pdf`로 **직접 합성**한다(양식 4종
  순환 + 표기 변형). 실제 회사 계약서는 기밀이라 넣지 않는다.
- 더 사실적인 멀티모달을 원하면, 운영자가 그 PDF를 실제 계약서 스캔/이미지로 **교체**할 수 있다.
  단 그 경우 PDF 내용과 `contracts.csv`의 값(계약명·날짜·금액·자동갱신·통지일)을 **글자 그대로
  일치**시켜야 채점이 맞는다(정답은 CSV가 유일 정의).
- 채점은 PDF가 아니라 CSV 기준값과 학생 제출 셀을 대조한다 → 추출 난이도와 정답 결정성은 분리된다.

## §6 재생성 → 채점 절차

```bash
# 1) contracts.csv 를 실제/원하는 계약으로 채운다 (헤더 유지, §4 모순 금지)
# 2) 데이터·정답 동시 생성
python eval/answer_key/build_dataset.py
#    → 데이터/1_계약서/*.pdf, 1_계약대장_제출용.xlsx, 2_계약대장_참고용.xlsx, 2_만료대상_제출용.xlsx
#    → eval/answer_key/1_계약대장_정답.xlsx, 2_만료대상_정답.xlsx
# 3) 자기채점(정답키 자기검증 — 100점 기대)
python eval/grade.py \
  --part1 eval/answer_key/1_계약대장_정답.xlsx \
  --part2 eval/answer_key/2_만료대상_정답.xlsx \
  --answer-dir eval/answer_key
```

> ⭐ **판정 축 ↔ 계약대장 칸 교집합(불변식)**: 만료 판정에 쓰는 모든 축은 계약대장에 실재해야 한다 —
> 만료경과·만료임박 ↔ `종료일`(=기준일+잔여일수), 자동연장주의 ↔ `종료일`+`자동갱신`+`갱신통지일`.
> **새 대상유형/축을 추가하려면 `contracts.csv`(노브)·`build_dataset.py`(`derive_targets`+
> `expected_from_flags` 한 쌍)·`grade.py`(`LEDGER_FIELDS` 또는 `TARGETS`/`norm_target`) 세 곳을
> 함께** 고친다(노브만 늘리면 판정 불가).
>
> ⭐ **정답=규칙 재적용**: 정답은 CSV 플래그를 직접 베끼지 않고, 합성한 계약(종료일·자동갱신·통지일)에
> 갱신 규칙을 다시 적용해 도출한다(`derive_targets`). `expected_from_flags`(플래그 의도)와
> `cross_check`로 대조해 불일치 시 발행을 중단한다 — 이것이 독립검증·결정성의 근거다.
