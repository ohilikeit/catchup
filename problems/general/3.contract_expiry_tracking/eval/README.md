# 계약 기한 관리 — 문제 방향성 (README)

> 일반사무(GEN) 직무 과제. **출제자·운영자용** 개요 문서. (학생에게 주는 파일은 [`../problem.md`](../problem.md))
> **고정 기준일: 2026-06-28**(만료까지 남은 날 계산 기준, 실제 오늘 아님). 난이도: **2단계**.
> 계약 정보는 단일 입력 [`answer_key/contracts.csv`](answer_key/contracts.csv)에 운영자가 채운다.
> 계약서 PDF·제출양식·정답키는 [`answer_key/build_dataset.py`](answer_key/build_dataset.py)가
> 그 CSV **하나만 읽어** 일괄 생성 → 재실행하면 PDF·정답이 항상 정합.

---

## 1. 문제 설명 (자연어)

총무·법무 지원 신입이 받은 업무: 회사에 쌓인 **임대·용역·구독·유지보수·라이선스 계약서(줄글 PDF)**
에서 기한·금액·자동갱신 조항을 읽어 **계약대장(정형표)** 으로 옮기고(Part1), 거기에 **갱신 규칙**을
적용해 **곧 만료되거나 챙겨야 할 계약만 추려내는(Part2)** 일이다. 계약서는 디지털화돼 있지 않고
양식·표기가 제각각이라, 사람이 한 장씩 읽어 정형화해야 한다 — 이를 AI 오케스트레이션으로 처리한다.

> 핵심 변별 포인트: **같은 "곧 만료"라도 자동갱신 조항 유무와 통지기한이 '지금 손을 써야 하는가'를
> 가른다.** 자동갱신 계약은 통지 마감을 놓치면 원치 않게 연장되고, 비자동갱신 계약은 방치하면
> 서비스가 끊긴다 — 그 차이를 규칙으로 정확히 갈라내는 것이 이 과제의 핵심이다.

## 2. 주어진 데이터 ([`../데이터/`](../데이터/))

| 파일 | 내용 | 형식 | 함정 |
|---|---|---|---|
| `데이터/1_계약서/` | 계약서 30건 (코드가 합성한 가상 계약서, 실제 회사 데이터 아님) | PDF(양식 4종) | 양식·날짜·금액 표기 제각각 → 추출 필요(멀티모달). 종료일 미표기·금액 미기재 섞임 |
| `데이터/1_계약대장_제출용.xlsx` | Part1 제출 양식(계약번호만 채워짐). **Part2의 입력이기도 함** | 엑셀('안내' 시트 포함) | — |
| `데이터/2_만료대상_제출용.xlsx` | Part2 제출 양식 | 엑셀('안내' 시트 + 예시행) | — |

> ⚠️ **계약서는 코드가 합성한다(취합/렌더형).** 실제 계약서는 회사 기밀이라 넣을 수 없으므로,
> `contracts.csv`의 값(canonical)으로 `build_dataset.py`가 다양한 양식의 가상 계약서 PDF를 직접
> 만든다. 정답은 항상 CSV에 있으므로 **채점은 OCR/추출 결과가 아니라 CSV 기준값과 대조** — 난이도
> (읽기 어려움)와 결정성(정답은 CSV가 유일 정의)을 분리한다. PDF를 다른 실파일로 교체해도 무방하나,
> 그 경우 CSV의 값과 PDF 내용을 운영자가 직접 일치시켜야 한다.

## 3. 해결해야 할 문제 (2 Part)

- **Part 1 — 추출.** 각 계약서 PDF를 읽어 계약대장 8칸을 채운다(계약명·거래상대방·계약유형·시작일·
  종료일·계약금액·자동갱신·갱신통지일). 계약서에 없는 정보는 비운다(금액 미기재 → 빈칸). 종료일이
  안 적혀 있으면 시작일+계약기간(개월)으로 계산한다.
- **Part 2 — 만료·갱신 판정.** **학생이 Part1에서 채운 계약대장(`1_계약대장_제출용.xlsx`)** 을 입력으로,
  아래 규칙을 적용해 대상만 골라 `(계약번호, 대상유형)`을 기록한다(통합형 — Part1 추출 오류는 그
  계약의 만료 판정으로 전이된다). Part2 채점은 늘 '진짜 정답 계약대장' 기준 정답키와 대조하므로,
  추출부터 판정까지 끝까지 정확히 맞췄는지를 본다. ※ 과거의 '정답 계약대장 참고용 별도 제공(분리형)'은
  이 과제에선 Part1 정답과 동일 산출물이라 복붙 시 Part1 채점을 무력화해 폐기했다.

만료·갱신 판정 규칙 (남은날 = 종료일 − 2026-06-28):
1. **만료경과** — 남은날 < 0 (이미 만료).
2. **만료임박** — 0 ≤ 남은날 ≤ 60 (오늘 만료 포함, 60일 포함).
3. **자동연장주의** — 자동갱신=Y 이고 아직 만료 전이며, 통지마감(= 종료일 − 갱신통지일)까지 남은날
   ≤ 30. (통지기한 임박/경과 → 방치 시 자동 연장.)

> ⭐ **판정 축 ↔ 데이터 칸 교집합 불변식**: 모든 판정은 계약대장에 실재하는 칸으로만 한다 —
> 만료경과·만료임박 ↔ `종료일`, 자동연장주의 ↔ `종료일`+`자동갱신`+`갱신통지일`. 축을 추가하려면
> `contracts.csv`·`build_dataset.py`(derive/expected)·`grade.py`(필드/대상유형) 세 곳을 동반 수정.
> ⭐ **확인 불가/미기재**: 계약서에 금액 조항이 없으면 계약대장 금액칸은 **빈칸**(0 아님). 만료
> 판정은 **날짜·자동갱신 조항만** 본다 — 감(感)으로 추가하지 않는다.

## 4. 최종 결과물 (제출물)

| 제출 파일 | 행 단위 | 핵심 컬럼 |
|---|---|---|
| `1_계약대장_제출용.xlsx` | 계약 1건 | 계약번호, 계약명, 거래상대방, 계약유형, 시작일, 종료일, 계약금액, 자동갱신, 갱신통지일 |
| `2_만료대상_제출용.xlsx` | (계약번호 × 대상유형) 1조합 | 계약번호, 대상유형 (대상 아닌 계약은 적지 않음) |

> **생성형(계약서 초안·요약문)은 만들지 않는다.** 이 과제는 '비정형 계약서 → 구조화 추출 → 규칙
> 적용'만 채점한다(결정성 확보). 문장 작성·요약은 범위 밖.

## 5. 평가방식

- **Part 1** — 계약대장 셀 단위 정확도(**Exact**, 8칸 × 30계약).
- **Part 2** — `(계약번호, 대상유형)` **집합 일치(Set: 정밀도·재현율·F1)**. 행 순서 무관·중복 1개 간주.
- **과정 점수(AI 협업)** — 채팅 로그로 별도 평가. 본 문서 범위 밖.

> 결정성 원칙: 모든 채점 칸은 (제공 PDF + 명시 규칙)에서 유일 정답으로 환원. 경계가 애매하게 갈릴
> 항목(말일 보정이 필요한 종료일 계산 등)은 입력 설계에서 제거했다. (`intention.md` 참조)

## 6. 재생성·채점

```bash
# 1) 생성: contracts.csv → 계약서 PDF 30 + 계약대장/대상표 양식 + 정답키
python eval/answer_key/build_dataset.py
#    → 데이터/1_계약서/*.pdf, 1_계약대장_제출용.xlsx, 2_만료대상_제출용.xlsx
#    → eval/answer_key/1_계약대장_정답.xlsx, 2_만료대상_정답.xlsx
# 2) 자기채점(정답키 자기검증 — 100점 기대)
python eval/grade.py \
  --part1 eval/answer_key/1_계약대장_정답.xlsx \
  --part2 eval/answer_key/2_만료대상_정답.xlsx \
  --answer-dir eval/answer_key
# 3) ★발행 게이트: 독립 재계산(build_dataset 미사용 제3 구현으로 정답키 정합 검증)
python eval/verify_recompute.py   # "✓ 모두 일치"가 아니면 발행 금지
# 4) 학생 채점
python eval/grade.py \
  --part1 데이터/1_계약대장_제출용.xlsx \
  --part2 데이터/2_만료대상_제출용.xlsx \
  --answer-dir eval/answer_key
```

> 발행 전 필수: ① `build_dataset.py` 자기검증 통과 → ② 자기채점 100점 → ③ `verify_recompute.py`
> "모두 일치". `build_dataset.py` 안의 `cross_check`는 종료일 산술 라운드트립 가드일 뿐이고,
> 생성기·채점기 공통 버그를 잡는 **진짜 독립검증은 `verify_recompute.py`** 다.

현재 입력 구성: 계약 30건 / 대상 25행(만료경과 5 · 만료임박 12 · 자동연장주의 8) / 정상 9건.
