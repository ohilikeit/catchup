# 출제 의도 (intention)

> 이 문제가 **무엇을 측정**하고, **어떤 결함을 일부러 심었으며**, 학생이 **어떤 과정으로 풀기를** 기대하는지 핵심만 적는다.

## 한 줄 의도

> "양식이 제각각인 거래처 4곳의 견적 파일을 코드로 읽어, 같은 품목을 품목코드로 한 줄에 묶고 거래처별 단가를 펼쳐 최저가를 고른다" — **구매·총무 신입의 다출처 견적 취합 업무를 챗봇 붙여넣기로는 못 풀고 Claude Code 오케스트레이션으로만 풀리게** 만든 문제. 모든 데이터·정답은 단일 입력 `quotes.csv`에서 생성돼, 품목을 바꿔도 동일 구조로 재현된다.

## 측정하는 능력

| 축 | 무엇을 보는가 |
|---|---|
| **직무 능력 (구매·총무/일반 사무)** | 양식이 다른 여러 견적을 공통 비교표로 맞춰 "행을 보존하며 모으는" 감각 — 컬럼 매핑·같은 품목 판정(품목코드)·표기 통일·최저가 선택·비교 가능성 판단 |
| **AI 활용 능력** | ① 형식이 다른 여러 파일(xlsx·csv)을 코드로 열어 일관 파싱 ② 정규화·키 통합·피벗(거래처→컬럼) 규칙을 데이터로 다뤄 재사용 파이프라인 작성 ③ 최저가·동점 처리·단위 검사 로직 구현 ④ 결과 검증 |
| **문제 해결력** | 흩어진 비정형(양식 제각각) 입력 → 규칙 적용 → 정형 한 표로 환원하는 분해력. "품목명 변형", "단가 3형식", "견적 안 한 칸(빈칸 보존, 0과 구분)", "동점 우선순위", "단위 불일치=비교불가" 같은 함정을 스스로 발견·처리. **확인 불가하면 무리해서 단정하지 않는** 판단(빈칸을 0으로 채우지 않음, 단위가 다르면 최저가 단정 안 함) |

> 설계 근거: [`../../../_6일반범용-마케팅-산업범용-업무형태-보강.md`](../../../_6일반범용-마케팅-산업범용-업무형태-보강.md)의 **GEN-L1-X1(거래처별 견적을 한 표로 취합해 품목별 최저가 비교)** 을 실제 사무(구매·총무) 도메인으로 구현한 사례. 채점은 [`_5 §6`](../../../_5직무-바이브코딩-과제설계.md)의 결정성 원칙을 따른다.

## 일부러 심은 결함 (함정)

학생이 **데이터를 곧이곧대로 쓰면 틀리도록** 설계했다. 이걸 발견·처리하는지가 변별점이다.

1. **품목명 변형 → 품목코드로 묶기** — 같은 품목코드인데 거래처마다 품목명을 다르게 적는다(앞뒤 공백 주입 3건, 길게/줄여 쓴 별칭 5건 — 예: `무선마우스`↔`옵티컬마우스`). 이 함정이 변별하는 건 **"품목코드로 묶었는가, 표시된 이름 문자열로 묶었는가"** 다 — 공백은 거래처마다 주입 폭이 달라(`pad_spaces` 1~2칸) 이름 문자열로 그룹핑하면 같은 물건이 여러 줄로 갈라지고(행집합 F1 하락), 별칭은 토큰 자체가 달라 갈라짐 + 비우선 거래처 이름을 쓰면 셀 오답까지 난다. 정답은 **품목코드로 묶고**, 비교표 품목명은 **거래처 우선순위(가나다) 1위 표기**(별칭이면 1위 거래처가 보인 정식명). 단, *코드로 올바로 묶은 뒤* 품목명 칸의 앞뒤·내부 공백 차이 자체는 `norm_str`이 흡수한다(G9 채점 관용 — 표기 차이엔 너그럽고, 묶기 실패엔 엄격).
2. **양식 차이(컬럼명·단가 표기)** — 컬럼명이 거래처마다 다르고(`단가`/`price`/`공급가`/`판매가` 등), 단가가 천단위 콤마 문자열(`"12,500"`)·정수·원 표기(`"12,500원"`)로 섞여 있다. 컬럼을 표준명으로 매핑하고 단가를 콤마·`원` 제거 정수로 통일해야 셀이 맞는다.
3. **견적 안 한 거래처 칸(빈칸 보존)** — 한두 거래처만 견적한 품목이 많다(빈 단가 칸 37개). 견적 안 한 거래처 칸은 **비워 둬야** 정답이다. 0이나 임의값으로 채우면 오답(`norm_int`은 빈칸과 0을 구분한다).
4. **한 거래처 전용 품목 보존** — 한 거래처만 견적한 품목(현재 1건)도 비교표에 빠짐없이 들어가야 한다. 여러 거래처 품목만 챙기다 보면 누락(FN) 발생.
5. **최저가·동점 우선순위** — 품목마다 견적 단가 중 최솟값을 골라 `최저가`·`최저가거래처`에 적는다. 최솟값이 **두 거래처에서 같으면(동점)** 우선순위가 빠른 거래처(가나다)를 택해야 한다. 아무나 택하면 셀 오답.
6. **규격 다른 동명 품목(과잉 병합 금지)** — 이름이 같아도 규격(품목코드)이 다른 품목 쌍이 있다(예: `포스트잇` 51×38 / 76×76). 이름만 보고 한 줄로 합치면 행 누락·셀 오답.
7. **단위 불일치 = 비교불가(판별 불가)** — 한 품목을 거래처들이 서로 다른 단위(박스/개 등)로 적은 경우가 있다(현재 4건). 가격을 곧바로 비교할 수 없으므로 `최저가`를 비우고 `최저가거래처`에 `비교불가`라고 적어야 한다. 무리하게 숫자만 비교해 최저가를 단정하면 오답.

> 결정성 봉쇄: 최저가가 **애매하게 갈리는** 경우는 입력 설계에서 통제했다 — 동점은 우선순위(가나다)로 유일하게 깨지고, 비교 불가능 케이스(단위 불일치)는 `비교가능=N`으로 명시해 "비교불가"라는 단일 정답으로 닫는다. `build_dataset.py`가 `비교가능=N`이면 거래처 단위를 실제로 다르게 렌더하고(`alt_unit`), fail-loud(`load_quotes`)로 모순 입력(별칭인데 별칭 없음, 비교불가인데 거래처 1곳 등)을 차단한다. 모든 케이스는 명시 규칙으로 단일 정답에 매핑되며, 정답은 항상 `quotes.csv` → `build_dataset.py`에서 유일하게 산출된다.

## 기대하는 풀이 과정

1. **4소스를 코드로 연다** — 형식이 다른 거래처 4개 견적 파일(xlsx·csv)을 각각 파싱하고, 컬럼을 표준명으로 매핑한다. (손/챗봇 붙여넣기로는 양식 제각각 파일을 일관 처리 불가)
2. **정규화한다** — 단가 콤마·`원` 제거 → 정수, 품목명 앞뒤 공백 trim, 견적 안 한 칸은 빈칸으로 보존.
3. **모은다(통합)** — `품목코드`로 그룹핑해 1행으로 묶고 거래처별 단가를 옆으로 펼친다. 품목명·규격은 거래처 우선순위(가나다) 1위 표기를 쓰고, 견적 단가 중 최솟값을 `최저가`(동점=가나다 우선)로, 단위가 갈리면 `비교불가`로 적는다.
4. **검증한다** — 비교표에 품목코드가 유일한지(과잉 병합·중복 미접기 없는지), 한 거래처 전용 품목이 빠지지 않았는지, 빈칸을 0으로 메우지 않았는지, 단위 다른 품목을 무리해서 비교하지 않았는지 표본 점검. (검증 습관이 변별 포인트)

## 현실성 (왜 이 시나리오인가)

여러 거래처에서 받은 견적을 한 표로 모아 최저가를 비교하는 일은 구매·총무·자재 관리에서 **가장 보편적인 사무 업무 중 하나**다. 양식이 제각각인 견적 N개를 행을 보존하며 한 비교표로 모으는 형태는 특정 회사에 종속되지 않은 보편 업무이며, 품목 수가 늘면 손으로는 비싼 곳을 고르기 쉬워 자동화 효용이 크다.

> **데이터 출처·고정성**: 견적은 운영자가 단일 입력 `eval/answer_key/quotes.csv`(canonical 1행=1품목)에 채운다. 각 거래처 단가 칸이 그 품목을 어느 거래처가 견적했는지(present)를 정하고, `표기변형`(none/품목명공백/품목명별칭)·`비교가능`(Y/N)이 표기·단위 함정을 건다. 비교표의 각 거래처 단가 칸은 그 거래처 소스에 대응 원본 컬럼이 있어야 채울 수 있다(표준 칸↔소스 컬럼 교집합 불변식: 거래처별 단가↔`단가`/`price`/`공급가`/`판매가`, 품목명↔`품명`/`name`/`품목명`/`상품명`). **현재 CSV는 canonical 품목 48건 구성 — 단일거래처 1건 + 복수거래처 47건, 소스 총 155행, 품목명 공백 3·별칭 5·비교불가 4, 빈 단가 칸 37개.** 정답 도출은 `quotes.csv`를 직접 베끼지 않고 **생성된 4소스를 다시 파싱·통합 규칙 재적용**해 재구성하며(독립 검증), `cross_check`가 canonical 의도와 일치하는지 fail-loud로 자기검증한다. `random.seed(20260628)` 고정, 전역 누적상태 없음 → **언제 재생성해도 동일**하다. 품목을 추가/수정하려면 `quotes.csv`만 고치고 재실행하면 데이터·정답이 함께 갱신된다.
