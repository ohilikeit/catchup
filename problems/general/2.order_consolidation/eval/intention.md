# 출제 의도 (intention)

> 이 문제가 **무엇을 측정**하고, **어떤 결함을 일부러 심었으며**, 학생이 **어떤 과정으로 풀기를** 기대하는지 핵심만 적는다.

## 한 줄 의도

> "양식이 제각각인 채널 3곳의 주문 파일을 코드로 읽어, 중복을 접고 날짜·금액·공백을 통일해 표준 한 표로 통합한다" — **사무/운영 신입의 다출처 데이터 취합 업무를 챗봇 붙여넣기로는 못 풀고 Claude Code 오케스트레이션으로만 풀리게** 만든 문제. 모든 데이터·정답은 단일 입력 `orders.csv`에서 생성돼, 주문을 바꿔도 동일 구조로 재현된다.

## 측정하는 능력

| 축 | 무엇을 보는가 |
|---|---|
| **직무 능력 (일반 사무/운영)** | 양식이 다른 여러 표를 공통 스키마로 맞춰 "행을 보존하며 합치는" 감각 — 컬럼 매핑·중복 판정·표기 통일·결측 처리 |
| **AI 활용 능력** | ① 형식이 다른 여러 파일(xlsx·csv)을 코드로 열어 일관 파싱 ② 정규화·dedup 규칙을 데이터로 다뤄 재사용 파이프라인 작성 ③ 충돌 해소(우선순위)·키 통합 로직 구현 ④ 결과 검증 |
| **문제 해결력** | 흩어진 비정형(양식 제각각) 입력 → 규칙 적용 → 정형 한 표로 환원하는 분해력. "중복", "날짜 3형식", "콤마 금액", "앞뒤 공백", "빈칸 보존(0과 구분)", "값 충돌 우선순위" 같은 함정을 스스로 발견·처리. **없는 값은 지어내지 않고 비우는** 판단(빈칸을 0으로 채우지 않음) |

> 설계 근거: [`../../../_6일반범용-마케팅-산업범용-업무형태-보강.md`](../../../_6일반범용-마케팅-산업범용-업무형태-보강.md)의 **GEN-L1-X4(다채널로 들어온 주문 양식 통일해서 한 표로, G12 다채널 주문/유입 데이터 표준화)** 를 실제 사무 도메인으로 구현한 사례. 채점은 [`_5 §6`](../../../_5직무-바이브코딩-과제설계.md)의 결정성 원칙을 따른다.

## 일부러 심은 결함 (함정)

학생이 **데이터를 곧이곧대로 쓰면 틀리도록** 설계했다. 이걸 발견·처리하는지가 변별점이다.

1. **중복 주문(여러 채널 동일 주문)** — 한 주문이 2~3개 채널에 동시에 잡혀 같은 주문번호가 소스에 여러 번 등장한다(현재 다채널 144건, 소스 총 432행). 그대로 붙이면 통합표에 같은 주문번호가 여러 줄로 남는다 → **1행으로 접어야** 한다(`주문번호`를 키로 dedup). 못 접으면 행집합 정밀도 하락 + 무결성 감점(이중 처벌).
2. **양식 차이(컬럼명·날짜 형식·금액 표기)** — 컬럼명이 채널마다 다르고(`주문번호`/`order_id`/`협력사주문ID` 등), 날짜가 3형식(`YYYY-MM-DD HH:MM` / `YYYY/MM/DD` / `MM/DD/YYYY`), 금액이 천단위 콤마 문자열(`"1,200,000"`)과 정수로 섞여 있다. 컬럼을 표준명으로 매핑하고 날짜를 `YYYY-MM-DD`로, 금액을 콤마 제거 정수로 통일해야 셀이 맞는다.
3. **표기 변형(앞뒤 공백)** — 일부 주문의 고객명·상품명 앞뒤에 공백이 주입돼 있다(`표기변형` 컬럼). trim하지 않으면 정답과 셀 불일치.
4. **결측(금액·주문일 빈칸)** — 원본에 금액 또는 주문일이 비어 있는 주문이 있다(현재 금액 빈칸 50건·주문일 빈칸 50건). 그 칸은 **비워 둬야** 정답이다. 빈칸을 0이나 임의값으로 채우면 오답(`norm_int`은 빈칸과 0을 구분한다).
5. **한 채널 전용 주문 보존** — 한 채널에만 있는 주문(현재 단일채널 108건)도 통합표에 빠짐없이 들어가야 한다. 다채널만 챙기다 보면 누락(FN) 발생.
6. **값 충돌 우선순위** — 다채널 주문은 채널마다 금액·수량·날짜가 일부러 다르게 들어가 있을 수 있다(값충돌 주입 144건). 통합 시 **web > partner > phone** 우선순위의 높은 채널 값을 택해야 한다. 아무 값이나 택하면 셀 오답.

> 결정성 봉쇄: 우선순위가 **애매하게 갈리는** 경우(예: 충돌 필드가 결측이라 우선순위를 적용할 수 없는 모순 케이스)는 입력 설계에서 **제외**했다(`build_dataset.py`가 결측 필드는 충돌 주입 대상에서 빼고, fail-loud로 모순 입력을 차단). 모든 케이스는 명시 규칙으로 단일 정답에 매핑되며, 정답은 항상 `orders.csv` → `build_dataset.py`에서 유일하게 산출된다.

## 기대하는 풀이 과정

1. **3소스를 코드로 연다** — 형식이 다른 `웹주문.xlsx`·`전화주문.csv`·`제휴주문.xlsx`를 각각 파싱하고, 컬럼을 표준명으로 매핑한다. (손/챗봇 붙여넣기로는 양식 제각각 파일을 일관 처리 불가)
2. **정규화한다** — 날짜 3형식 → `YYYY-MM-DD`(웹은 시각 떼기), 금액 콤마 제거 → 정수, 고객명·상품명 앞뒤 공백 trim, 빈칸은 빈칸으로 보존.
3. **통합한다(Part 1)** — `주문번호`로 그룹핑해 1행으로 접고, 값 충돌은 우선순위(web>partner>phone)로 해소, `출처채널`은 등장 채널을 정렬·파이프결합한다.
4. **검증한다** — 통합표에 주문번호가 유일한지(중복 미제거 없는지), 한 채널 전용 주문이 빠지지 않았는지, 빈칸을 0으로 메우지 않았는지 표본 점검. (검증 습관이 변별 포인트)

## 현실성 (왜 이 시나리오인가)

여러 채널·지점·협력사로 들어온 주문/유입 데이터를 공통 스키마로 표준화하는 일은 영업지원·주문처리·구매(발주) 등에서 **가장 보편적인 사무 자동화 업무 중 하나**다(산업 전반 자동화 TOP10 안에 든다 — `_6` §1). 양식이 제각각인 N개를 행을 보존하며 한 표로 합치는 형태는 특정 회사에 종속되지 않은 보편 업무다.

> **데이터 출처·고정성**: 주문은 운영자가 단일 입력 `eval/answer_key/orders.csv`(canonical 1행=1주문)에 채운다. `channels` 컬럼이 그 주문을 어느 채널 소스에 렌더할지 정하고(2개 이상이면 중복 주입 → dedup 대상), `표기변형`·`결측`이 공백·빈칸 함정을 건다. 표준 통합표의 모든 칸은 3소스 각각에 대응 원본 컬럼이 있어야 채울 수 있다(표준 칸↔소스 컬럼 교집합 불변식: 주문번호↔`주문번호`/`order_id`/`협력사주문ID` · 고객명↔`고객명`/`name`/`구매자` · 상품명↔`상품`/`item`/`품목` · 수량↔`수량`/`qty`/`개수` · 금액_원↔`금액`/`amount`/`결제액` · 주문일↔`주문일시`/`date`/`일자`). **현재 CSV는 canonical 주문 252건 구성 — 단일채널 108건 + 다채널 144건, 소스 총 432행(중복 포함), 값충돌 주입 144건, 금액 빈칸 50건·주문일 빈칸 50건.** 정답 도출은 `orders.csv`를 직접 베끼지 않고 **생성된 3소스를 다시 파싱·통합 규칙 재적용**해 재구성하며(독립 검증), `cross_check`가 canonical 의도와 일치하는지 fail-loud로 자기검증한다. `ASSIGN_DATE = 2026-06-28`·`random.seed(20260628)` 고정, 전역 누적상태 없음 → **언제 재생성해도 동일**하다. 주문을 추가/수정하려면 `orders.csv`만 고치고 재실행하면 데이터·정답이 함께 갱신된다.
