# INPUT_GUIDE — orders.csv 채우는 법 (출제자용)

이 과제의 **모든 데이터·정답은 단일 입력 파일 `orders.csv` 하나에서 생성**된다.
`orders.csv`(canonical 1행=1주문)를 실제 주문으로 채우고 `build_dataset.py`를 재실행하면,
3개 채널 소스(양식 제각각)·제출 양식·정답키가 **항상 정합하게 함께 갱신**된다. 수기로
엑셀을 고치지 말 것.

> ⚠️ **현재 들어 있는 `orders.csv`는 사무용품 주문을 본뜬 샘플 겸 템플릿이다.**
> 컬럼 형식과 함정 구성을 그대로 보여주기 위한 예시이므로, 출제 시 **실제 주문
> 데이터로 행을 교체**해서 쓰면 된다. 헤더(컬럼명)는 절대 바꾸지 말 것.
> canonical 1행은 "통합표에 들어갈 최종 1주문"이고, `channels`가 그 주문을 어느 채널
> 소스에 (몇 번) 렌더할지 정한다.

---

## 1. 컬럼 의미 / 형식 (헤더 순서 고정)

| 컬럼 | 의미 | 형식 / 예시 |
|------|------|------------|
| `order_id` | 주문 고유키 | `ORD26-0001`… (중복 금지 — canonical 주문은 유일) |
| `고객명` | 고객 이름 | 자유 문자열 (비울 수 없음) |
| `상품명` | 상품 이름 | 자유 문자열 (비울 수 없음) |
| `수량` | 주문 수량 | 양의 정수 (비울 수 없음) |
| `금액_원` | 주문 금액(원) | 정수. `결측=금액결측`이면 **반드시 비움**(그 외엔 양의 정수) |
| `주문일` | 주문일 | `YYYY-MM-DD`. `결측=주문일결측`이면 **반드시 비움** |
| `channels` | 이 주문이 등장한 채널 | `web`·`partner`·`phone` 중 1~다를 **파이프(`|`)로** (§2) |
| `표기변형` | 텍스트 공백 함정 | `none` \| `상품명공백` \| `고객명공백` (§3) |
| `결측` | 빈칸 함정 | `none` \| `금액결측` \| `주문일결측` (§3) |

`order_id`·`고객명`·`상품명`·`수량`·`channels`는 비울 수 없다. 빈 행은 무시된다.

> ⭐ **`channels`가 중복(dedup)을 만든다.** `channels`에 채널이 **2개 이상**이면 그 주문번호가
> 해당 채널 소스마다 한 번씩 **중복 렌더**된다(학생이 1행으로 접어야 할 dedup 대상). 채널이
> **1개**면 그 채널 전용 단일 주문(통합표에 보존돼야 함). 통합표의 `출처채널`은 등장 채널을
> **알파벳순 정렬해 파이프결합**한 값이다(예: `web|partner` → `partner|web`).

> ⭐ **표준 칸 ↔ 소스 컬럼 교집합(불변식).** 통합표의 7칸은 3소스 각각에 대응 원본 컬럼이
> 있어야 채워진다. 현재 대응은:
> 주문번호↔`주문번호`/`order_id`/`협력사주문ID` · 고객명↔`고객명`/`name`/`구매자` ·
> 상품명↔`상품`/`item`/`품목` · 수량↔`수량`/`qty`/`개수` · 금액_원↔`금액`/`amount`/`결제액` ·
> 주문일↔`주문일시`/`date`/`일자` · 출처채널↔(등장 채널 파생).
> **새 표준 칸을 추가하려면 `build_dataset.py`의 3소스 렌더(`build_sources`)·정답 재구성
> (`parse_sources`/`consolidate`)과 `grade.py`의 `STD_FIELDS`에 짝이 되는 컬럼·규칙을 함께
> 추가**해야 한다(한 곳만 늘리면 통합 불가).

## 2. channels — 채널 구성·값 충돌 우선순위

- 형식: `web`·`partner`·`phone`을 파이프로. 예: `web` / `web|phone` / `web|partner|phone`.
- **단일 채널**(예: `phone`) → 그 채널 전용 주문. 한 소스에만 렌더, 통합표에 1행 보존.
- **다채널**(예: `web|partner`) → 같은 주문번호가 두 소스에 중복 렌더 = dedup 대상. 이때
  비우선 채널에 **값 충돌**(금액·수량·날짜 중 하나를 다르게)이 자동 주입된다.
- **값 충돌 우선순위**: 통합 시 우선순위 높은 채널 값을 택한다 — **web > partner > phone**.
  (생성기는 우선 채널에 canonical 원값을, 비우선 채널에 변형값을 넣는다.)
- 채널 다양성·dedup 변별을 위해 다채널 주문을 일정 비율 섞는다(현재 단일 108 / 다채널 144).

## 3. 표기변형 / 결측 — 정규화·빈칸 함정

- `표기변형` = `상품명공백`/`고객명공백`이면 해당 텍스트 앞뒤에 공백이 주입된다(모든 채널
  렌더에 적용 → 학생이 trim해야 함). `none`이면 변형 없음.
- `결측` = `금액결측`이면 `금액_원`을 전 채널에서 빈값으로, `주문일결측`이면 `주문일`을 빈값으로
  렌더한다. **그 칸의 정답은 빈칸**(0으로 채우면 오답). `none`이면 결측 없음.
- ⚠️ **모순 입력은 fail-loud 차단**: `결측=금액결측`인데 `금액_원`에 값이 있으면(또는 그 반대)
  생성기가 즉시 중단한다. 결측 플래그와 실제 값은 항상 일치시킨다. (결측 필드는 값 충돌
  주입 대상에서도 제외돼 우선순위 모순이 생기지 않는다.)

## 4. 정답 도출 — 소스 재파싱, canonical 직접 안 베낌

생성기는 `orders.csv`를 직접 정답으로 쓰지 않는다.

```
3소스 렌더(build_sources)  →  소스 재파싱(parse_sources)  →  통합(consolidate)
                                                            ↘ cross_check(== canonical 의도)  # 불일치 시 중단
```

- 정답 통합표 = **생성된 3소스를 다시 파싱·정규화·dedup·우선순위 재적용**해 재구성한 행집합.
- `cross_check`가 그 재구성 결과를 canonical 의도(`expected_from_canonical`)와 대조해 일치하지
  않으면 fail-loud로 중단한다(생성기/입력 모순 탐지).
- **고정 기준일 `ASSIGN_DATE = 2026-06-28`**·**`random.seed(20260628)`**(build_dataset.py 상단 상수,
  `datetime.now()` 미사용, 전역 누적상태 없음) → 언제 재생성해도 동일. `ASSIGN_DATE`는 웹
  주문일시의 시각 합성에만 쓰고 채점에는 쓰지 않는다.
- 현재 CSV 구성: **canonical 주문 252건**(단일채널 108 / 다채널 144), 소스 총 432행(중복 포함),
  값충돌 주입 144건, 금액 빈칸 50건·주문일 빈칸 50건.

## 5. 채널 소스에는 별도 파일 배치가 필요 없다

이 과제는 멀티모달(포스터/이미지) 입력이 없다. 학생용 입력 3소스(`웹주문.xlsx`·`전화주문.csv`·
`제휴주문.xlsx`)는 모두 `build_dataset.py`가 `orders.csv`에서 **자동 생성**한다 — 운영자가 따로
넣을 파일이 없다. (youth_policy류의 `data/<source>/` 포스터 배치 단계 N/A.)

## 6. 재생성 → 채점 절차

```bash
# 1) orders.csv 를 실제 주문으로 채운다 (헤더 유지, order_id 중복 금지)
# 2) 데이터·정답 동시 생성
python3 eval/answer_key/build_dataset.py
#    → data/웹주문.xlsx, data/전화주문.csv, data/제휴주문.xlsx
#    → data/consolidated_template.xlsx (제출 양식: '안내'+'통합주문' 시트)
#    → eval/answer_key/consolidated_answer.xlsx (정답키)
# 3) 학생 제출물 채점 (Set(주문번호) + Exact(정규화 셀))
python3 eval/grade.py \
  --part1 data/consolidated_template.xlsx \
  --answer-dir eval/answer_key
```

`orders.csv`만 바꾸면 3소스 양식·중복·함정·정답이 새 주문 구성에 맞춰 generic하게 재생성되므로,
출제자는 주문 데이터만 정확히 입력하면 된다.
