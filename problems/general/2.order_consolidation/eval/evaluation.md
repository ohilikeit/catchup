# 평가 방식 (evaluation)

> 제출물 1개를 **정답키와 자동 대조**한다. 채점 스크립트는 [`grade.py`](grade.py), 정답키는 [`answer_key/`](answer_key/).
> 결과(문제 해결) 점수만 다룬다. 과정(AI 협업) 점수는 채팅 로그 기반 별도 루브릭.

---

## 1. 제출물 스키마 (정답이 결정되는 형식)

### Part 1 — `consolidated_template.xlsx` · 시트 `통합주문`
행 단위 = **통합 주문 1건** (`주문번호` 1개, 중복은 1행). 정답은 모두 생성된 3소스를 통합 규칙으로 재구성한 값에서 나온다. 컬럼 순서: `주문번호,고객명,상품명,수량,금액_원,주문일,출처채널`.

| 컬럼 | 형식 / 허용값 | 채점유형 |
|---|---|---|
| `주문번호` | `ORD26-0001`… (키) — 결과 표에 **유일**해야 함 | Set (키) |
| `고객명` | 문자열. 앞뒤 공백 제거 | Exact (`norm_str`) |
| `상품명` | 문자열. 앞뒤 공백 제거 | Exact (`norm_str`) |
| `수량` | 정수 | Exact (`norm_int`) |
| `금액_원` | 정수(원). 콤마 제거. 원본 결측이면 **빈칸** | Exact (`norm_int`) |
| `주문일` | `YYYY-MM-DD`. 원본 결측이면 **빈칸** | Exact (`norm_date`) |
| `출처채널` | 등장 채널을 정렬·파이프결합: `web`\|`partner`\|`phone` 조합(예: `partner|web`, `partner|phone|web`) | Exact (`norm_channel`) |

> 채점은 **주문번호 키로 조인 + 6개 표준 칸 셀 Exact** 와 **`{주문번호}` 행집합 Set** 을 결합한다. **행 순서 무관**, 같은 주문번호의 중복 행은 dedup 실패로 본다(첫 행만 셀 비교에 사용하고, 나머지는 무결성·정밀도에서 처벌). **빈칸과 0은 구분**한다(`norm_int`: 빈칸=결측, `0`=금액 0원). 출처채널은 토큰을 분해·정렬 후 비교하므로 순서·공백 차이는 흡수한다(`web|partner`≡`partner|web`).

## 2. 채점 로직 (`grade.py` 구성요소)

```
grade.py
├─ load_sheet(path, sheet)            # openpyxl 로드(data_only) → 헤더 정규화, 빈 행 스킵
├─ norm_str / norm_int / norm_date / norm_channel   # 칸별 정규화(아래 규칙)
├─ grade_part1(sub, ans)             # 통합표: Set(주문번호) + Exact(정규화 셀)
│   • 주문번호 키로 정답·제출 조인. 제출은 키별 행 목록(중복 탐지)
│   • 행집합: tp=A∩S, fp=S−A(유령), fn=A−S(누락)
│       precision = tp / 제출 원본행수(중복·유령이 분모에 그대로 남아 정밀도 하락)
│       recall    = tp / 정답 키수,  F1 = 2PR/(P+R)
│   • 셀 Exact: 정답 키마다 (중복이면 첫 행) 6칸 정규화 후 일치 집계 → 필드별·전체 셀 정확도
│   • 무결성: 유령 주문번호(미존재 키) + 중복 미제거(같은 주문번호 2행+) 집계
└─ score(p1) / report()              # 영역별 점수 합산 + JSON·콘솔 표
```

### 정규화 규칙(채점 관용)
- `norm_str`(고객명·상품명): 모든 공백 제거 후 비교 — 앞뒤 trim 함정 흡수, 내부 공백 표기차도 관용.
- `norm_int`(수량·금액_원): 콤마·공백·`.0` 제거 후 정수 비교. **빈칸과 0은 구분**(빈칸=결측, 0=금액 0원).
- `norm_date`(주문일): 3형식(`YYYY-MM-DD [HH:MM]` / `YYYY/MM/DD` / `MM/DD/YYYY`)·엑셀 datetime을 모두 `YYYY-MM-DD`로. 빈칸 보존.
- `norm_channel`(출처채널): `|`로 분해 → 토큰 정렬 → 재결합. 순서·공백 무관.
- 빈 데이터(정답·제출 모두 0행) F1=1로 처리. 양식의 '예시' 행(`예시ORD-0001`)은 정답 키에 없으므로 유령으로 잡힌다 → 학생은 예시 행을 지우고 제출해야 한다.

## 3. 배점 (결과 점수 100점)

| 영역 | 배점 | 산정 |
|---|--:|---|
| Part 1 — 셀 Exact | 60 | 셀정확도(정확 셀 / 전체 채점 셀) × 60. 전체 셀 = 정답 주문수 × 6칸 (현재 252×6 = 1512) |
| Part 1 — 행집합 Set-F1 | 30 | `{주문번호}` 집합의 F1 × 30 |
| 무결성 | 10 | `max(0, 10 − (유령행수 + 중복미제거수) × 0.5)` |

> **합격선(1단계 능력)**: 3소스를 일관 파싱해 표준 한 표로 합치고 컬럼·날짜·금액을 정규화. **변별(2단계)**: 중복을 정확히 접고(dedup), 값 충돌 우선순위·결측 빈칸 보존까지 통과해 셀 정확도와 행집합 F1을 동시에 끌어올림.

### 흔한 실패 = 의도한 함정 적중
- 3소스를 그대로 이어붙이고 **dedup 안 함** → 같은 주문번호 다중 행 → 행집합 **정밀도 급락 + 무결성 감점**(이중 처벌).
- 날짜를 통일 안 하거나 형식 오인(`MM/DD/YYYY`↔`YYYY/MM/DD`) → `주문일` **셀 오답** 대량.
- 금액 콤마 문자열을 숫자로 못 바꾸거나 공백 trim 누락 → `금액_원`·`고객명`·`상품명` **셀 오답**.
- 결측 칸을 0/임의값으로 채움 → 빈칸≠0이라 **셀 오답**.
- 값 충돌에서 비우선 채널 값을 택함 → `금액_원`·`수량`·`주문일` **셀 오답**.
- 한 채널 전용 주문을 빠뜨림 → 행집합 **재현율 하락(FN)**. / 존재하지 않는 주문번호(예시 행 등)를 남김 → **유령(FP) + 무결성 감점**.

## 4. 정답키 생성·관리

- 정답키(`answer_key/consolidated_answer.xlsx`)와 제공 데이터(`../data/`의 3소스·제출양식)는 **단일 입력 [`answer_key/orders.csv`](answer_key/orders.csv)** 에서 같은 스크립트로 나온다 → 데이터·정답이 항상 정합.
- 정답 도출은 `orders.csv`를 직접 베끼지 않는다 — **생성된 3소스를 다시 파싱하고 통합 규칙(정규화·dedup·우선순위)을 재적용**해 통합표를 재구성한다(독립 검증). canonical 의도와의 일치는 `cross_check`가 fail-loud로 자기검증한다.
- 주문을 바꾸려면 **`orders.csv`만 수정**하고 생성 스크립트를 다시 돌려 **데이터와 정답키를 동시 갱신**한다(생성물 수기 편집 금지). CSV 작성법은 [`answer_key/INPUT_GUIDE.md`](answer_key/INPUT_GUIDE.md).
- 생성기: [`answer_key/build_dataset.py`](answer_key/build_dataset.py) — `orders.csv` 읽기 → 3소스(양식 제각각) 렌더 + 제출양식 + 정답키를 일괄 산출. `ASSIGN_DATE = 2026-06-28`·`random.seed(20260628)` 상수 고정(`datetime.now()` 미사용), 전역 누적상태 없음 → 언제 재생성해도 동일.

```bash
# 자기채점(정답키 자기검증, 100점 기대)
python eval/grade.py \

  --answer-dir eval/answer_key
```
