# 5개 직무 기반 바이브코딩 AX 과제 — 설계 분석

> 입력 자료: `2025 부서별 AX 과제_v.2.xlsx`(18개 부서 시트), `AI 이용현황 설문조사_결과보고_0617.xlsx`(1,289명)
> 레퍼런스: `problems/ai-native-challenge-2026` (청년주택 입주 자동화)
> 대상: 대학생 / 환경: 내부망 code-server(웹 fetch·검색 불가) / 도구: Claude Code

## 1. 두 파일에서 뽑은 핵심 사실

### AX 과제 파일 — "직무별로 자동화하고 싶은 실제 반복업무" 목록
18개 부서 시트가 전부 *현업이 직접 적어낸* 업무개선 후보다. 5개 직무에 입힐 **진짜 시나리오**가 여기 다 있다.

| 직무 매핑 | AX 파일에서 나온 실제 업무 (테마 후보) |
|---|---|
| 일반-범용 | 만족도 조사결과 분석 자동화(주관식 텍스트 분류·요약), 매뉴얼 검색 지원, 보고서 요약 |
| 경영/사무 | 손익예측·장부 병합·공용비 배부(재경실), 월정산 ERP↔결제사 **데이터 불일치 대사**(개발부), 출고·반품 이상값 탐지(블랙라벨) |
| 마케팅 | 콘텐츠 **성과 분석 자동화**(채널별 지표), 카드뉴스 자동제작, SEO/AEO, 경쟁 채널 비교 |
| 영업 | **외주비 산정**(작업유형·난이도 분류), 방문 일정/인력 관리, 입찰 제안서, 채권·담보 모니터링 |
| 기획 | 콘텐츠 기획 아이템 발굴, **경쟁 채널 비교 리포트**, 교재 시장분석, 모집요강 변경 비교, 연도별 전형 비교표 |

### 설문 파일 — 난이도 보정의 근거
- 응답자 = **2030 대학생·구직자 1,289명** (정확히 우리 시험 대상층).
- AI 사용 72% / 미사용 28%. 그런데 **실사용도 대부분 기초**:
  - 단순 Q&A 24% · 자료분석 위임 19% · 다단계 위임 12.5% · **파일·코드 직접 처리 9.6%** · **자동화 워크플로우 6.4%**.
- 도구: LLM 챗봇 85.7% vs **코딩툴(Claude Code/Cursor 등) 10.6%**.
- 요청 방식: 상황 서술 36.5% · 짧은 질문 34% · **역할/형식/제약까지 구조화 8.5%**.
- 검토 방식: 한 번 읽고 수정 39% · 그냥 사용 30% · **출처·실행 검증 18.6%**.

> **결론(스윗스팟)**: 대상층은 "챗봇에 붙여넣기"는 익숙하지만 **다파일·대량·다규칙·정형출력**은 거의 못 한다. 그래서 시나리오는 한눈에 이해되되, 손/챗봇으로는 도저히 못 풀고 **Claude Code 오케스트레이션(파일 읽기 → 처리 코드 작성 → xlsx 채우기 → 검증)** 을 해야만 풀리는 문제가 정답 난이도다.

## 2. 레퍼런스 문제의 "복제해야 할 DNA"

청년주택 문제가 좋은 평가 도구인 이유 = 아래 6개를 모든 직무 과제가 그대로 물려받아야 한다.

1. **현실 직무 시나리오** — "당신은 ○○ 담당자입니다. 이 반복업무를 AI에 맡기세요." (AX 파일에서 그대로 차용 → 진짜 같음)
2. **흩어진 비정형 입력 + 정형 명부** — 정보가 PDF/이미지에 흩어져 있고, 처리 대상은 xlsx 명부.
3. **추출 → 규칙 적용 → 고정 양식 출력** — 채점은 **주어진 `submission_template.xlsx`에 채운 결과만**. (안내 시트에 칸 규격 명시)
4. **2단 에스컬레이션** — Part 1: 각 행을 판정/집계(기초 표 완성). Part 2: 그 위에 **다조건 필터/계산**을 쌓음.
5. **"새 입력에도 똑같이 돌아가야 함"** — 값 하드코딩이 아니라 *재사용 가능한 처리*를 만들었는지를 가름.
6. **양만으로 손풀이를 차단** — (레퍼런스는 53명×5공고=265행). 대량이라 사람이 못 함 → 반드시 자동화.

### 난이도 조절 노브 (직무별로 이걸로 조정)
- 규칙 개수 / 예외 조건 수
- 교차 참조해야 하는 파일 수 (1개 → 여러 개)
- 입력의 지저분함(병합셀·표기 불일치·결측치)
- 출력의 형식 엄격성(정렬·세미콜론 구분·`고정` 같은 특수 표기)
- Part 2의 다조건 동시 통과 로직

## 3. 5개 직무 과제 설계 (테마·파일·스킬 전부 다르게)

각 과제는 **"AX 파일의 실제 업무 → 레퍼런스 DNA로 포장 → 직무색 입힘"** 으로 만든다.
모두 *웹 불필요 · 제공 파일만으로 풀림 · submission_template.xlsx 채점*.

| # | 직무 | 테마 | 주 입력 파일 | 가르는 핵심 역량 | 주 파일타입 |
|---|------|------|------------|----------------|-----------|
| 1 | 일반-범용 | 사내 설문·피드백 분석 | 대용량 응답 xlsx(주관식+객관식) + 분류기준 PDF | 분류·집계·요약 (대량 데이터) | Excel |
| 2 | 경영/사무 | 경비/정산 대사 + 영수증 처리 | ERP xlsx ↔ 결제 xlsx + 영수증 **이미지** + 규정 PDF | 대사·검증·규칙계산 (숫자 정확성) | Excel+이미지 |
| 3 | 마케팅 | 멀티채널 콘텐츠 성과 분석 | 채널별 성과 xlsx 3종 + 캠페인 PDF | 지표통합·계산·랭킹·콘텐츠 생성 | Excel+PDF |
| 4 | 영업 | 외주비 산정(작업 분류·견적) | 단가표 PDF/이미지 + 작업의뢰 내역 xlsx | 분류·룩업·계산 (견적 로직) | PDF+Excel |
| 5 | 기획 | 경쟁/시장 비교 → 우선순위 | 이종 자료(경쟁사 PDF 여러 개 + 자사 xlsx + 차트 **이미지**) | 종합·스코어링·우선순위화 | PDF+Excel+이미지 |

테마·파일조합·핵심스킬이 셋 다 겹치지 않게 배치했다. 아래는 각 과제의 상세.

---

### 과제 1 — 일반-범용직무: "사내 만족도 설문, 하루 만에 보고서로"
**출처**: AX「만족도 조사결과 분석 자동화」(난이도 하), 「주관식 응답 분석에 인력 소모 큼」

- **시나리오**: 사내 교육/행사 만족도 설문 결과 원본(엑셀 1,000+행)이 왔다. 객관식은 집계하고, **주관식은 카테고리로 분류**해서 부서별·항목별 통계표와 한 장 요약을 만들어라.
- **입력**: `responses.xlsx`(응답 원문 다수), `분류기준.pdf`(주관식을 어떤 카테고리로 나눌지 정의 — 설문 파일의 '주관식 응답 구분' 시트가 실제 모델)
- **Part 1**: 객관식 문항별 응답수·비율 집계표 완성.
- **Part 2**: 주관식 응답을 기준 PDF의 카테고리로 분류 + 부서×카테고리 교차표 + 핵심 불만/칭찬 TOP N 요약.
- **가르는 것**: 대량 행 처리, 분류 규칙의 일관 적용, 정형 집계 — 챗붙기로는 양 때문에 불가.
- **재사용 트위스트**: "다음 분기 설문이 와도 같은 양식으로 나와야 함."

---

### 과제 2 — 경영/사무(인사·재무·총무): "정산 대사, 1원도 안 틀리게"
**출처**: AX「월정산 ERP↔결제사 정산 데이터 **불일치 내역 검증**」(개발부), 「공용비 배부」(재경실), 「출고·반품 이상값 탐지」

- **시나리오**: 우리 장부(ERP 추출)와 결제사 정산내역, 두 엑셀이 안 맞는다. **불일치 건을 찾아 사유를 분류**하고, 규정대로 부서별 공용비를 배부한 정산표를 완성하라.
- **입력**: `erp_ledger.xlsx`, `pg_settlement.xlsx`(같은 거래를 양쪽에서), `정산규정.pdf`(매칭 키·허용 오차·배부 기준), `영수증/` 이미지 몇 장(엑셀에 없는 수기 경비 — **이미지에서 금액·항목 추출**해 합산).
- **Part 1**: 두 파일 대사 → 일치/불일치 판정, 불일치는 사유(금액차·누락·중복·날짜불일치) 태깅.
- **Part 2**: 영수증 이미지 반영 + 규정대로 공용비 배부 계산 → 부서별 최종 정산표.
- **가르는 것**: 두 데이터 키 매칭, 숫자 정확성·이중검증(설문상 18.6%만 하는 검증 습관), 멀티모달(이미지 OCR).
- **난이도 포인트**: "그냥 사용 30%" 식 태도면 숫자가 틀림 → 검증을 강제.

---

### 과제 3 — 마케팅: "흩어진 채널 지표를 한 장의 성과 리포트로"
**출처**: AX「콘텐츠 성과 분석 자동화」, 「SNS 채널별 지표 일일 수집」, 「카드뉴스 제작 자동화」

- **시나리오**: 유튜브·인스타·블로그 성과가 채널마다 다른 엑셀로 흩어져 있다. 통합해 **캠페인별 성과를 계산·랭킹**하고, 잘된 콘텐츠로 카드뉴스 카피까지 뽑아라.
- **입력**: `youtube.xlsx`/`instagram.xlsx`/`blog.xlsx`(컬럼명·단위 제각각), `campaigns.pdf`(캠페인↔콘텐츠 매핑, 목표 지표)
- **Part 1**: 채널 지표 통합(컬럼 정규화) → CTR·전환율·참여율 계산 → 캠페인별 집계·순위표.
- **Part 2**: 기준 충족 콘텐츠 선별 + 상위 콘텐츠의 **카드뉴스용 텍스트(제목/3줄 요약/해시태그)** 생성해 양식에 기입.
- **가르는 것**: 이종 스키마 정규화(N:1 매핑), 파생지표 계산, 데이터→콘텐츠 생성 결합.
- **마케팅색**: 지표·랭킹·카피라이팅이 한 흐름.

---

### 과제 4 — 영업: "작업 견적, 2주 걸리던 걸 1시간에"
**출처**: AX「외주비 산정 — 작업난이도·소요시간·작업유형 구분」(영업부), 「시장조사 결과 요약」

- **시나리오**: 업체가 보낸 작업내역 엑셀을 보고, **단가표 기준으로 작업유형·난이도를 분류**해 외주비를 산정하라. 견적서 양식을 채우면 끝.
- **입력**: `work_items.xlsx`(작업 수십~수백 건, 설명이 자유서술), `단가표.pdf` 또는 `단가표.png`(작업유형×난이도별 단가 매트릭스 — 이미지로 주면 표 인식까지 평가)
- **Part 1**: 각 작업의 유형·난이도 판정(자유서술 → 단가표 카테고리 매핑) → 건별 단가 룩업.
- **Part 2**: 수량·할증 규칙 적용해 합계 산정 + 업체별/유형별 소계 + 예외(단가표에 없는 작업) 표시.
- **가르는 것**: 비정형 텍스트 분류, 룩업 테이블 조인, 견적 계산 로직, 예외 처리.
- **재사용 트위스트**: "다음 달 새 작업내역이 와도 같은 견적 로직이 돌아야 함." (레퍼런스의 '새 공고' 장치와 동형)

---

### 과제 5 — 기획: "경쟁사 자료 더미에서 우리 다음 수를 뽑아라"
**출처**: AX「경쟁 채널 비교 리포트 자동화」, 「교재 시장분석」, 「연도별 전형 비교 자료 생성」

- **시나리오**: 경쟁사 자료(PDF 여러 개)와 자사 데이터(엑셀), 트렌드 차트(이미지)가 책상에 쌓였다. **비교표로 정리**하고, 가중치 기준으로 **기획 우선순위를 스코어링**하라.
- **입력**: `competitor_*.pdf` 3~4개(형식 제각각), `our_metrics.xlsx`, `trend_chart.png`(이미지에서 추세 읽기), `평가기준.pdf`(스코어링 항목·가중치)
- **Part 1**: 이종 자료에서 비교 축(가격/기능/타깃/성과 등) 추출 → 정규화된 비교표.
- **Part 2**: 평가기준의 가중치로 각 기회 항목 스코어링 → 우선순위 랭킹 + 근거 요약.
- **가르는 것**: 가장 비정형·다출처 종합, 평가 프레임워크 적용, 정성→정량 변환.
- **기획색**: "분석"이 아니라 **의사결정용 우선순위**가 산출물. 5개 중 최상 난이도(종합·판단 결합).

## 4. 공통 운영 규격 (레퍼런스와 동일하게 맞출 것)

각 과제 폴더는 레퍼런스 구조를 그대로 따른다:

```
problems/<job-slug>/
├── 0_시작하기.md          # 시나리오 + 파일 안내 + 진행 순서
├── 1_문제1.md             # Part 1 (기초 표 완성)
├── 2_문제2.md             # Part 2 (다조건/계산 심화)
├── CLAUDE.md, AGENTS.md   # "Vibe Coding Assessment Facilitator" 역할 + submit 안내
├── data/                  # 비정형 소스 (pdf / png / 이미지)
└── part1/, part2/
    ├── <input>.xlsx
    └── submission_template.xlsx   # '안내' 시트에 칸 규격 → 채점 대상은 이 파일뿐
```

**난이도 가드레일(대학생 + Claude Code 기준)**
- ✅ 시나리오 한 문단으로 이해 / 산출물은 "표를 채워라"로 명확.
- ✅ 손·챗봇으로 불가능한 **양**(수백 행) + **다파일 교차** + **2~4개 동시조건**.
- ✅ 정답이 결정적(채점 가능) — 애매한 건 '비우기'/'제약 없음' 규칙으로 봉쇄(레퍼런스 방식).
- ✅ 웹 0회 — 모든 근거가 제공 파일 안에.
- ⚠️ 너무 쉬움 방지: Part 2에 *반드시* 다조건 동시통과 또는 누적 계산을 넣는다.
- ⚠️ 너무 어려움 방지: 규칙은 PDF/안내시트에 **명시**(추론으로 규칙을 발명하게 하지 않음).

**채점 친화 설계**: 행 순서 무관, 칸 이름·형식은 안내 시트에 고정, 불가/예외 표기 규칙(세미콜론·`고정` 등)을 통일 → 자동 채점 스크립트로 정오 판정.

# 6. ⭐ 결과 채점 가능성(Evaluability) — 설계의 1급 제약

> 평가 리포트(`CATCHUP AX AI 역량 검사 리포트_V2.0`)를 역설계해 보면, 이 시험은 **두 점수**를 낸다.
> 과제를 설계할 때 *결과 점수가 자동 채점 가능한가*를 통과하지 못하면 그 과제는 폐기 대상이다.

## 6.1 리포트가 알려주는 채점 구조

| 점수 | 무엇으로 | 채점 방식 | 직무 과제 설계에 주는 함의 |
|---|---|---|---|
| **AI 협업 평가(과정)** 82점 | **채팅 로그** | 5개 역량(문제 정의·AI 출력 검토·실행 환경 관리·완성 및 가치·불확실성 관리)을 대화 행동으로 채점 | **도메인 무관**. 어떤 과제든 동일 루브릭으로 매겨짐 → 과제는 "좋은 협업 행동이 나오도록" 유도만 하면 됨 |
| **문제 해결 평가(결과)** 89점 | **제출 xlsx** | 과제별 세부기준의 **정확도 + 형식 준수**. 과제2 실제 기준 = `판정 정확도·기준 적용·결과 정확도·선택지 누락·컬럼명 및 값 형식` | **정답키 대조 + 자동 형식검사**. 그래서 *결과가 결정적이지 않으면 이 점수를 못 만든다* |

**핵심 결론**: 청년주택이 채점되는 이유 = 모든 채점 칸이 (제공 PDF의 규칙 + xlsx 데이터)로부터 **단일 정답값**으로 결정되고, 학생은 *기준을 발명하지 않고 적용*하기 때문. → 이게 모든 직무 과제가 통과해야 할 시험이다.

## 6.2 채점 가능성의 제1법칙

> **모든 채점 대상 칸은 (제공 파일 + 명시된 규칙)으로부터 단일 정답값(또는 닫힌 정답집합)으로 환원되어야 한다.**
>
> 학생이 *기준을 발명*해야 하면 → 채점 불가.
> 해법: **그 기준을 입력 파일로 제공**해서 '발명'을 '적용'으로 바꾼다. (청년주택이 자격요건 PDF로 하는 바로 그 장치)
>
> 생성형 산출물(리포트 산문, 카피)은 ① 채점 대상에서 빼서 **과정 점수**로만 평가하거나, ② **구조화 슬롯 + 검증 가능 제약**(정확한 데이터 인용·길이·개수·올바른 대상 선택)으로 바꿔 *근거/형식* 기준으로 채점한다. **산문 품질 자체는 결과 채점하지 않는다.**

## 6.3 채점 가능한 정답의 5가지 유형 (모든 출력 칸을 이 중 하나로)

| 유형 | 예 | 자동 채점법 |
|---|---|---|
| **정확도(Exact)** | 가능/불가, 분류 카테고리, 불일치 여부 | 정답키와 셀 단위 일치율 |
| **닫힌 선택(Set)** | "기준 충족 콘텐츠 ID 집합", "선택 가능한 옵션" | 집합 일치(정밀도/재현율) |
| **계산(Computed)** | 외주비 금액, 집계 수치, 배부액 | 허용오차(±0 또는 ε) 내 일치 |
| **순위(Rank)** | 우선순위 랭킹 | 점수 산식 적용 결과의 정렬 일치 |
| **형식·근거(Format/Grounding)** | 컬럼명·값 형식, 카피가 올바른 수치를 인용했는지, 길이·개수 제약 | 규칙 기반 검사(정규식·길이·참조 무결성) |

생성형으로 보이는 것도 위 유형으로 **분해**되면 채점된다. 분해가 안 되면 결과 채점에서 빼고 과정 점수로 보낸다.

## 6.4 "애매한 것"을 채점 가능하게 바꾸는 4가지 전환 기법

- **(A) 기준 제공(Provide-the-rubric)** — 학생이 우선순위/가중치/분류기준을 *정하게* 하지 말고, `평가기준.pdf`·`분류기준.pdf`·`단가표.pdf`로 **준다**. 그러면 정답이 수학적으로 하나로 결정된다.
- **(B) 구조화 슬롯(Structured slots)** — "리포트를 써라"가 아니라 "요약 시트의 이 칸들을 채워라". 각 칸은 계산된 값 → 결정적. 산문은 미채점 장식.
- **(C) 근거 결속(Grounding)** — 생성 텍스트는 "반드시 해당 콘텐츠의 실제 조회수 숫자를 포함", "정확히 3개 해시태그", "20자 이하"처럼 **검증 가능한 제약**을 건다. → 청년주택의 '결과 형식' 기준과 동형.
- **(D) 폐쇄화(Close the world)** — 입력 데이터를 *설계할 때* 각 항목이 한 카테고리/한 정답에만 매핑되도록 만든다(경계 모호 항목 배제). 모호하면 '비우기'/'제약 없음' 규칙으로 봉쇄.

## 6.5 직무별 채점 가능성 판정 + 처방

| # | 직무 | 결과 채점 난도 | 처방 | 채점 가능? |
|---|------|------------|------|:---:|
| 2 | 경영/사무(정산 대사+영수증) | **쉬움** | 전부 Exact/Computed. 영수증 금액·대사 결과·배부액 모두 단일 정답 | ✅ 최상 |
| 1 | 일반-범용(설문 분석) | 쉬움 | 객관식=Exact 집계. 주관식=분류기준 PDF 제공(A) + 응답을 명확매핑 설계(D) → 카테고리 칸 Exact | ✅ |
| 4 | 영업(외주비 산정) | 보통 | 단가표 제공(A). 작업분류만 소프트 → 작업설명을 명확매핑 설계(D). 금액=Computed | ✅ |
| 3 | 마케팅(성과+카피) | 보통 | 지표·랭킹=Computed/Rank로 채점(주). 카드뉴스 카피는 **결과 채점에서 분리** → 근거 결속(C)으로 '형식/근거'만 검사하거나 과정 점수로 | ✅ (분리 후) |
| 5 | 기획(비교→우선순위) | **주의** | **평가기준.pdf로 가중치·산식 제공(A)** → 우선순위는 Rank로 결정. 비교표는 가능한 한 수치/닫힌값 필드로(D). 근거 산문은 미채점 | ✅ (기준 제공 시) |

### 처방 상세 — 당신이 짚은 두 과제

**기획: "우선순위 비교의 결과는 정해진 것인가?" → 기준을 주면 YES.**
학생이 우선순위를 *판단*하면 채점 불가. 대신 `평가기준.pdf`에 산식을 박는다. 예:

```
우선순위 점수 = 0.4×시장성 + 0.3×실행용이성 + 0.3×자사적합도
- 시장성: competitor PDF에서 추출한 '월 검색량' 정규화(0~10)
- 실행용이성: our_metrics.xlsx의 '예상 공수(주)'를 역수 정규화
- 자사적합도: 평가표의 적합도 코드(A=10,B=6,C=3) 그대로
```

그러면 제출 양식은 **완전 통제 가능**:

| 기회ID | 시장성점수 | 실행용이성점수 | 자사적합도점수 | 종합점수 | 우선순위 |
|---|---|---|---|---|---|
| OPP-01 | 8.0 | 6.7 | 10 | 8.21 | 1 |

→ 모든 칸이 Computed/Rank. **정답키 1개**. 청년주택과 동일 수준으로 통제됨. (학생의 창의성은 '판단'이 아니라 *여러 PDF에서 데이터를 정확히 뽑아 산식을 올바로 적용*하는 데서 평가됨)

**마케팅: "성과 리포트를 어떻게 평가?" → 리포트를 '구조화 요약 시트'로 정의한다.**
"좋은 리포트"를 채점하지 말고, 리포트가 **반드시 담아야 할 결정적 사실의 칸**을 정의해 그 칸을 채점한다. 즉 *리포트 = 계산값 채우기*.

`submission_template.xlsx`의 '요약' 시트(예시 — 모든 칸이 입력에서 유일하게 계산됨):

| 항목 | 값(채점) |
|---|---|
| 최고 ROI 캠페인 | `CAMP-03` ← Set/Exact |
| 해당 캠페인 ROI | `312%` ← Computed(±1%p) |
| 전월 대비 총전환 증감 | `+18.4%` ← Computed |
| 채널별 전환 1위 | `YouTube` ← Exact |
| 기준 미달(ROI<100%) 캠페인 수 | `2` ← Exact |

그리고 카드뉴스 카피는 **별도 시트**에 두되, *결과 채점은 형식/근거만*:
- 대상 = 종합 1위 콘텐츠인가(Set) · 실제 조회수 숫자 포함(Grounding) · 제목 ≤ 20자(Format) · 해시태그 정확히 3개(Format).
- 카피의 *문장력*은 결과 점수가 아니라 **과정(채팅) 점수**에서 본다.

→ "꼭 갖춰야 할 요소를 리포트가 갖췄는가"라는 당신의 직관을 **그대로 채점 가능한 칸 목록으로 못 박은 것**. 요소 = 미리 정의한 결정적 슬롯.

## 6.6 모든 과제에 공통 적용할 채점 규격

1. **제출물은 항상 `submission_template.xlsx`** — 마크다운·자유 문서 금지. '안내' 시트에 컬럼명·값 형식·시트명 고정(리포트의 '컬럼명 및 값 형식' 기준에 직결).
2. **정답키(answer key) + 자동 채점 스크립트를 과제와 함께 제작** — 셀 단위 비교(Exact/Set/Computed/Rank)와 형식 검사(정규식·길이·참조)로 점수화. *이 스크립트를 못 짜는 과제는 출제하지 않는다*가 출제 게이트.
3. **부분점수 차원 분리** — 정확도/형식/누락을 분리 집계(리포트가 `결과 정확도`와 `컬럼명 및 값 형식`을 따로 매기듯). 형식만 틀린 학생과 판정이 틀린 학생을 구분.
4. **모호성 봉쇄** — 정답이 갈릴 수 있는 항목은 입력 설계 단계에서 제거하거나 규칙으로 단일화('비우기'·'제약 없음'·허용오차 명시).
5. **생성형은 과정으로** — 결정적으로 못 박지 못하는 산출물은 결과 채점에서 빼고 채팅 로그(과정) 점수로만 본다. 결과 점수의 결정성을 절대 희생하지 않는다.

> **요컨대**: 결과 채점의 생명은 *결정성*이다. 직무가 무엇이든, 최종 제출은 "규칙으로부터 유일하게 계산되는 값들로 채운 통제된 xlsx"여야 한다. 리포트·우선순위처럼 보이는 과제도 **기준을 입력으로 제공(A)** 하고 **구조화 슬롯(B)** 으로 받으면 청년주택과 동일한 채점 가능성을 얻는다. 못 박이지 않는 창의·문장 영역은 과정 점수가 흡수한다.
