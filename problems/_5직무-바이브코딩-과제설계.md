# 5개 직무 × 3단계 바이브코딩 AX 과제 — 설계 (75 사례)

> 입력 자료: `2025 부서별 AX 과제_v.2.xlsx`(18개 부서 시트), `AI 이용현황 설문조사_결과보고_0617.xlsx`(1,289명)
> 레퍼런스: `problems/ai-native-challenge-2026` (청년주택 입주 자동화) — **이 문제가 2단계(기준) 난이도다.**
> 대상: 대학생 / 환경: 내부망 code-server(웹 fetch·검색 불가) / 도구: Claude Code

## 0. 이번 업그레이드에서 바뀐 것 (컨셉)

1. **모든 사례 = "신입이 입사해서 부여받은 실제 업무를 바이브코딩으로 해결한다".**
   각 과제의 시나리오는 *사수/팀장이 신입에게 던지는 업무 지시*로 쓴다.
   ("입사 첫 주, 사수가 '이거 좀 정리해줘'라고 넘긴 일" 톤.)
2. **난이도를 1~3단계로 사다리화.** 레퍼런스(청년주택)가 **정확히 2단계**다.
   - 1단계 = 그보다 쉽다(입문). 2단계 = 레퍼런스급(기준). 3단계 = 그보다 어렵다(심화).
3. **5직무 × 3단계 × 5사례 = 총 75개 사례.**
   소재는 `AX 과제` 파일의 실제 업무에서, 난이도는 `설문`이 보여준 대상층 수준에 맞춰 조절한다.

기존 5개 과제(설문분석·정산대사·멀티채널성과·외주비산정·경쟁비교)는 **각 직무의 2단계 대표 사례**로 그대로 흡수했다.

## 1. 두 파일에서 뽑은 핵심 사실

### AX 과제 파일 — "직무별로 자동화하고 싶은 실제 반복업무" 목록
18개 부서 시트가 전부 *현업이 직접 적어낸* 업무개선 후보다. 5개 직무에 입힐 **진짜 시나리오**가 여기 다 있다.

| 직무 매핑 | AX 파일에서 나온 실제 업무 (소재 풀) |
|---|---|
| 일반-범용 | 만족도 조사결과 분석(주관식 분류·요약), 매뉴얼 검색 지원, 보고서 요약, 출결/비품/명부 정리, 헬프데스크 분류 |
| 경영/사무 | 손익예측·장부 병합·공용비 배부(재경실), 월정산 ERP↔결제사 **불일치 대사**(개발부), 출고·반품 이상값(블랙라벨), 급여·근태·경비·채용 |

| 기획 | 콘텐츠 아이템 발굴, **경쟁 채널 비교 리포트**, 교재 시장분석, 모집요강 변경 비교, 연도별 전형 비교표, 포트폴리오 우선순위 |

### 설문 파일 — 난이도 보정의 근거
- 응답자 = **2030 대학생·구직자 1,289명** (정확히 우리 시험 대상층).
- AI 사용 72% / 미사용 28%. 그런데 **실사용도 대부분 기초**:
  - 단순 Q&A 24% · 자료분석 위임 19% · 다단계 위임 12.5% · **파일·코드 직접 처리 9.6%** · **자동화 워크플로우 6.4%**.
- 도구: LLM 챗봇 85.7% vs **코딩툴(Claude Code/Cursor 등) 10.6%**.
- 요청 방식: 상황 서술 36.5% · 짧은 질문 34% · **역할/형식/제약까지 구조화 8.5%**.
- 검토 방식: 한 번 읽고 수정 39% · 그냥 사용 30% · **출처·실행 검증 18.6%**.

> **결론(스윗스팟)**: 대상층은 "챗봇에 붙여넣기"는 익숙하지만 **다파일·대량·다규칙·정형출력**은 거의 못 한다. 그래서 시나리오는 한눈에 이해되되, 손/챗봇으로는 도저히 못 풀고 **Claude Code 오케스트레이션(파일 읽기 → 처리 코드 작성 → xlsx 채우기 → 검증)** 을 해야만 풀리는 문제가 정답 난이도다. 이 스윗스팟의 *중앙*이 2단계, *아래/위*가 1·3단계다.

## 2. 레퍼런스의 "복제해야 할 DNA" (모든 75 사례 공통)

청년주택 문제가 좋은 평가 도구인 이유 = 아래 6개를 모든 사례가 단계와 무관하게 물려받는다.

1. **현실 직무 시나리오** — "신입인 당신이 ○○ 업무를 받았다. 이 반복작업을 AI에 맡겨라." (AX 파일에서 차용 → 진짜 같음)
2. **흩어진 비정형 입력 + 정형 명부** — 정보가 PDF/이미지/여러 엑셀에 흩어져 있고, 처리 대상은 xlsx 명부.
3. **추출 → 규칙 적용 → 고정 양식 출력** — 채점은 **주어진 `submission_template.xlsx`에 채운 결과만**.
4. **2단 에스컬레이션** — Part 1: 각 행을 판정/집계(기초 표 완성). Part 2: 그 위에 **다조건 필터/계산**을 쌓음. (3단계는 Part 3까지 갈 수 있음)
5. **"새 입력에도 똑같이 돌아가야 함"** — 값 하드코딩이 아니라 *재사용 가능한 처리*를 만들었는지를 가름.
6. **양만으로 손풀이를 차단** — 대량이라 사람이 못 함 → 반드시 자동화. (레퍼런스는 53명×5공고=265행)

## 3. ⭐ 3단계 난이도 사다리 (설계의 척추)

난이도는 아래 **7개 노브**로만 조절한다. 같은 직무·같은 채점 가능성을 유지한 채 노브만 올린다.

| 난이도 노브 | 1단계 (입문) | **2단계 (기준 = 레퍼런스)** | 3단계 (심화) |
|---|---|---|---|
| **파일 수 / 종류** | 1~2개, **엑셀 위주** | 2~4개, **엑셀 + 규칙 PDF** | 4개+, **이종 다출처**(여러 PDF·여러 xlsx) |
| **규칙 출처** | 안내 시트의 단순 표/키워드 | **규칙 PDF 1종**(읽어서 적용) | **규칙 PDF 여러 종 + 가중치/산식** |
| **규칙·예외 수** | 1~2개 조건 | 3~4개 조건 + 예외 1~2 | 다규칙 + 연쇄 예외 + 우선순위 |
| **입력 지저분함** | 비교적 정제됨 | 표기 불일치·결측·병합셀 일부 | 스키마 제각각·단위 혼재·노이즈 많음 |
| **멀티모달** | 없음 | **이미지 1종**(영수증·단가표 등) | **이미지 다수**(차트·캡처·감정서 OCR) |
| **데이터 양** | 100~300행 | 200~500행 / 교차곱 | 500행+ / 다파일 조인 |
| **Part 구성** | Part 1 위주(또는 단순 Part 2) | **Part 1 + Part 2**(다조건 동시통과/누적계산) | **Part 1~3**(정규화→계산→가중스코어·랭킹) |

**레퍼런스를 2단계로 고정하는 근거 (calibration anchor):**
- 파일: 공고 PDF 5개 + 지원자 xlsx → "엑셀 + 규칙 PDF" ✔
- 규칙: PDF에서 자격요건 추출해 적용(발명 아님) ✔
- Part 1: 53×5=265행 판정 + 불가사유 세미콜론 표기 ✔
- Part 2: 신청자격·보증금·월세·입주시기 **4조건 동시통과** + `고정`/`비우기` 특수표기 ✔
- 멀티모달 없음, 가중치 스코어링 없음 → 3단계는 아님 ✔

→ **1단계는 "PDF 없이 엑셀 + 안내시트 규칙으로 끝"**, **3단계는 "이미지 OCR + 다PDF 가중 스코어링·랭킹"** 으로 레퍼런스 양옆을 잡는다.

### 단계별 "가르는 능력"
- **1단계** — 파일을 코드로 열어 **대량을 일관 처리**할 수 있는가(챗붙기 한계 돌파). 합격선.
- **2단계** — **규칙을 외부 문서에서 읽어 정확히 적용** + **다조건/멀티모달** 오케스트레이션.
- **3단계** — **이종 다출처 종합 + 가중 산식·랭킹**까지. 검증 습관(18.6%)이 없으면 숫자가 틀림.

## 5. 공통 운영 규격 (레퍼런스와 동일하게)

각 사례 폴더는 레퍼런스 구조를 그대로 따른다. **단계가 올라가면 `data/`의 파일 종류와 `partN/`의 수가 늘어난다.**

```
problems/<job>-L<단계>-<번호>/
├── 0_시작하기.md          # 신입 업무 시나리오 + 파일 안내 + 진행 순서
├── 1_문제1.md             # Part 1 (기초 표 완성)
├── 2_문제2.md             # Part 2 (다조건/계산 심화)
├── 3_문제3.md             # (3단계만) Part 3 (정규화→가중스코어·랭킹)
├── CLAUDE.md, AGENTS.md   # "Vibe Coding Assessment Facilitator" 역할 + submit 안내
├── data/                  # 비정형 소스 (pdf / png) — 단계↑ 일수록 다출처·멀티모달
└── part1/ · part2/ [· part3/]
    ├── <input>.xlsx
    └── submission_template.xlsx   # '안내' 시트에 칸 규격 → 채점 대상은 이 파일뿐
```

**단계별 가드레일 (대학생 + Claude Code 기준)**
- **공통** — ✅ 시나리오 한 문단으로 이해 / 산출물은 "표를 채워라"로 명확 / 웹 0회(근거는 제공 파일 안) / 정답 결정적(애매한 건 '비우기'·'제약 없음'·허용오차로 봉쇄).
- **1단계** — 손/챗봇으로 안 되는 **양**(수백 행)만으로 가른다. 규칙은 안내시트에. PDF·이미지 없음. *너무 어렵게 만들지 말 것* — 합격선 측정용.
- **2단계** — **규칙 PDF 1종 + 멀티모달 1종 + Part 2 다조건 동시통과**를 *반드시* 넣는다(레퍼런스와 동률).
- **3단계** — **이종 다출처 + 가중 산식/랭킹 + Part 3**. 단, 규칙·가중치·산식은 **모두 PDF로 명시**(추론으로 발명시키지 않음 — §6.4 A). *너무 어려움 방지*의 핵심.

**채점 친화 설계**: 행 순서 무관, 칸 이름·형식은 안내 시트에 고정, 불가/예외 표기(세미콜론·`고정`·`비우기`) 통일 → 자동 채점 스크립트로 정오 판정.

## 6. ⭐ 결과 채점 가능성(Evaluability) — 설계의 1급 제약

> 평가 리포트(`CATCHUP AX AI 역량 검사 리포트_V2.0`)를 역설계하면 이 시험은 **두 점수**를 낸다.
> *결과 점수가 자동 채점 가능한가*를 통과 못 하는 사례는 — 단계 불문 — 폐기 대상이다.

### 6.1 채점 구조
| 점수 | 무엇으로 | 채점 방식 | 함의 |
|---|---|---|---|
| **AI 협업(과정)** | 채팅 로그 | 5역량(문제정의·출력검토·환경관리·완성가치·불확실성)을 대화 행동으로 | **도메인·단계 무관**. 동일 루브릭 → 과제는 "좋은 협업 행동 유도"만 하면 됨 |
| **문제 해결(결과)** | 제출 xlsx | 정확도 + 형식 준수 | **정답키 대조 + 자동 형식검사**. 결과가 결정적이지 않으면 못 만든다 |

### 6.2 제1법칙
> **모든 채점 대상 칸은 (제공 파일 + 명시된 규칙)으로부터 단일 정답값(또는 닫힌 정답집합)으로 환원되어야 한다.**
> 학생이 *기준을 발명*해야 하면 채점 불가 → **그 기준을 입력 파일로 제공**해 '발명'을 '적용'으로 바꾼다.
> 생성형 산출물(산문·카피)은 ① 결과 채점에서 빼 과정 점수로, 또는 ② 구조화 슬롯 + 검증 가능 제약으로 *근거/형식*만 채점. **산문 품질 자체는 결과 채점하지 않는다.**

### 6.3 채점 가능한 정답 5유형
| 유형 | 예 | 자동 채점법 |
|---|---|---|
| **Exact** | 가능/불가, 분류 카테고리, 불일치 여부 | 정답키와 셀 단위 일치율 |
| **Set** | 충족 콘텐츠 ID 집합, 선택 옵션 | 집합 일치(정밀도/재현율) |
| **Computed** | 외주비·집계·배부액 | 허용오차(±0 또는 ε) |
| **Rank** | 우선순위 랭킹 | 산식 적용 결과의 정렬 일치 |
| **Format/Grounding** | 컬럼·값 형식, 카피의 수치 인용·길이·개수 | 정규식·길이·참조 무결성 |

### 6.4 "애매한 것"을 채점 가능하게 — 4기법
- **(A) 기준 제공** — 우선순위/가중치/분류기준을 학생이 정하게 하지 말고 `평가기준.pdf`·`분류기준.pdf`·`단가표.pdf`로 **준다**. (3단계 가중 스코어링이 채점 가능한 이유)
- **(B) 구조화 슬롯** — "리포트를 써라"가 아니라 "요약 시트의 이 칸들을 채워라". 각 칸은 계산값 → 결정적.
- **(C) 근거 결속** — 생성 텍스트엔 "실제 조회수 포함·해시태그 정확히 3개·20자 이하" 같은 검증 가능 제약.
- **(D) 폐쇄화** — 입력 데이터를 *설계할 때* 각 항목이 한 정답에만 매핑되게(경계 모호 항목 배제). 모호하면 '비우기'·'제약 없음'.

### 6.5 단계별 채점유형 지도 (난이도가 올라도 결정성은 유지)
| 단계 | 주 채점유형 | 채점 가능성 확보 장치 |
|:--:|---|---|
| 1 | Exact · Computed | 규칙을 안내시트 표/키워드로 — 발명 여지 0 |
| 2 | Exact · Set · Computed | 규칙 PDF 제공(A) + 입력 폐쇄화(D) + 생성물은 근거결속(C)으로 분리 |
| 3 | Computed · Rank (+Set) | **가중치·산식을 PDF로 제공(A)** → 우선순위도 Rank로 결정. 비교표는 수치/닫힌값 필드(B,D). 근거 산문은 미채점 |

**기획 3단계 예 (우선순위가 정해지는 이유):** `평가모델.pdf`에 산식을 박는다.
```
우선순위 점수 = 0.4×시장성 + 0.3×실행용이성 + 0.3×자사적합도
- 시장성: competitor PDF '월 검색량' 정규화(0~10)
- 실행용이성: our_metrics.xlsx '예상 공수(주)' 역수 정규화
- 자사적합도: 평가표 적합도 코드(A=10,B=6,C=3) 그대로
```
→ 제출 양식의 모든 칸이 Computed/Rank, **정답키 1개**. 학생의 역량은 '판단'이 아니라 *여러 자료에서 데이터를 정확히 뽑아 산식을 올바로 적용*하는 데서 평가.

**마케팅 생성물 예:** "좋은 리포트"를 채점하지 말고 *결정적 슬롯*을 채점 — `최고 ROI 캠페인=CAMP-03`(Set), `해당 ROI=312%`(Computed±1%p), `기준미달 캠페인 수=2`(Exact). 카드뉴스 카피는 별도 시트에서 **형식/근거만**(1위 콘텐츠 대상·실제 수치 포함·제목≤20자·해시태그 3개), 문장력은 과정 점수.

### 6.6 모든 사례 공통 채점 규격
1. **제출물은 항상 `submission_template.xlsx`** — 마크다운·자유문서 금지. '안내' 시트에 컬럼·값 형식·시트명 고정.
2. **정답키 + 자동 채점 스크립트를 과제와 함께 제작** — 셀 단위 비교(Exact/Set/Computed/Rank) + 형식 검사. *스크립트를 못 짜는 사례는 출제하지 않는다*가 출제 게이트.
3. **부분점수 차원 분리** — 정확도/형식/누락을 분리 집계.
4. **모호성 봉쇄** — 정답이 갈릴 항목은 입력 설계 단계에서 제거하거나 규칙으로 단일화.
5. **생성형은 과정으로** — 결정적으로 못 박지 못하는 산출물은 결과 채점에서 빼고 채팅 로그(과정)로만. 결과 점수의 결정성을 절대 희생하지 않는다.

## 7. 한 줄 요약

> 레퍼런스(청년주택)를 **2단계 기준점**으로 고정하고, **7개 난이도 노브**(파일수·규칙출처·예외수·지저분함·멀티모달·데이터양·Part수)만 위아래로 움직여 **1단계(엑셀+안내시트, 입문) ↔ 3단계(다출처+멀티모달+가중랭킹, 심화)** 를 만든다. 소재는 `AX 과제`의 실제 업무를 **"신입이 받은 업무"** 로 포장하고, **5직무 × 3단계 × 5사례 = 75개** 를 깐다. 어떤 단계든 최종 제출은 "규칙으로부터 유일하게 계산되는 값으로 채운 통제된 xlsx" — *시나리오는 쉽게, 풀이는 Claude Code 없이 불가능하게, 채점은 결정적으로*.
