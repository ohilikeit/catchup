# INPUT_GUIDE — policies.csv 채우는 법 (출제자용)

이 과제의 **모든 데이터·정답은 단일 입력 파일 `policies.csv` 하나에서 생성**된다.
`policies.csv`를 실제 정책으로 채우고 `build_dataset.py`를 재실행하면, 회원 DB·제출
양식·정답키가 **항상 정합하게 함께 갱신**된다. 수기로 엑셀을 고치지 말 것.

> ⚠️ **현재 들어 있는 `policies.csv`는 실제 서울 청년정책을 본뜬 샘플 겸 템플릿이다.**
> 컬럼 형식과 자격 매칭 구성을 그대로 보여주기 위한 예시이므로, 출제 시 **실제
> 정책 데이터로 행을 교체**해서 쓰면 된다. 헤더(컬럼명)는 절대 바꾸지 말 것.
> **매칭은 신청 날짜를 보지 않는다 — 자격만 본다.** `apply_start/apply_end` 컬럼은
> 미사용·참고용으로만 남아 있고 매칭·채점에 쓰이지 않는다.

## 1. 컬럼 의미 / 형식 (헤더 순서 고정)

| 컬럼 | 의미 | 형식 / 예시 |
|------|------|------------|
| `policy_id` | 정책 고유키 | `YP01`, `YP02` … (중복 금지) |
| `name` | 정책명 | 자유 문자열 (쉼표 포함 시 따옴표로 감쌈) |
| `field` | 분야 | `일자리` \| `주거` \| `금융복지` \| `교육문화` (이 4개만) |
| `poster_file` | 포스터 파일명 | `데이터/1_포스터/` 안의 실제 파일명. 비워도 채점엔 무관 |
| `region` | 거주 요건 | 3형식 중 하나 (아래 §2) |
| `age_min` | 만 나이 하한 | 정수. 비우면 하한 없음 |
| `age_max` | 만 나이 상한 | 정수. 비우면 상한 없음 |
| `employment` | 취업 요건 | `무관` \| `미취업` \| `재직` |
| `company_size` | 기업규모 요건 | 문자열 예: `중소기업`. 회원 `기업규모`와 일치해야 통과. **비우면 무관** |
| `income_max_month` | **본인** 월 소득 절대 상한(원) | 정수. 포스터에 '본인 월소득 ○○만원 이하'처럼 금액이 명시될 때. **비우면 무관** (0과 빈칸은 다름) |
| `income_median_pct` | **가구 기준중위소득 비율(%)** | 정수(예: `150`). 포스터가 '(가구) 기준 중위소득 ○○% 이하'면 그 퍼센트. 회원 `가구원수`별 상한으로 환산해 `월소득(원)`과 비교. **비우면 무관** (`income_max_month`와 별개 축) |
| `income_year_max` | **연 소득 상한(원)** | 정수. 회원 `연소득(원)`이 그 이하면 통과. **비우면 무관** (월소득 상한과 별개 축) |
| `no_house` | 무주택 필수 | `Y` 이면 무주택자만. 비우면 무관 |
| `enroll_status` | 학력/재학 요건 | `재학`(대학·대학원 재학/휴학) \| `졸업`(졸업 후). 비우면 무관 |
| `marital` | 혼인 요건 | `신혼부부`(기혼) \| `미혼`. 비우면 무관 |
| `matchable` | 회원 명단으로 자격 확인 가능 여부 | `Y`(기본) \| `N`. **`N` = 회원 DB로 대상 판별 불가 → 어떤 회원도 통과 못 함(추천 0건)** |
| `apply_start` | 신청 시작 | `YYYY-MM-DD` — **미사용·참고용**(매칭·채점 안 씀) |
| `apply_end` | 신청 마감 | `YYYY-MM-DD` — **미사용·참고용**(매칭·채점 안 씀) |

빈 칸 = "제약 없음". 포스터에 명시되지 않은 자격은 **반드시 비운다**.

> ⭐ **`matchable=N`의 의미(판별 불가 정책).** 자격의 **핵심 게이트가 회원 명단에 컬럼이 아예 없는
> 정보**(부모/배우자 소득·자산, 학자금대출 보유, 가구 전체 소득·자녀 수 등)인 정책은 회원 DB로
> 대상을 가릴 수 없다. 이런 정책은 `matchable=N`으로 두면 **자격이 맞아 보여도 어떤 회원도
> 통과시키지 않아 추천 0건**이 된다 (`member_passes()`가 즉시 False). `matchable=N` 정책은
> `build_dataset.py`가 경계 회원도 심지 않는다(어차피 0매칭). 정책표 정답에서는 **회원 명단으로
> 잴 수 없는 자격 칸만 빈칸**으로 두고, **측정 가능한 자격(거주지·연령·본인 월소득 등)은 포스터대로
> 채운다**(추천 0건은 확인 불가 게이트 때문이지, 모든 자격을 비워서가 아니다). `matchable`은
> 정책표(제출 양식)에 노출하지 않는 **운영 전용** 컬럼이다.

> ⭐ **매칭 축 ↔ 회원 컬럼 교집합(불변식).** 매칭에 쓰는 모든 자격 축은 `2_회원명단.xlsx`에
> 대응 컬럼이 반드시 있어야 판단이 가능하다. 현재 최대 9축의 대응은:
> 연령↔`생년월일` · region↔`거주지` · employment↔`취업상태` · company_size↔`기업규모` ·
> income_max_month↔`월소득(원)` · **income_median_pct↔`월소득(원)`+`가구원수`**(가구원수별 상한으로 환산) ·
> **income_year_max↔`연소득(원)`** · no_house↔`주택소유여부` · enroll_status↔`재학상태` · marital↔`혼인여부`.
> **새 자격 축을 추가하려면 `build_dataset.py`의 회원 합성(컬럼·경계 생성)과 `member_passes()`,
> `grade.py`의 `P1_FIELDS`에 짝이 되는 회원 컬럼·규칙을 함께 추가**해야 한다(컬럼만 늘리면
> 매칭 불가). 일부 정책에서 그 축이 비어(null) 있어도 무방하다.

## 2. region — 지역 요건 3형식

- `전국` → 모든 회원 통과
- `<시도>` → 회원 시도와 일치해야 통과. 예: `서울특별시`, `경기도`
- `<시도> <자치구>` → 시도 **AND** 자치구 모두 일치. 예: `서울특별시 관악구`

지역 다양성을 위해 1~2개 정책은 자치구 한정(예: `서울특별시 관악구`)으로 두면 변별력이
올라간다. 나머지는 `서울특별시` 전체로 둔다.

## 3. 연령 / 소득 / 취업 / 무주택 설정

- **연령**: `age_min`/`age_max`는 만 나이. 한쪽만 있어도 되고, 둘 다 비우면 연령 무관.
  만 나이는 회원 생년월일과 고정 기준일로 계산된다(생일 안 지났으면 -1).
- **소득(두 축)**: ① `income_max_month` = **본인** 월소득 절대 상한(원). 회원 `월소득(원)`이 그 이하면 통과(`<=`).
  포스터에 '본인 월소득 ○○만원 이하'처럼 **금액이 명시될 때만**(예: 희망두배 `2550000`). ② `income_median_pct`
  = **가구 기준중위소득 %**. 포스터가 '(가구) 기준 중위소득 ○○% 이하'면 그 퍼센트(예: `150`)를 적는다 — 절대 금액으로
  환산하지 말 것. 매칭 시 회원 `가구원수`별 상한(`median_cap` = `MEDIAN_INCOME[가구원수] × % ÷ 100`, 원단위 반올림)으로
  환산해 `월소득(원)`과 비교한다(가구원수가 크면 상한도 큼). 가구원수별 상한표는 `2_추천리스트` 파일의 '소득기준표' 시트로
  학생에게 제공된다. 두 축 모두 소득 무관이면 **빈칸**.
- **취업**: `미취업` 정책은 회원 취업상태가 `미취업`/`단기근로`일 때, `재직` 정책은
  `재직`/`단기근로`일 때 통과. `무관`이면 모두 통과. (예: 청년수당=`미취업`, 희망두배=`재직`)
- **기업규모**: `company_size`가 있으면 회원 `기업규모`가 그 값과 같을 때만 통과(예:
  `중소기업`). 비우면 무관. 회원 `기업규모`는 취업상태가 `미취업`이면 `없음`, 그 외(재직/
  단기근로)면 `중소기업`/`중견기업`/`대기업`/`공공기관` 중 하나다. (예: YP08 중소기업감면)
- **연소득**: `income_year_max`(연 소득 상한, 원)가 있으면 회원 `연소득(원)`이 그 이하면 통과
  (`<=`). 월소득 상한(`income_max_month`)과 **별개 축**이다. 비우면 무관. (예: YP07 청년미래적금=`75000000`)
- **무주택**: `no_house=Y`면 회원 `주택소유여부=아니오`만 통과.
- **학력/재학**: `재학` 정책은 회원 `재학상태`가 `재학`/`휴학`일 때, `졸업` 정책은 `졸업`일 때
  통과. 비우면 무관. (예: 문화패스·학자금=`재학`, 청년수당=`졸업`)
- **혼인**: `신혼부부` 정책은 회원 `혼인여부=기혼`, `미혼` 정책은 `미혼`만 통과. 비우면 무관.

## 4. 매칭 대상 — 날짜 무관, 자격만 본다

**매칭은 신청 날짜를 보지 않는다.** 매칭 발송 대상 = **`matchable != N` 인 모든 정책**(신청
날짜와 무관). 회원이 9축 자격을 모두 통과하면 추천한다.

```
대상정책 = [p for p in policies if p.matchable != 'N']        # 날짜 필터 없음
```

- **대상(발송)으로 만들려면**: `matchable`을 비우거나 `Y`로 두고, 자격(연령·지역·소득 등)을 채운다.
- **판별 불가(추천 0건)로 만들려면**: `matchable=N`으로 둔다 → 정답 매칭 0건.
- `apply_start/apply_end`는 채워 두어도 **매칭·채점에 쓰이지 않는다**(미사용·참고용).

**고정 기준일 `ASSIGN_DATE = 2026-06-28`** (build_dataset.py 상단 상수, `datetime.now()`
사용 안 함)은 **만 나이 계산에만** 쓴다(날짜 필터에는 쓰지 않음). 기준일을 바꾸려면
`build_dataset.py`의 `ASSIGN_DATE`만 고치면 만 나이 경계가 그 날짜 기준으로 재계산된다.

현재 CSV는 정책 **9건** 구성이다:
- **대상(`matchable != N`, 매칭 발생) — 6건**: `YP01`(미취업·졸업·중위소득150%)·`YP02`(21~23·중위소득150%)·`YP03`(무주택·중위소득150%)·`YP05`(중랑구·미취업)·`YP07`(연소득상한 75,000,000 **+ 가구중위소득 200%**)·`YP08`(재직·기업규모=중소기업·15~34).
- **판별 불가(`matchable=N`) — 3건**: `YP04` 희망두배(부모/배우자 소득·자산 확인 불가)·`YP06` 학자금(학자금대출 보유 확인 불가)·`YP09` 꿈나래통장(가구중위소득+자녀 확인 불가). 모두 **정답 매칭 0건**. 다만 정책표에는 **측정 가능한 자격(거주지·연령·본인월소득)은 채우고**, 회원 명단에 컬럼이 없는 자격(부모소득·학자금대출·자녀 등)만 **빈칸**으로 둔다(추천 0건은 이 게이트 때문).

## 5. 포스터 파일 배치

- 학생이 자격요건을 읽어낼 **실제 홍보 1_포스터/이미지**를 `데이터/1_포스터/` 폴더에 넣는다.
- 파일명은 CSV의 `poster_file` 값과 **똑같이** 맞춘다(예: `YP01_청년수당.png`).
- 코드는 포스터를 만들지 않는다 — 출제자가 실제 정책 포스터(1~2p)를 직접 배치한다.
- `poster_file`이 비어 있어도 데이터 생성·채점은 동작한다(포스터는 학생용 입력일 뿐).

## 6. 재생성 → 채점 절차

```bash
# 1) policies.csv 를 실제 정책으로 채운다 (헤더 유지)
# 2) 데이터/1_포스터/ 에 poster_file 과 같은 이름으로 포스터를 넣는다
# 3) 데이터·정답 동시 생성
python3 eval/answer_key/build_dataset.py
#    → 데이터/2_회원명단.xlsx, 1_정책정리표_제출용.xlsx, 2_추천리스트_제출용.xlsx
#    → eval/answer_key/1_정책정리표_정답.xlsx, 2_추천리스트_정답.xlsx
# 4) 학생 제출물 채점 (P1 셀 비교 + P2 (회원ID,정책ID) 집합 F1)
python3 eval/grade.py \
  --part1 데이터/1_정책정리표_제출용.xlsx \
  --part2 데이터/2_추천리스트_제출용.xlsx \
  --answer-dir eval/answer_key
```

`policies.csv`만 바꾸면 회원 함정·정답이 새 정책 축에 맞춰 generic하게 재생성되므로,
출제자는 정책 데이터만 정확히 입력하면 된다.
