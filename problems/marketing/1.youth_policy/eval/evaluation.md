# 평가 방식 (evaluation)

> 제출물 2개를 **정답키와 자동 대조**한다. 채점 스크립트는 [`grade.py`](grade.py), 정답키는 [`answer_key/`](answer_key/).
> 결과(문제 해결) 점수만 다룬다. 과정(AI 협업) 점수는 채팅 로그 기반 별도 루브릭.

---

## 1. 제출물 스키마 (정답이 결정되는 형식)

### Part 1 — `1_정책정리표_제출용.xlsx` · 시트 `정책정리`
행 단위 = **정책 1건** (`policies.csv`에 정의된 모든 정책, `policy_id` = `YP01`…). 정답은 모두 `policies.csv` 값에서 나온다. 컬럼 순서: `정책ID,정책명,분야,거주지요건,연령_최소,연령_최대,취업요건,기업규모요건,월소득상한(원),월소득_중위소득기준(%),연소득상한(원),무주택요건,학력요건,혼인요건`.

| 컬럼 | 형식 / 허용값 | 채점유형 |
|---|---|---|
| `정책ID` | `YP01`… (키, `policy_id`) | — |
| `정책명` | 문자열(`name`) — **양식에 미리 주어짐(채점 안 함)** | — |
| `분야` | `일자리`\|`주거`\|`금융복지`\|`교육문화` (`field`) — **양식에 미리 주어짐(채점 안 함)** | — |
| `거주지요건` | 정책 `region` 그대로: `전국` \| 시도(`서울특별시`·`경기도`…) \| `시도 자치구`(`서울특별시 관악구`…) | Exact |
| `연령_최소` | 정수(만 나이, `age_min`). 하한 없으면 **빈칸** | Exact |
| `연령_최대` | 정수(만 나이, `age_max`). 상한 없으면 **빈칸** | Exact |
| `취업요건` | `무관` \| `미취업` \| `재직` (`employment`) | Exact |
| `기업규모요건` | 문자열(`company_size`, 예: `중소기업`). 무관이면 **빈칸** | Exact |
| `월소득상한(원)` | 정수(원, `income_max_month`) — **본인** 월소득 절대 상한. 없으면 **빈칸** | Exact |
| `월소득_중위소득기준(%)` | 정수(`income_median_pct`, 예 `150`) — 가구 기준중위소득 %. 없으면 **빈칸**. 가구원수별 금액 환산은 Part2 매칭 단계 | Exact |
| `연소득상한(원)` | 정수(원, `income_year_max`). 상한 없으면 **빈칸** | Exact |
| `무주택요건` | `필요`(`no_house=Y`) 또는 **빈칸** | Exact |
| `학력요건` | `재학` \| `졸업` (`enroll_status`) 또는 **빈칸** | Exact |
| `혼인요건` | `신혼부부` \| `미혼` (`marital`) 또는 **빈칸** | Exact |

> 정책명·분야는 제출 양식에 **미리 채워져 제공**된다(채점 대상 아님). **매칭은 신청 날짜를 보지 않으므로 신청시작/신청마감/마감2주이내여부 칸은 양식에서 삭제됐다.** `apply_start/apply_end`는 `policies.csv`에 미사용·참고용으로만 남아 있다(추출·채점 대상 아님). 학생은 자격(거주·연령·취업·기업규모·월소득·연소득·무주택·학력·혼인)만 추출한다. 포스터에 명시 안 된 자격 칸은 **빈칸이 정답**이다(제약 없음). **판별 불가 정책(`matchable=N`: YP04·YP06·YP09)도 회원 명단에 컬럼이 없는 자격(부모소득·학자금대출·자녀 등)만 빈칸이고, 측정 가능한 자격(거주지·연령·본인 월소득)은 포스터대로 채우는 게 정답**이다(추천만 0건). `matchable`은 정책표에 노출하지 않는다(운영 전용). 채점은 `무관`≡빈칸, 무주택 `필요`≡`Y`/`예`/`O`로 정규화한다.

### Part 2 — `2_추천리스트_제출용.xlsx` · 시트 `타게팅`
행 단위 = **(회원 × 추천정책) 1조합**. 자격 조건(나이·거주·취업·기업규모·월소득·연소득·무주택·학력·혼인)을 모두 통과한 조합만 기록(신청 날짜는 보지 않음). 어떤 정책에도 안 맞는 회원은 적지 않는다. **`matchable=N` 정책은 어떤 회원도 통과시키지 않으므로 추천 0건이 정답**이다.

| 컬럼 | 형식 | 채점유형 |
|---|---|---|
| `회원ID` | `2_회원명단.xlsx`의 식별자 (`M0001`…) | Set |
| `추천정책ID` | `policies.csv`의 `policy_id`(`YP01`…) 중 **`matchable != N` 정책만**(날짜 무관) | Set |

> 채점은 **(회원ID, 추천정책ID) 튜플의 집합**으로 한다. **행 순서 무관**, 중복 행은 1개로 간주.

## 2. 채점 로직 (`grade.py` 구성요소)

```
grade.py
├─ load_xlsx(path, sheet)             # openpyxl 로드 → 정규화(공백 strip, 날짜 ISO, 숫자 캐스팅)
├─ grade_part1(sub, ans)             # 정책정리표: 셀 단위 비교
│   • 키(정책ID)로 행 정렬·조인
│   • P1_FIELDS = 거주지요건·연령_최소·연령_최대·취업요건·기업규모요건(norm_constraint)·
│     월소득상한(원)·월소득_중위소득기준(%)·연소득상한(원)(norm_int)·무주택요건(norm_house)·학력요건·혼인요건
│     (신청시작/마감/마감2주이내여부 칸은 양식에서 삭제 — 채점 대상 없음)
│   • 필드별 일치 집계 → 필드별 정확도 + 전체 셀 정확도
├─ grade_part2(sub, ans)             # 타게팅: 집합 비교
│   • {(회원ID, 정책ID)} 집합화
│   • precision / recall / F1
│   • 오발송(정답 아닌데 보냄=FP)·누락(보내야 하는데 빠짐=FN) 분리 집계
├─ checks()                          # 무결성 검사
│   • Part2의 정책ID가 valid_policies(= `matchable != N` 전체, 날짜 무관)에 드는지
│   • Part2에 'matchable=N' 정책 추천이 섞였는지 (판별 불가 정책 추천 = 오발송 플래그)
│   • 회원ID·정책ID 참조 무결성(존재하지 않는 ID 사용 탐지)
└─ report()                          # 부분점수 차원 분리 출력(JSON + 콘솔 표)
```

### 정규화 규칙(채점 관용)
- `norm_constraint`(취업요건·기업규모요건): `무관`/`없음`/`제한없음`/빈칸 → 동일(`제약없음`)으로 본다.
- `norm_int`(월소득상한(원)·월소득_중위소득기준(%)·연소득상한(원)): 천단위 콤마 제거 후 정수 비교. 빈칸=제약없음, `0`=상한 0원으로 구분.
- `norm_house`(무주택요건): `필요`/`Y`/`예`/`O`/`무주택`/`필수` → `필요`. 빈칸=무관.
- 빈 집합(자격 칸이 양쪽 모두 빈칸·정책 추천 0건)의 F1=1로 처리. 템플릿의 '예시' 회원ID 행은 무시한다.
- 문자열: 앞뒤 공백·중복 공백 제거 후 비교. `서울특별시 관악구`/`서울특별시  관악구`는 동일 처리(공백 무시).
- 숫자: `3,600,000`/`3600000` 동일. 빈칸과 `0`은 **구분**(빈칸=제약없음, 0=상한 0원).
- 불리언: `Y/N`, `예/아니오`, `True/False` 매핑 허용.

## 3. 배점 (결과 점수 100점 기준 예시)

| 영역 | 배점 | 산정 |
|---|--:|---|
| Part 1 자격 추출 정확도 | 50 | (정확 셀 / 전체 채점 셀) × 50 |
| Part 2 타게팅 F1 | 40 | F1 × 40 |
| Part 2 무결성(유령ID·`matchable=N` 추천 0건) | 10 | 위반 1건당 감점 |

> **합격선(1단계 능력)**: Part 1을 채워 대량을 일관 처리. **변별(2단계)**: 경계값·주소 정규화를 모두 통과해 Part 2 F1을 끌어올림.

### 흔한 실패 = 의도한 함정 적중
- 만 나이를 출생연도 뺄셈으로 계산 → 생일 경계 회원 **오분류**.
- 주소를 문자열 그대로 비교 → `서울 노원구`를 자치구 매칭 실패 → **FN 급증**(누락).
- 지역 범위 오인 → 자치구·타시도 한정 정책을 '서울 전체'로 넘겨짚어 **FP/FN**, 또는 포스터에 없는 자격(무주택·소득)을 임의로 채워 매칭이 **틀어짐**.
- 판별 불가 정책(`matchable=N`: YP04·YP06·YP09)을 본인 자격이 맞아 보인다는 이유로 추천 → Part 2 **FP**(오발송). 확인 불가 게이트(부모소득·학자금대출·자녀)를 임의 숫자로 채우거나, 반대로 측정 가능한 칸까지 비우면 → Part 1 **셀 오답**.

## 4. 정답키 생성·관리

- 정답키(`answer_key/1_정책정리표_정답.xlsx`, `answer_key/2_추천리스트_정답.xlsx`)와 제공 데이터(`../데이터/`)는 **단일 입력 [`answer_key/policies.csv`](answer_key/policies.csv)** 에서 같은 스크립트로 나온다 → 정책·회원DB·정답이 항상 정합. (포스터 파일은 운영자가 `데이터/1_포스터/`에 직접 넣는다 — 코드 생성 아님)
- 정책을 바꾸려면 **`policies.csv`만 수정**하고 생성 스크립트를 다시 돌려 **데이터와 정답키를 동시 갱신**한다(생성물 수기 편집 금지). CSV 작성법은 [`answer_key/INPUT_GUIDE.md`](answer_key/INPUT_GUIDE.md).
- 생성기: [`answer_key/build_dataset.py`](answer_key/build_dataset.py) — `policies.csv` 읽기 → 회원 합성(경계 회원 자동 삽입) + 제출양식 + 정답키 + 매칭 정답을 일괄 산출. 매칭 대상 = `matchable != N` 인 모든 정책(날짜 무관). 기준일 `ASSIGN_DATE = 2026-06-28` 상수 고정(`datetime.now()` 미사용) — **만 나이 계산에만** 쓰고 날짜 필터에는 쓰지 않는다.

## 5. 채점 실행

```bash
# 학생 제출물 채점
python eval/grade.py \
  --part1 데이터/1_정책정리표_제출용.xlsx \
  --part2 데이터/2_추천리스트_제출용.xlsx \
  --answer-dir eval/answer_key
# → 콘솔 표 + result.json (영역별 점수·FP/FN 목록)
```
