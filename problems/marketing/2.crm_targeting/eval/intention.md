# 출제 의도 (intention)

> 이 문제가 **무엇을 측정**하고, **어떤 결함을 일부러 심었으며**, 학생이 **어떤 과정으로 풀기를** 기대하는지 핵심만 적는다.

## 한 줄 의도

> "정형화 안 된 캠페인 브리프(이미지·PDF)를 코드로 읽어 대상 조건을 정형화하고, 수백 명 고객과 다조건 매칭해 '누구에게 어떤 리텐션 캠페인을 보낼지' 타게팅 리스트를 뽑는다" — **신입 CRM 마케터의 라이프사이클 타게팅 업무를 챗봇 붙여넣기로는 못 풀고 Claude Code 오케스트레이션으로만 풀리게** 만든 문제. 모든 데이터·정답은 단일 입력 `campaigns.csv`에서 생성돼, 캠페인을 바꿔도 동일 구조로 재현된다.

## 측정하는 능력

| 축 | 무엇을 보는가 |
|---|---|
| **직무 능력 (마케팅 CRM)** | 캠페인의 대상 조건을 정확히 읽고, 휴면·등급·동의 같은 라이프사이클 세그먼트로 고객을 가른 뒤 "누구에게 무엇을" 보낼지 결정하는 리텐션 타게팅 감각. **휴면(N일 이상)과 활성(N일 이내)처럼 방향이 반대인 조건**을 혼동 없이 다루는지 |
| **AI 활용 능력** | ① 멀티모달(이미지·PDF OCR) 추출 ② 여러 파일을 코드로 열어 일관 처리 ③ 규칙을 데이터로 다뤄 재사용 가능한 분석 파이프라인 작성 ④ 결과 검증 |
| **문제 해결력** | 흩어진 비정형 입력 → 규칙 적용 → 정형 출력으로 환원하는 분해력. "만 나이", "휴면일수 = 기준일 − 최근주문일(날짜 파생)", "누적구매액 하한(≥, 방향 반대)", "주소 정규화" 같은 함정을 스스로 발견·처리. **브리프에 없거나 고객 명단으로 확인 불가한 조건은 비워야** 한다는 판단(과잉 제약 금지·무리한 추천 금지) |

> 설계 근거: [`../../../_6일반범용-마케팅-산업범용-업무형태-보강.md`](../../../_6일반범용-마케팅-산업범용-업무형태-보강.md)의 **MKT-L2-X1(고객 데이터로 라이프사이클 세그먼트 분리·휴면 추출, CRM/M8)** 을 실제 도메인(범용 이커머스 리텐션 캠페인)으로 구현한 사례다. 여기에 같은 뱅크의 **MKT-L2-X6(다조건 동시통과 발송 대상 선별)** 매칭 구조를 결합해, "휴면 세그먼트 추출 → 다조건 매칭 → 발송 대상 명단"까지를 한 과제로 묶었다. 채점은 `_5 §6`의 결정성 원칙을 따른다.

## 일부러 심은 결함 (함정)

학생이 **데이터를 곧이곧대로 쓰면 틀리도록** 설계했다. 이걸 발견·처리하는지가 변별점이다. 모든 함정 회원은 `build_dataset.py`가 각 캠페인의 axes를 읽어 generic하게 심으며, 경계 외 다른 축은 모두 '통과' 값으로 둔다.

1. **나이 경계·만 나이 함정** — 연령 하한 `age_min`-1/`age_min`, 상한 `age_max`/`age_max`+1 회원을 심는다. 특히 **생일이 아직 안 지난(7~12월생)** 회원은 단순 출생연도 빼기(2026 − 출생연도)로 풀면 만 나이가 한 살 더 나와 경계에서 틀린다(만 나이는 기준일 2026-06-28로 계산, 생일 안 지났으면 -1). (예: `C01` 25~54, `C05` 20~39)
2. **휴면일수 경계(89/90/91) — 날짜 파생 축** — 휴면일수는 `(2026-06-28 − 최근주문일).days`로 코드가 계산한다. 캠페인은 '휴면 N일 이상'(`dormant_days_min`) 또는 '최근 N일 이내'(`dormant_days_max`)로 표현되고, 경계 회원(min-1/min/min+1, 예 89/90/91 · max-1/max/max+1)을 자동 삽입한다. **날짜 컬럼을 그대로 비교하거나 일수 변환을 빠뜨리면** 경계가 갈린다. 휴면(`C01` ≥90)과 활성(`C03` ≤14)은 **부호가 반대**라 혼동을 유발한다.
3. **누적구매액 하한(≥) — 방향 반대 함정** — 청년정책의 소득은 상한(`<=`)이었지만, 여기 누적구매액은 **하한(`>=`)** 이다. `total_spend_min`-1(탈락)·`total_spend_min`(같으면 통과) 경계 회원을 심는다. 무심코 `<=`로 풀면 정반대 결과가 난다. (예: `C02` ≥1,000,000)
4. **지역 범위·표기 불일치** — 캠페인 지역은 전국 / 시도 / 자치구로 제각각이고, 고객 주소도 `서울특별시 관악구 봉천동` / `서울 관악구` / `관악구 신림동`처럼 표기가 제각각이다. 시도·자치구를 정규화해 범위 포함관계를 따져야 한다. (예: `C05` 서울특별시)
5. **빈 조건 칸의 의미** — 브리프에 명시되지 않은 조건은 `campaigns.csv`에서 **비어 있고, 그건 "제약 없음"** 이다. 임의 기본값(예: 전 캠페인 수신동의 요구, 임의 등급)을 넣으면 매칭이 틀어진다. 수신동의 `N` 고객은 `opt_in_required=Y` 캠페인에서 **제외**된다(빈칸=무관).
6. **categorical 경계(등급·채널·동의·앱설치)** — 회원등급·선호채널이 일치/불일치인 경계, 수신동의·앱설치가 Y/N인 경계 회원을 요건이 있는 캠페인마다 심는다. (예: `C04` 선호채널 앱푸시 ∧ 앱설치 Y, `C06` 골드 ∧ 수신동의 필요)
7. **판별 불가 캠페인(`matchable=N`) — 무리하게 채우지 않는 판단력** — `C07`(오프라인 매장 방문 고객 전용)은 대상의 핵심이 **고객 명단에 없는 정보**(오프라인 방문 이력)다. 학생은: ① 정책표에서 **고객 명단으로 잴 수 없는 조건 칸을 비워야** 한다(억지로 값 넣으면 오답 — 정답표도 그 칸이 빈칸). ② Part2에서 **아무에게도 추천하지 않는다(정답 0건)**. 조건이 맞아 보여도 명단으로 확인 불가하면 추천=오발송(FP). 일반 원칙은 "**브리프에 안 나오거나 명단으로 확인 불가한 칸은 비우고, 확실할 때만 추천한다**" — 데이터 없으면 무리하지 않는 현업 감각을 측정한다.

> 결정성 봉쇄: 경계가 **애매하게 갈리는** 항목(예: 계산 방식에 따라 만 나이가 달라지는 생일 당일 케이스)은 입력 설계에서 **제외**했다. 모든 케이스는 명시 규칙으로 단일 정답에 매핑되며, 정답은 항상 `campaigns.csv` → `build_dataset.py`에서 유일하게 산출된다.

## 기대하는 풀이 과정

1. **브리프를 코드로 연다** — 이미지(png/jpg)·PDF를 비전/OCR로 열어 대상 조건(거주·연령·휴면일수·누적구매액·등급·채널·동의·앱설치)을 뽑고, **명시 안 됐거나 고객 명단으로 확인 불가한 칸은 비운다.** (손/챗봇 붙여넣기로는 다수 브리프를 일관 처리 불가)
2. **캠페인 정리표를 만든다(Part 1)** — 추출 결과를 정형 스키마로 정규화한다.
3. **고객 DB와 매칭한다(Part 2)** — 만 나이 계산, **휴면일수 = 기준일 − 최근주문일** 파생, 주소→시도/자치구 정규화, 누적구매액 하한(≥), categorical/boolean 8개 조건 축 동시통과 로직을 코드로 작성해 (고객 × 캠페인)을 생성한다. **`matchable=N` 캠페인은 추천에서 제외**한다. **Part2 입력은 제공된 정답 캠페인표(`campaign_table_given.xlsx`)** 라 Part1을 틀려도 영향이 없다(분리형).
4. **검증한다** — 경계 회원이 올바로 갈렸는지(89/90/91 일수, 누적구매액 ±1원, 7~12월생 만 나이), `matchable=N` 캠페인이 추천에 섞이지 않았는지 표본 점검.

## 현실성 (왜 이 시나리오인가)

이커머스 CRM은 실제로 휴면 윈백·VIP 감사·앱푸시 이벤트 같은 리텐션 캠페인을 상시 운영하고, 각 캠페인의 대상 조건은 디자인·기획 브리프(이미지·PDF)로 먼저 돌아다닌다. **"브리프 → 마케터가 직접 대상 조건 정형화 → 고객 세그먼트 매칭 발송"** 은 어느 이커머스에서나 흔한 실제 업무이며, 특정 회사색이 없는 보편 CRM 타게팅 과제다.

> **데이터 출처·고정성**: 캠페인 대상 조건(지역·연령·휴면일수·누적구매액·회원등급·선호채널·수신동의·앱설치)은 **실제 캠페인 브리프에서 추출**해 운영자가 단일 입력 `eval/answer_key/campaigns.csv`에 채운다. 매칭에 쓰는 모든 대상 축은 `customers.xlsx`에 대응 컬럼(생년월일·거주지·최근주문일·누적구매액_원·회원등급·선호채널·마케팅수신동의·앱설치여부)이 있어야 판단된다(축↔고객 컬럼 교집합 불변식). 휴면일수는 `최근주문일`에서 파생되는 날짜 축이다. 일부 캠페인에서 축이 비어 있어도(null) 무방하다. `matchable=N`은 대상 축이 아니라 "고객 명단으로 확인 불가" 운영 플래그로, 그 캠페인은 추천 0건이 정답이다. **현재 CSV는 캠페인 7건 구성 — 대상 6건(`C01`~`C06`, `matchable != N`) + 판별 불가 1건(`C07` 오프라인 매장 방문 전용, `matchable=N` → 추천 0건).** 고객 DB(약 800명)·제출양식·정답키는 `build_dataset.py`가 이 CSV **하나만 읽어** 한 번에 생성하며, 기준일 상수(`ASSIGN_DATE = 2026-06-28`, 만 나이·휴면일수 계산용)와 `random.seed(20260628)`가 고정돼 있어 **언제 재생성해도 동일**하다. 캠페인을 추가/수정하려면 `campaigns.csv`만 고치고 재실행하면 데이터·정답이 함께 갱신된다.
