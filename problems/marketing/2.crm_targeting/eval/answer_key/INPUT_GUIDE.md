# INPUT_GUIDE — campaigns.csv 채우는 법 (출제자용)

이 과제의 **모든 데이터·정답은 단일 입력 파일 `campaigns.csv` 하나에서 생성**된다.
`campaigns.csv`를 실제 캠페인으로 채우고 `build_dataset.py`를 재실행하면, 고객 DB·제출
양식·분리형 입력표·정답키가 **항상 정합하게 함께 갱신**된다. 수기로 엑셀을 고치지 말 것.

> ⚠️ **현재 들어 있는 `campaigns.csv`는 범용 이커머스 CRM 캠페인을 본뜬 샘플 겸 템플릿이다.**
> 컬럼 형식과 대상 조건 구성을 그대로 보여주기 위한 예시이므로, 출제 시 **실제 캠페인
> 데이터로 행을 교체**해서 쓰면 된다. 헤더(컬럼명)는 절대 바꾸지 말 것.

---

## 1. 컬럼 의미 / 형식 (헤더 순서 고정)

| 컬럼 | 의미 | 형식 / 예시 |
|------|------|------------|
| `campaign_id` | 캠페인 고유키 | `C01`, `C02` … (중복 금지) |
| `name` | 캠페인명 | 자유 문자열 (쉼표 포함 시 따옴표로 감쌈) |
| `channel` | 발송 채널(참조용) | `이메일` \| `앱푸시` \| `SMS` \| `오프라인` 등. 채점 대상 아님 |
| `brief_file` | 브리프 파일명 | `data/briefs/` 안의 실제 파일명. 비워도 채점엔 무관 |
| `region` | 거주 요건 | 3형식 중 하나 (아래 §2). **빈칸 금지(fail-loud)** |
| `age_min` | 만 나이 하한 | 정수. 비우면 하한 없음 |
| `age_max` | 만 나이 상한 | 정수. 비우면 상한 없음 |
| `dormant_days_min` | **휴면일수 하한** | 정수(일). '휴면 N일 이상' = 고객 휴면일수 ≥ N. 비우면 무관 |
| `dormant_days_max` | **휴면일수 상한** | 정수(일). '최근 N일 이내 구매' = 고객 휴면일수 ≤ N. 비우면 무관 |
| `total_spend_min` | **누적구매액 하한(원)** | 정수. 고객 `누적구매액_원` ≥ N 통과(**같으면 통과**). 비우면 무관 (0과 빈칸은 다름) |
| `member_grade` | 회원등급 요건 | `일반` \| `실버` \| `골드` \| `VIP`. 비우면 무관 |
| `pref_channel` | 선호채널 요건 | `이메일` \| `앱푸시` \| `SMS`. 비우면 무관 |
| `opt_in_required` | 마케팅 수신동의 필수 | `Y` 이면 수신동의 `Y` 고객만. 비우면 무관 |
| `app_installed_required` | 앱 설치 필수 | `Y` 이면 앱설치 `Y` 고객만. 비우면 무관 |
| `matchable` | 고객 명단으로 대상 확인 가능 여부 | `Y`(기본) \| `N`. **`N` = 고객 DB로 대상 판별 불가 → 추천 0건** |

빈 칸 = "제약 없음". 브리프에 명시되지 않은 조건은 **반드시 비운다**.

> ⭐ **휴면일수는 날짜 파생 축이다.** 고객 컬럼은 `최근주문일`(날짜)이고, 휴면일수는
> `(ASSIGN_DATE − 최근주문일).days`로 코드가 계산한다. 캠페인은 **일수 임계값**
> (`dormant_days_min`/`dormant_days_max`)으로만 표현한다. 경계 함정(89/90/91 등)은
> `build_dataset.py`가 `최근주문일 = ASSIGN_DATE − 휴면일수`로 역산해 자동 삽입한다.

> ⭐ **누적구매액은 하한(≥) 축이다.** 청년정책 소득(상한 ≤)과 **방향이 반대**다.
> 고객 누적구매액이 `total_spend_min` **이상**이어야 통과하며 같으면 통과(`>=`).

> ⭐ **`matchable=N`의 의미(판별 불가 캠페인).** 대상의 핵심이 **고객 명단에 없는 정보**
> (오프라인 매장 방문 이력 등)인 캠페인은 고객 DB로 대상을 가릴 수 없다. 이런 캠페인은
> `matchable=N`으로 두면 **조건이 맞아 보여도 어떤 고객도 통과시키지 않아 추천 0건**이 된다
> (`member_passes()`가 즉시 False). 그런 캠페인엔 자격 축(나이/휴면/누적구매액/등급/채널/
> 수신동의/앱설치)을 **모두 비워야** 한다 — 정답표의 그 칸이 빈칸이어야 하는데 값이 채워지면
> 자기모순이라 `build_dataset.py`가 fail-loud로 중단한다. `matchable`은 캠페인표(제출 양식)에
> 노출하지 않는 **운영 전용** 컬럼이다.

> ⭐ **매칭 축 ↔ 고객 컬럼 교집합(불변식).** 매칭에 쓰는 모든 대상 축은 `customers.xlsx`에
> 대응 컬럼이 반드시 있어야 판단이 가능하다. 8축 대응:
> 나이↔`생년월일` · region↔`거주지` · 휴면일수↔`최근주문일`(파생) · total_spend_min↔`누적구매액_원` ·
> member_grade↔`회원등급` · pref_channel↔`선호채널` · opt_in_required↔`마케팅수신동의` ·
> app_installed_required↔`앱설치여부`.
> **새 대상 축을 추가하려면 `build_dataset.py`의 고객 합성·`member_passes()`,
> `grade.py`의 `P1_FIELDS`에 짝이 되는 고객 컬럼·규칙을 함께 추가**해야 한다(컬럼만 늘리면
> 매칭 불가 — 세 곳 동반 수정). 일부 캠페인에서 그 축이 비어(null) 있어도 무방하다.

## 2. region — 지역 요건 3형식

- `전국` → 모든 고객 통과
- `<시도>` → 고객 시도와 일치해야 통과. 예: `서울특별시`, `경기도`
- `<시도> <자치구>` → 시도 **AND** 자치구 모두 일치. 예: `서울특별시 관악구`

지역 다양성을 위해 1~2개 캠페인은 시도/자치구 한정으로 두면 변별력이 올라간다(예: `C05` 서울특별시). region은 **빈칸 금지** — 비우면 조용히 '전국'이 되어 대량 오발송할 위험이 있어 `load_campaigns()`가 fail-loud로 막는다.

## 3. 각 축 설정법 (축마다 한 줄)

- **나이**(`age_min`/`age_max`, 만 나이): 한쪽만 있어도 되고, 둘 다 비우면 연령 무관. 만 나이는 고객 생년월일과 고정 기준일로 계산(생일 안 지났으면 -1). (예: `C01` 25~54, `C05` 20~39)
- **휴면일수**(`dormant_days_min`/`dormant_days_max`, 일): '휴면 N일 이상'이면 `dormant_days_min=N`, '최근 N일 이내 구매'면 `dormant_days_max=N`. 휴면일수 = 기준일 − 최근주문일. 비우면 무관. (예: `C01` 휴면 ≥90, `C03` 활성 ≤14)
- **누적구매액 하한**(`total_spend_min`, 원): '누적구매 N원 이상'이면 `N`. 고객 누적구매액 ≥ N 통과(같으면 통과, `>=`). 비우면 무관. 0과 빈칸은 다르다. (예: `C02` ≥1,000,000)
- **회원등급**(`member_grade`): `일반`/`실버`/`골드`/`VIP` 중 하나면 그 등급만 통과. 비우면 무관. (예: `C02` VIP, `C06` 골드, `C03` 일반)
- **선호채널**(`pref_channel`): `이메일`/`앱푸시`/`SMS` 중 하나면 그 채널 선호 고객만 통과. 비우면 무관. (예: `C04` 앱푸시)
- **수신동의**(`opt_in_required`): `Y`면 마케팅수신동의 `Y` 고객만. 비우면 무관. (예: `C01`·`C02`·`C06` 필요)
- **앱설치**(`app_installed_required`): `Y`면 앱설치 `Y` 고객만. 비우면 무관. (예: `C04` 필요)

## 4. 매칭 대상 규칙 — 자격만 본다

매칭 발송 대상 = **`matchable != N` 인 모든 캠페인**. 고객이 8축 자격을 모두 통과하면 추천한다.

```
대상캠페인 = [p for p in campaigns if p.matchable != 'N']
```

- **대상(발송)으로 만들려면**: `matchable`을 비우거나 `Y`로 두고, 조건(연령·지역·휴면·누적구매액 등)을 채운다.
- **판별 불가(추천 0건)로 만들려면**: `matchable=N`으로 두고 자격 축은 모두 비운다 → 정답 매칭 0건.

**고정 기준일 `ASSIGN_DATE = 2026-06-28`**(build_dataset.py 상단 상수, `datetime.now()` 사용 안 함)은 **만 나이·휴면일수 계산에만** 쓴다. 기준일을 바꾸려면 `ASSIGN_DATE`만 고치면 만 나이·휴면일수 경계가 그 날짜 기준으로 재계산된다.

현재 CSV는 캠페인 **7건** 구성이다:
- **대상(`matchable != N`, 매칭 발생) — 6건**:
  - `C01` 휴면 윈백 — 전국, 만 25~54, 휴면일수 ≥ 90, 수신동의 필수
  - `C02` VIP 감사 — 전국, 누적구매액 ≥ 1,000,000, 회원등급 VIP, 수신동의 필수
  - `C03` 활성 일반등급 리텐션 — 전국, 휴면일수 ≤ 14, 회원등급 일반
  - `C04` 앱푸시 한정 이벤트 — 전국, 선호채널 앱푸시, 앱설치 필수
  - `C05` 서울 오프라인 팝업 초대 — 서울특별시, 만 20~39
  - `C06` 골드 등급 전용 프로모션 — 전국, 회원등급 골드, 수신동의 필수
- **판별 불가(`matchable=N`) — 1건**: `C07` 오프라인 매장 방문 고객 전용 — 대상 핵심이
  '오프라인 방문 이력'이라 고객 명단으로 확인 불가. **정답 매칭 0건**, 조건 칸 모두 빈칸.

## 5. 브리프 파일 배치

- 학생이 대상 조건을 읽어낼 **실제 캠페인 브리프(이미지/PDF)** 를 `data/briefs/` 폴더에 넣는다.
- 파일명은 CSV의 `brief_file` 값과 **똑같이** 맞춘다(예: `C01_winback.png`). 소싱 방법은 [`../../data/briefs/README.md`](../../data/briefs/README.md).
- 코드는 브리프를 만들지 않는다 — 출제자가 실제 브리프(1~2p)를 직접 배치한다.
- `brief_file`이 비어 있어도 데이터 생성·채점은 동작한다(브리프는 학생용 입력일 뿐).

## 6. 재생성 → 채점 절차

```bash
# 1) campaigns.csv 를 실제 캠페인으로 채운다 (헤더 유지)
# 2) data/briefs/ 에 brief_file 과 같은 이름으로 캠페인 브리프(이미지/PDF)를 넣는다
# 3) 데이터·정답 동시 생성
python3 eval/answer_key/build_dataset.py
#    → data/customers.xlsx, campaign_table_template.xlsx, targeting_template.xlsx,
#      campaign_table_given.xlsx(분리형 Part2 입력)
#    → eval/answer_key/campaign_table_answer.xlsx, targeting_answer.xlsx
# 4) 학생 제출물 채점 (P1 셀 비교 + P2 (고객ID,캠페인ID) 집합 F1)
python3 eval/grade.py \
  --part1 data/campaign_table_template.xlsx \
  --part2 data/targeting_template.xlsx \
  --answer-dir eval/answer_key
```

## 7. 분리형(decouple) — Part2 입력

`campaign_table_given.xlsx`(matchable!=N 캠페인만, **올바른 대상 조건**으로 채운 정답표)가
Part2 입력이다. **2단계는 1단계 결과가 아니라 이 제공표를 쓴다 — 1단계를 틀려도 2단계는
영향 없다.** 채점은 Part1·Part2를 독립 채점한다.
