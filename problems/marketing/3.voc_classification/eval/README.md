# VOC 유형·감성 2축 분류 — 문제 방향성 (README)

> 마케팅/CS 직무 3번 과제. **출제자·운영자용** 개요 문서. (학생에게 주는 파일은 [`../problem.md`](../problem.md))
> **고정 기준일: 2026-06-28**(참고 상수 — 이 과제는 날짜를 채점에 쓰지 않는다). 난이도: **2단계**.
> 문의유형·감성 라벨은 **우선순위 규칙북**으로 결정되며, 운영자가 단일 입력 [`answer_key/items.csv`](answer_key/items.csv)에 시나리오를 채운다.
> 데이터·제출양식·정답키는 [`answer_key/build_dataset.py`](answer_key/build_dataset.py)가 그 CSV **하나만 읽어** 일괄 생성 → 재실행하면 정답이 정합.

## 1. 문제 설명 (자연어)

신입 CS/마케터가 쌓인 고객 문의·리뷰 텍스트를 받아, 각 문장을 **문의유형**(무엇을 묻나)과 **감성**(긍/부/중) 두 축으로 분류하는 업무다. 실제 CS 운영에서 인입 채널(메일·채팅·리뷰)의 자유 텍스트를 유형별로 라벨링해 통계·라우팅·우선순위를 잡는 일을 **회사색을 뺀 산업 범용 형태**로 환원했다 — 어떤 제품·브랜드든 "환불 문의가 늘었다", "제품불량 비중이 높다" 같은 판단은 텍스트 분류에서 시작한다.

핵심 변별 포인트: **같은 문장에 여러 신호가 섞여 있을 때 무엇으로 분류하느냐**다. "환불해 주세요, 배송도 너무 늦었고요"는 환불·배송 둘 다 걸리지만 규칙북의 우선순위가 단 하나의 라벨로 결정한다 — 자유 판단이 아니라 규칙 적용이라는 점이 이 과제를 결정적으로 채점 가능하게 만든다.

## 2. 주어진 데이터 ([`../data/`](../data/))

| 파일 | 내용 | 형식 | 함정 |
|---|---|---|---|
| `data/voc_데이터.xlsx` | 분류 대상 VOC 문장 (약 211건) | 엑셀(item_id, text) | 한 문장에 여러 유형/감성 신호 혼재, 약한 신호·판별불가 섞임 |
| `data/classification_template.xlsx` | 제출 양식 (문의유형·감성 빈칸 + '안내' 시트) | 엑셀 | '안내' 시트에 규칙북 전문 수록 |

> ⚠️ **판별불가(키워드 0매치)**: 규칙북 어느 키워드도 안 걸리는 문장이 섞여 있다. 무리하게 추측하지 말고 **유형=기타·감성=중립**으로 둔다(추측 채우기 처벌). 라벨은 라벨 없이 학생에게 제공되며, 정답은 운영자만 보유한다.

## 3. 해결해야 할 문제 (단일 산출, 분리형 불필요)

- **분류표 작성.** `voc_데이터.xlsx`의 각 문장을 읽고, 제출 양식 '분류' 시트의 두 칸(`문의유형`·`감성`)을 규칙북대로 채운다.

분류 기준(두 축 ↔ 규칙북):
1. **문의유형** ↔ 우선순위 규칙북 — 1.환불취소 2.배송문제 3.제품불량 4.사용법문의 5.칭찬감사 6.기타. 위에서부터 첫 매치, 여러 키워드 충돌 시 **번호가 작은(우선순위 높은) 라벨**.
2. **감성** ↔ 부정 > 긍정 > 중립 — 부정어가 하나라도 있으면 부정, 없고 긍정어가 있으면 긍정, 둘 다 없으면 중립.

> ⭐ **두 축은 독립**: 문의유형(무엇을 묻나)과 감성(긍/부/중)은 별개 축이고 키워드 어휘도 겹치지 않는다. "칭찬감사" 유형이라고 무조건 긍정이 아니다 — 감성은 감성어만 보고 정한다(약한신호면 중립).
> ⭐ **판별불가 → 기타·중립**: 규칙 키워드가 하나도 안 걸리면 유형=기타·감성=중립. 이것이 "데이터로 확인 못 하는 건 비운다"는 검증 신중함을 본다.

> **분리형(decouple) 불필요**: youth_policy는 Part1(추출)→Part2(매칭) 전이를 막으려 분리형을 썼지만, 이 과제는 한 시트에서 유형·감성을 **동시 산출**하는 단일 제출이라 given 별도 입력이 필요 없다.

## 4. 최종 결과물 (제출물)

| 제출 파일 | 행 단위 | 핵심 컬럼 |
|---|---|---|
| `classification_template.xlsx` ('분류' 시트) | VOC 1건 | item_id, 문의유형, 감성 |

> **생성형(요약·답변 카피)은 만들지 않는다.** 이 과제는 "이 문장이 무슨 유형·어떤 감성인지" 결정하는 분류 분석만 채점한다(결정성 확보). 고객 응답 문구 작성은 범위 밖.

## 5. 평가방식

- **문의유형 (6클래스)** — 다클래스 **macro-F1**(클래스별 F1을 평균). 단순 정확도가 아니라 macro라 다수 클래스로만 찍으면 소수 클래스 F1이 0이 되어 평균이 급락한다.
- **감성 (3클래스)** — 다클래스 **macro-F1**.
- **무결성** — 라벨집합 외 값·빈칸·유령 item_id 위반 감점.
- 채점 시 **혼동행렬**(행=정답, 열=제출)을 출력해 어느 클래스를 어디로 틀렸는지 진단한다.
- **과정 점수(AI 협업)** — 채팅 로그로 별도 평가. 본 문서 범위 밖.

> 결정성 원칙: 모든 라벨은 (제공 문장 + 규칙북)에서 유일 정답으로 환원된다. 정답은 생성된 `text`에 규칙북을 **재적용**해 도출하므로, `text`만 있으면 독립 채점자도 같은 정답을 재계산할 수 있다. 경계가 애매하게 갈리는 항목은 입력 설계 단계에서 제거했다. (`intention.md` 참조)
