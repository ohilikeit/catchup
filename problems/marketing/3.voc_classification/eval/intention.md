# 출제 의도 (intention)

> 이 문제가 **무엇을 측정**하고, **어떤 결함을 일부러 심었으며**, 학생이 **어떤 과정으로 풀기를** 기대하는지 핵심만 적는다.

## 한 줄 의도

> "수천 건의 고객 문의·리뷰를 유형·감성으로 분류하라" — 챗봇에 한 건씩 붙여넣어서는 못 풀고(분량·일관성), Claude Code로 규칙북을 코드화해 전체에 일관 적용해야만 풀리는 문제. 모든 데이터·정답은 단일 입력 `items.csv`에서 생성돼, 텍스트를 바꿔도 동일 구조로 재현된다.

## 측정하는 능력

| 축 | 무엇을 보는가 |
|---|---|
| **직무 능력 (CS/마케팅)** | 자유 텍스트를 닫힌 라벨 집합으로 떨어뜨리는 감각 — 한 문장에 신호가 섞여도 정해진 우선순위로 단일 라벨을 고르고, 유형과 감성을 별개 축으로 분리해 보는 능력 |
| **AI 활용 능력** | ① 비정형 텍스트를 코드로 일괄 처리 ② 규칙(키워드·우선순위)을 데이터/코드로 다뤄 재사용 가능한 분류 파이프라인 구성 ③ 200여 건 전체에 일관 적용 ④ 결과 검증(클래스 분포·혼동) |
| **문제 해결력** | 비정형 → 규칙 적용 → 정형 라벨 분해력 + "신호가 없으면 기타·중립으로 비운다"는 판단(유형에서 감성을 추론하거나 무리하게 추측하지 않음) |

> 설계 근거: `_6일반범용-마케팅-산업범용-업무형태-보강.md`의 **GEN-L2-X5("리뷰·VOC 수천 건 유형·감성 분류", G2/G9)** 와 **M10("비정형 멘션/응답 → 감성·주제 분류")** 를 실제 도메인(CS/마케팅 VOC)으로 구현한 사례. 채점은 `_5 §6`의 결정성 원칙을 따르고, 분류·감성처럼 본래 주관적인 요소를 `_6 §(C) 근거 결속`대로 **닫힌 라벨 집합 + 라벨 일치율(macro-F1)** 로만 채점한다.

## 일부러 심은 결함 (함정)

학생이 **텍스트를 곧이곧대로 또는 직관으로 분류하면 틀리도록** 설계했다. (B 카탈로그 — 분류판)

1. **다중 키워드 충돌 (유형충돌)** — 한 문장에 우선순위가 다른 두 유형 키워드를 함께 심었다(예: 환불취소+배송문제). 우선순위 규칙(번호 작은 라벨)을 모르면 어느 쪽으로든 갈린다. *측정 의도*: 규칙북의 우선순위를 정확히 적용하는가. (items.csv 34건이 충돌 주입)
2. **감성 반전어 (감성충돌)** — 긍정어와 부정어를 한 문장에 공존시켰다(예: "최고예요. 그런데 너무 불편합니다"). 규칙(부정 > 긍정)을 모르면 긍정으로 잘못 찍는다. *측정 의도*: 부정 우선 규칙 준수.
3. **약한 신호 (유형≠감성)** — 유형 키워드만 있고 감성 신호가 없는 문장. "칭찬감사 유형이니 당연히 긍정"처럼 **유형에서 감성을 추론하면 틀린다**(정답=중립). *측정 의도*: 두 축을 독립으로 보는가.
4. **판별불가 → 기타·중립** — 규칙북 어느 키워드도 안 걸리는 중립 문장(18건). 무리하게 유형을 추측해 채우면 오답. *측정 의도*: 데이터로 확인 못 하는 건 비우는 신중함.
5. **라벨집합 외 임의값** — 정해진 6유형/3감성 외의 값이나 빈칸은 오답 처리 + 무결성 감점. *측정 의도*: 닫힌 라벨 집합 준수.
6. **클래스 불균형 (macro로 변별)** — 소수 클래스(칭찬감사 23건, 긍정 33건)를 일부러 적게 두었다. 다수 클래스로만 찍으면 소수 클래스 F1이 0이 되어 macro 평균이 급락한다. *측정 의도*: 소수 클래스도 정확히 잡는가.

> 결정성 봉쇄: 애매하게 갈리는 항목(키워드가 어느 유형으로도 해석될 수 있는 모호어)은 입력 설계에서 **제외**했다. 모든 케이스는 규칙북으로 단일 정답에 매핑되며, 정답은 항상 생성된 `text`에 규칙북을 재적용(`derive_labels`)해 유일하게 산출된다. `items.csv`의 `유형/감성` 컬럼(의도 라벨)은 정답을 베끼는 데 쓰지 않고, 규칙 재적용 결과와 일치하는지 `cross_check`로 자기검증(불일치 시 생성 중단)하는 데만 쓴다.

## 기대하는 풀이 과정

1. `voc_데이터.xlsx`를 코드로 연다(엑셀 라이브러리).
2. '안내' 시트의 규칙북(유형 우선순위 키워드 + 감성 부정>긍정 규칙)을 코드로 옮긴다.
3. 각 문장에 규칙을 일괄 적용해 (문의유형, 감성)을 산출 — 첫 매치/부정 우선/판별불가→기타·중립을 그대로 구현.
4. 제출 양식 '분류' 시트에 채워 저장하고, 클래스 분포가 한쪽으로 쏠리지 않는지 검증한다.

> 검증 습관(소수 클래스가 0건으로 빠지지 않았는지, 판별불가를 무리하게 채우지 않았는지)이 변별 포인트다.

## 현실성 (왜 이 시나리오인가)

실제 CS/마케팅 운영은 인입 채널의 자유 텍스트를 유형별로 라벨링해 통계·라우팅·우선순위를 잡는다. 분류 기준(유형 체계·감성 정의)은 보통 팀의 운영 룰북으로 고정돼 있고, 신입은 그 룰북을 정확히 적용하는 일부터 맡는다 — 특정 회사에 종속되지 않는 보편 업무다.

> **데이터 출처·고정성**: 라벨은 규칙북에서 유일하게 도출 → 운영자가 `items.csv`에 시나리오(의도 라벨·충돌·경계)를 채움 / 정답은 의도 라벨을 베끼지 않고 생성된 `text`에 규칙북 **재적용**으로 도출(독립검증 성립) / 유형↔유형키워드·감성↔감성키워드 두 어휘는 **교집합 ∅**(`_assert_vocab_disjoint`가 강제) / 현재 행 구성 = 211건(명확 + 충돌 34 + 경계 36[판별불가 18·약한신호 18]) / `ASSIGN_DATE=2026-06-28`·`seed=20260628` 고정 → 언제 재생성해도 동일.
