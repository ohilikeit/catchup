# INPUT_GUIDE — VOC 유형·감성 분류 단일 입력(items.csv) 작성법 + 규칙북 전문

> 이 과제의 **모든 데이터·정답은 단일 입력 `items.csv` 하나에서 생성**된다. `build_dataset.py`가
> 그 CSV만 읽어 학생용 `voc_데이터.xlsx`·제출양식·정답키를 **일괄 생성**한다. 정답키 엑셀을
> 수기로 고치지 말 것 — 바꿀 게 있으면 `items.csv`를 고치고 재실행한다.

> ⚠️ 현재 `items.csv`는 샘플 겸 템플릿이다. **헤더는 절대 바꾸지 말 것**. 실제 데이터로 행을 교체/추가한다.

---

## 0. 핵심 철학 — "모호함을 규칙으로 결정화"

분류는 본래 "이게 무슨 문의냐"가 사람마다 갈린다(정답 모호). 그래서 이 과제는 **자유 판단을
금지**하고 아래 **우선순위 규칙북**으로 모든 문장을 **유일 라벨**로 떨어뜨린다. 정답은 생성된
문장에 규칙북을 **재적용**해서 도출한다(시나리오에 적은 의도 라벨을 그대로 베끼지 않는다).
이 재적용 결과와 의도 라벨이 일치하는지 `cross_check`가 매 항목 검사하고, 어긋나면 생성을 **중단**한다.

## 1. items.csv 컬럼 의미/형식 — **헤더 순서 고정**

| 컬럼 | 의미 | 형식 / 허용값 |
|---|---|---|
| `item_id` | VOC 고유키 | `V001`… (중복 금지) |
| `템플릿` | 문장 조립 힌트 | `auto`(기본) — 채점·도출과 무관, 가독성만 |
| `유형` | **최종 의도** 문의유형 | 환불취소 \| 배송문제 \| 제품불량 \| 사용법문의 \| 칭찬감사 \| 기타 |
| `감성` | **최종 의도** 감성 | 긍정 \| 부정 \| 중립 |
| `충돌주입` | 함정 주입 | none \| 유형충돌 \| 감성충돌 |
| `충돌상대` | 유형충돌 시 함께 주입할 **하위 우선순위** 유형 | 유형보다 우선순위 낮은 유형 / 그 외 `없음` |
| `경계케이스` | 경계 함정 | none \| 판별불가 \| 약한신호 |

`유형`·`감성`은 **충돌 해소 후의 최종 라벨**을 적는다(규칙이 골라야 할 답). 생성기는 그 라벨이
규칙 재적용으로 똑같이 나오도록 키워드를 심고, 다르면 fail-loud로 멈춘다.

## 2. 규칙북 전문 (rulebook — 정답의 유일 근거)

### 2.1 문의유형 (우선순위 순, 위에서부터 첫 매치)

한 텍스트에 여러 유형 키워드가 동시에 걸리면 **번호가 작은(우선순위 높은) 라벨**을 고른다.

| 우선 | 라벨 | 트리거 키워드 |
|---|---|---|
| 1 | **환불취소** | 환불 · 취소 · 반품 · 돈 돌려 · 결제 취소 |
| 2 | **배송문제** | 배송 · 택배 · 도착 · 안 와 · 발송 |
| 3 | **제품불량** | 불량 · 고장 · 깨져 · 작동이 안 · 하자 · 망가 |
| 4 | **사용법문의** | 어떻게 쓰 · 사용법 · 사용 방법 · 설정 · 연결하는 방법 · 방법 문의 · 방법 알려 |
| 5 | **칭찬감사** | 친절 · 칭찬 · 수고 · 고맙 · 고마웠 |
| 6 | **기타** | 위 어디에도 안 걸리면 |

예: "환불해 주세요. 배송도 늦었고요" → 환불(1)·배송(2) 둘 다 걸리지만 우선순위 높은 **환불취소**.

### 2.2 감성 (부정 > 긍정 > 중립)

부정어가 **하나라도** 있으면 **부정**. 없고 긍정어가 있으면 **긍정**. 둘 다 없으면 **중립**.

- **부정어**: 화가 · 실망 · 최악 · 불편 · 짜증 · 별로 · 엉망
- **긍정어**: 좋아 · 좋네 · 좋습니다 · 만족 · 최고 · 훌륭 · 마음에 · 감동

예: "최고예요. 그런데 너무 불편합니다" → 긍정어·부정어 공존 → 규칙(부정>긍정)상 **부정**.

### 2.3 판별불가 → 기타 / 중립

규칙 키워드가 **하나도** 안 걸리면 무리하게 추측하지 말고 **유형=기타·감성=중립**. (현업의 신중함 = 데이터로 확인 못 하는 건 비운다.)

### 2.4 유형 ≠ 감성 (별개 축)

문의유형(무엇을 묻나)과 감성(긍/부/중)은 **독립**이다. 키워드 어휘도 두 축이 겹치지 않는다
(예: '감사'는 감성어가 아님 — 칭찬감사 유형은 '고맙/친절'로 잡고, 긍정 감성은 '좋아/만족'으로 잡는다).
"칭찬감사"라고 무조건 긍정이 아니다 — 감성은 **감성어만** 보고 정한다(약한신호면 중립).

## 3. 함정(충돌·경계) 설정법

| 함정 | items.csv 설정 | 규칙이 풀어야 할 정답 |
|---|---|---|
| **유형충돌** | `충돌주입=유형충돌`, `충돌상대`=유형보다 하위 우선순위 유형 | 우선순위 높은 `유형` (예: 환불취소+배송 → 환불취소) |
| **감성충돌** | `충돌주입=감성충돌` (이때 `감성`은 반드시 **부정**) | 부정 (부정어+긍정어 공존 → 부정) |
| **판별불가** | `경계케이스=판별불가` (이때 `유형=기타`·`감성=중립`·`충돌주입=none`) | 기타 / 중립 |
| **약한신호** | `경계케이스=약한신호` (이때 `감성=중립`·유형은 기타 아님) | 유형은 정상, 감성=중립(유형에서 감성 추론 금지) |
| **라벨집합 외** | (학생 함정) 정해진 6/3 라벨 외 값·빈칸 | 채점에서 오답 + 무결성 감점 |
| **클래스 불균형** | 소수 클래스(예: 칭찬감사)를 일부러 적게 | macro-F1이 소수 클래스 무시(다 찍기)를 처벌 |

### fail-loud 가드 (생성기가 즉시 중단하는 자기모순)
- `유형충돌`인데 `충돌상대` 우선순위가 `유형`보다 높거나 같음 → 규칙이 유형을 못 고름.
- `유형충돌`인데 `유형=기타` → 기타는 키워드가 없어 충돌 해소 불가.
- `감성충돌`인데 `감성≠부정` → 규칙(부정>긍정)과 모순.
- `판별불가`인데 `유형≠기타` 또는 `감성≠중립` 또는 `충돌주입≠none`.
- `약한신호`인데 `감성≠중립` 또는 `유형=기타` 또는 `충돌주입≠none`.

## 4. 재생성 → 채점 절차

```bash
# 1) items.csv 를 실제 데이터로 채운다 (헤더 유지, 모든 6유형·3감성 클래스가 1건 이상 등장하게)
# 2) 데이터·정답 동시 생성
python3 eval/answer_key/build_dataset.py
#    → data/voc_데이터.xlsx, data/classification_template.xlsx
#    → eval/answer_key/classification_answer.xlsx
#    (cross_check 통과 못 하면 여기서 중단 — 의도 라벨이 규칙대로 안 풀림)
# 3) 학생 제출물 채점
python3 eval/grade.py \
  --submission data/classification_template.xlsx \
  --answer-dir eval/answer_key
#    → 콘솔 표 + 혼동행렬 + result.json
```

> ⭐ **모든 클래스 support 보장**: macro-F1은 클래스별 F1의 평균이라, 6유형·3감성 각 클래스가
> 정답에 **최소 1건** 등장해야 한다(없으면 그 클래스가 분모에서 빠지거나 변별이 사라짐). 현재
> items.csv 분포: 유형 6클래스 + 감성 3클래스 모두 다수 등장(소수 클래스 = 칭찬감사·긍정).

> ⭐ **규칙 재적용 = 정답**: 정답은 `유형/감성` 컬럼을 베낀 게 아니라 생성된 `text`에 §2 규칙북을
> 다시 적용해 도출한다. 그래서 `text`만 있으면 누구든(독립 채점자) 같은 정답을 재계산할 수 있다 —
> 이것이 결정성·독립검증의 근거다. `유형/감성` 컬럼은 자기검증(cross_check)용 의도 표기일 뿐이다.

> ⭐ **분리형 불필요**: 2축 분류는 한 시트('분류')에 문의유형·감성을 **동시 산출**하는 단일
> 제출이라, Part1→Part2 전이를 차단하는 분리형(given 입력)이 필요 없다.
