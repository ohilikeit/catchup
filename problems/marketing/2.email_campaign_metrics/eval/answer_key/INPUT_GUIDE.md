# INPUT_GUIDE — spec.csv 채우는 법 (출제자용)

이 과제의 **모든 데이터·정답은 단일 입력 파일 `spec.csv` 하나에서 생성**된다.
`spec.csv`를 캠페인 명세로 채우고 `build_dataset.py`를 재실행하면, 발송로그·제출
양식·`campaign_metrics_given.xlsx`·정답키가 **항상 정합하게 함께 갱신**된다. 수기로
엑셀을 고치지 말 것.

> ⚠️ **현재 들어 있는 `spec.csv`는 이커머스/CRM 캠페인을 본뜬 샘플 겸 템플릿이다(50건).**
> 컬럼 형식과 함정 구성(정상·발송0·오픈0·반올림 경계)을 그대로 보여주기 위한 예시이므로,
> 출제 시 **실제 캠페인 수치로 행을 교체**해서 쓰면 된다. 헤더(컬럼명)는 절대 바꾸지 말 것.
> 생성기는 **spec 숫자를 직접 베끼지 않고** 발송로그를 합성한 뒤 *다시 그룹바이*해 정답을
> 도출한다 — 그래서 spec과 로그가 어긋나면 `cross_check`가 즉시 중단시킨다(fail-loud).

---

## 1. 컬럼 의미 / 형식 (헤더 순서 고정)

| 컬럼 | 의미 | 형식 / 예시 |
|------|------|------------|
| `campaign_id` | 캠페인 고유키 | `C001`, `C002` … (중복 금지) |
| `name` | 캠페인명 | 자유 문자열 (쉼표 포함 시 따옴표로 감쌈) |
| `발송수` | 그 캠페인 발송 건수 | 0 이상 정수. 발송로그 행 수가 된다 |
| `오픈수` | 오픈 건수 | 0 이상 정수. **오픈수 ≤ 발송수** |
| `클릭수` | 클릭 건수 | 0 이상 정수. **클릭수 ≤ 오픈수**(클릭은 오픈의 부분집합) |
| `전환수` | 전환 건수 | 0 이상 정수. **전환수 ≤ 클릭수**(전환은 클릭의 부분집합) |
| `매출합계_원` | 그 캠페인 총매출(원) | 0 이상 정수. 전환 행에 분배(합=이 값). **전환수=0이면 0** |
| `zero_denom` | 분모 0 유형 | `none` \| `발송0` \| `오픈0` (아래 §3) |
| `round_boundary` | 반올림 경계 캠페인 | `Y` \| `N`. `Y`면 어떤 율이 X.X5 경계에 와야 함(자기검증) |

> ⭐ **퍼널 단조성(불변식).** 항상 **전환수 ≤ 클릭수 ≤ 오픈수 ≤ 발송수** 여야 한다. 위반하면
> `build_dataset.py`가 `[중단]`으로 즉시 종료한다(fail-loud). 이 단조성이 깨지면 발송로그를
> 부분집합으로 합성할 수 없기 때문이다(전환 행 ⊆ 클릭 행 ⊆ 오픈 행 ⊆ 발송 행).

> ⭐ **집계 지표 ↔ 발송로그 컬럼 교집합(불변식).** 학생이 채울 모든 지표는 발송로그에
> 대응 컬럼이 반드시 있어야 계산된다:
> 발송수↔로그 **행 수** · 오픈수↔`오픈여부=Y` · 클릭수↔`클릭여부=Y` · 전환수↔`전환여부=Y` ·
> 매출합계↔`매출액_원` 합 · 율↔(건수/발송수)×100 · ARPU↔매출합계/발송수.
> **새 지표 축을 추가하려면** `spec.csv`(입력 컬럼)·`build_dataset.py`(`build_log`의 로그 컬럼과
> `regroup_metrics`의 집계)·`grade.py`(`P1_INT_FIELDS`/`P1_FLOAT_FIELDS`)에 짝을 함께 추가해야
> 한다(한쪽만 늘리면 집계 불가).

## 2. 매출 분배 — 전환 행에만

`매출합계_원`은 **전환 행(전환여부=Y)에 분배**된다(`distribute_revenue`: 몫을 깔고 나머지를
앞에서부터 +1 → 합이 정확히 `매출합계_원`). 따라서:
- 전환수 > 0 인데 매출합계_원 ≤ 0 → `[중단]`(양수여야 함).
- 전환수 = 0 인데 매출합계_원 ≠ 0 → `[중단]`(전환 없으면 매출 0).

ARPU는 **매출합계 ÷ 발송수**(전환수가 아니라 발송수가 분모)임에 유의 — 발송 1건당 평균매출.

## 3. zero_denom — 분모 0 / 빈·오픈0 캠페인

| 값 | 의미 | 제약 |
|---|---|---|
| `none` | 정상 캠페인 | 발송수 > 0 |
| `발송0` | **빈 캠페인**(발송 0건) | 발송수=0(나머지도 0). 발송로그 행 0. 정답: 모든 율=0.0, ARPU=0 |
| `오픈0` | 발송은 됐으나 **아무도 안 엶** | 발송수>0 **그리고** 오픈수=0. 율은 정상 계산(분모=발송수>0 → 0.0) |

- `발송0`인데 발송수≠0, `오픈0`인데 발송수=0 또는 오픈수≠0 → `[중단]`(일관성 검증).
- 발송수=0인데 `zero_denom`이 `발송0`이 아니면 → `[중단]`.
- **분모0 트랩**: `발송0` 캠페인을 1~2건 두면 0 나눗셈 처리 능력을 측정한다. `오픈0`은 "발송>0이라
  나눌 수 있으나 결과가 0"인 결을 추가로 측정한다.

## 4. round_boundary — 반올림 경계 트랩

`round_boundary=Y`로 둔 캠페인은 **어떤 율(오픈율·클릭율·전환율 중 하나)이 X.X5 경계**(소수
둘째 자리가 정확히 5)에 오도록 발송/건수를 맞춰야 한다. 예: 오픈수=133, 발송수=400 →
33.25% → 반올림 33.3 / 버림 33.2 로 갈린다.

```
# 경계 판정(build_dataset.py): num/den*100 의 1자리 스케일 소수부가 정확히 0.5 인가
lands_on_boundary(num, den)  # 둘째 소수가 5 → half-up과 truncate가 0.1 차로 갈림
```

- `round_boundary=Y`인데 **어떤 율도 X.X5 경계에 오지 않으면** `cross_check`가 `[중단]`(트랩
  실재성 보장 — 건수를 조정해 실제로 경계에 오게 하라).
- 경계 캠페인은 발송수를 100·200·400·2000처럼 **분모를 깔끔히** 두고 건수를 맞추면 만들기 쉽다
  (예: 발송 400·오픈 133 = 33.25, 발송 2000·클릭 245 = 12.25 …). 현재 `C001`~`C006`이 경계 케이스.

## 5. 발송로그 합성 규칙 (생성기 내부)

`build_log`는 캠페인마다 발송수개 행을 만들고, **앞쪽부터** 전환수개=전환(=클릭=오픈),
그다음 클릭수개=클릭(=오픈), 그다음 오픈수개=오픈으로 부분집합을 깐다. 매출은 전환 행에
분배. 발송일은 `ASSIGN_DATE`에서 캠페인별로 흩뿌린다(`seed` 고정, **채점엔 미사용**).
이렇게 만든 로그를 `regroup_metrics`가 다시 그룹바이해 정답을 낸다(spec 직접 베끼기 금지).

## 6. 재생성 → 채점 절차

```bash
# 1) spec.csv 를 실제 캠페인 수치로 채운다 (헤더 유지, 퍼널 단조성 지킴)
# 2) 데이터·정답 동시 생성
python3 eval/answer_key/build_dataset.py
#    → data/발송로그.xlsx
#    → data/campaign_metrics_template.xlsx, data/summary_template.xlsx
#    → data/campaign_metrics_given.xlsx  (Part2 입력용 정답 집계표 = 분리형)
#    → eval/answer_key/campaign_metrics_answer.xlsx, summary_answer.xlsx
# 3) 학생 제출물 채점 (P1 셀 비교 + P2 요약 1행)
python3 eval/grade.py \
  --part1 data/campaign_metrics_template.xlsx \
  --part2 data/summary_template.xlsx \
  --answer-dir eval/answer_key
```

> **고정 기준일 `ASSIGN_DATE = 2026-06-28`** (build_dataset.py 상단 상수, `datetime.now()`
> 미사용)은 **발송일 합성에만** 쓰고 채점·집계에는 쓰지 않는다. `random.seed(20260628)`도
> 고정이라, `spec.csv`가 같으면 발송로그·양식·정답이 **언제 재생성해도 동일**하다.

현재 `spec.csv`는 캠페인 **50건** 구성이다:
- **정상(`none`) — 46건**: 일반 캠페인(그중 `C001`~`C006`은 `round_boundary=Y` 경계 트랩).
- **발송0(`발송0`, 빈 캠페인) — 2건**: `C007`·`C008` — 발송 0건이라 모든 율=0.0, ARPU=0.
- **오픈0(`오픈0`) — 2건**: `C009`·`C010` — 발송>0·오픈 0건이라 율 0.0(분모는 발송수).

`spec.csv`만 바꾸면 발송로그·함정·정답이 새 캠페인 구성에 맞춰 재생성되므로, 출제자는
캠페인 수치만 정확히(퍼널 단조성 지켜) 입력하면 된다.
