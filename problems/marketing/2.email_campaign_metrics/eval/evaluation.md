# 평가 방식 (evaluation)

> 제출물 2개를 **정답키와 자동 대조**한다. 채점 스크립트는 [`grade.py`](grade.py), 정답키는 [`answer_key/`](answer_key/).
> 결과(문제 해결) 점수만 다룬다. 과정(AI 협업) 점수는 채팅 로그 기반 별도 루브릭.

---

## 1. 제출물 스키마 (정답이 결정되는 형식)

### Part 1 — `campaign_metrics_template.xlsx` · 시트 `집계표`
행 단위 = **캠페인 1건** (`발송로그.xlsx`에 등장하는 모든 `campaign_id`, 빈 캠페인 포함). 정답은 모두 발송로그를 `campaign_id`로 그룹바이해 도출한다. 컬럼 순서: `campaign_id,발송수,오픈수,클릭수,전환수,오픈율,클릭율,전환율,매출합계,ARPU`.

| 컬럼 | 형식 / 허용값 | 채점유형 |
|---|---|---|
| `campaign_id` | `C001`… (키) — **양식에 미리 주어짐(채점 안 함)** | — |
| `발송수` | 정수(그 캠페인 발송로그 행 수) | Exact(정수) |
| `오픈수` / `클릭수` / `전환수` | 정수(`오픈여부`/`클릭여부`/`전환여부` = `Y` 인 행 수) | Exact(정수) |
| `매출합계` | 정수(원, 그 캠페인 `매출액_원` 합) | Exact(정수) |
| `오픈율` | 오픈수/발송수×100, 소수 첫째 자리 반올림. 발송0 → `0.0` | **Computed(±0.1)** |
| `클릭율` | 클릭수/발송수×100, 소수 첫째 자리 반올림. 발송0 → `0.0` | **Computed(±0.1)** |
| `전환율` | 전환수/발송수×100, 소수 첫째 자리 반올림. 발송0 → `0.0` | **Computed(±0.1)** |
| `ARPU` | 매출합계/발송수, 소수 첫째 자리 반올림. 발송0 → `0.0` | **Computed(±0.1)** |

> `campaign_id`는 제출 양식에 **미리 채워져 제공**된다(채점 대상 아님). **발송 0건(빈 캠페인)의 율·ARPU는 `0.0`, 건수·합계는 `0`이 정답**(빈칸이 아니다 — 빈칸과 0은 구분한다). 발송은 됐지만 오픈 0건인 캠페인도 율은 `0.0`이 정답(분모는 발송수>0). 율 칸은 `33.3` 같은 숫자로 적는다(`%` 기호·콤마는 채점 시 제거).

### Part 2 — `summary_template.xlsx` · 시트 `전체요약`
행 단위 = **전사 요약 단 1행**. 입력은 **제공된 정답 집계표 `campaign_metrics_given.xlsx`**(분리형 — Part1을 틀려도 Part2는 영향 없음). 컬럼 순서: `총발송,총오픈,총클릭,총전환,전체전환율,총매출,전체ARPU`.

| 컬럼 | 형식 / 허용값 | 채점유형 |
|---|---|---|
| `총발송` / `총오픈` / `총클릭` / `총전환` | 정수(모든 캠페인 합) | Exact(정수) |
| `총매출` | 정수(원, 모든 캠페인 매출합계의 합) | Exact(정수) |
| `전체전환율` | **총전환/총발송×100 (가중)**, 소수 첫째 자리 반올림. 캠페인별 전환율의 단순평균이 아니다 | **Computed(±0.1)** |
| `전체ARPU` | 총매출/총발송, 소수 첫째 자리 반올림 | **Computed(±0.1)** |

> **전체전환율을 '캠페인 전환율들의 평균'으로 내면 가중 정답과 0.1 이상 벌어져 오답**이 잡힌다(핵심 함정). 행 순서·여분 빈칸은 무시한다.

## 2. 채점 로직 (`grade.py` 구성요소)

```
grade.py
├─ load_sheet(path, sheet)            # openpyxl 로드 → 헤더 정규화, 빈 행 스킵
├─ norm_int(v)                        # 합계·건수: 빈칸 보존(0과 구분), 콤마·공백·'원'·.0 제거 → 정수 문자열
├─ norm_float(v)                      # 율·평균: 콤마·%·공백 제거 → float (빈칸/파싱불가 → None)
├─ grade_part1(sub, ans)             # 캠페인별 집계표: 키(campaign_id)로 조인, 셀 단위 비교
│   • P1_INT_FIELDS(발송수·오픈수·클릭수·전환수·매출합계) → int_eq (정수 Exact)
│   • P1_FLOAT_FIELDS(오픈율·클릭율·전환율·ARPU)        → float_eq(±0.1)
│   • 필드별 일치 집계 → 필드별 정확도 + 전체 셀 정확도
│   • 유령 campaign_id(정답에 없는 키) + 제출 행 퍼널 단조성 위반 탐지
├─ grade_part2(sub, ans)             # 전체 요약 1행: 셀 단위 비교
│   • SUM_INT_FIELDS(총발송·총오픈·총클릭·총전환·총매출) → int_eq
│   • SUM_FLOAT_FIELDS(전체전환율·전체ARPU)             → float_eq(±0.1)
└─ score(p1, p2) + report()          # 영역별 점수 산정 → JSON + 콘솔 표
```

### 채점 프리미티브 (Computed, ±ε 허용오차)
- `int_eq`(건수·합계): `norm_int`로 정규화 후 **문자열 정확 일치**. 빈칸≠`0`(빈칸=미기입, 0=값 0). 천단위 콤마·`원`·`.0` 허용.
- `float_eq`(율·평균, **tol=0.1**): `norm_float` 후 `round(|정답−제출|, 4) < 0.1`이면 정답. 정답은 항상 숫자(빈칸 정답이면 0.0으로 간주), 제출이 비었으면 오답. **4자리 반올림으로 부동소수 잡음을 제거**하므로 33.3 vs 33.30000001은 통과, 반올림 경계를 반대로 굴린 33.2 vs 33.3(0.1 차)은 **엄격히 오답**.
- 빈 행·여분 행: 모든 셀이 비면 스킵. 행 순서는 채점에 무관(키로 조인).

## 3. 배점 (결과 점수 100점 기준)

| 영역 | 배점 | 산정 |
|---|--:|---|
| Part 1 캠페인별 집계표 | 55 | 셀 정확도 × 55 (정확 셀 / 전체 채점 셀; 9필드 × 캠페인 수) |
| Part 2 전체 요약 | 35 | 셀 정확도 × 35 (7필드 중 정확 셀 비율) |
| 무결성 | 10 | `10 − (유령 campaign_id + 퍼널 단조성 위반) × 0.5` (최저 0) |

> **합격선(1단계 능력)**: 그룹바이로 건수·합계·율을 일관 산출. **변별(2단계)**: 분모0·반올림 경계를 모두 통과하고, Part2 전체전환율을 **가중**으로 내 만점에 수렴.

### 흔한 실패 = 의도한 함정 적중
- 율을 `오픈수/발송수`로 그냥 계산 → **발송 0 캠페인에서 0 나눗셈 오류/빈칸** → 율·ARPU 셀 오답.
- 반올림을 버림·banker's rounding으로 처리 → **X.X5 경계 캠페인(C001~C006)에서 0.1 차** → 율 셀 오답.
- 전체전환율을 **캠페인 전환율들의 단순평균**으로 산출 → 가중 정답과 갈려 Part2 `전체전환율` 셀 오답.
- 발송로그를 잘못 묶어 정답에 없는 campaign_id를 만들거나 전환>오픈 같은 퍼널 역전을 적음 → **무결성 감점**.

## 4. 정답키 생성·관리

- 정답키(`answer_key/campaign_metrics_answer.xlsx`, `answer_key/summary_answer.xlsx`)와 제공 데이터(`../data/`)는 **단일 입력 [`answer_key/spec.csv`](answer_key/spec.csv)** 에서 같은 스크립트로 나온다 → 발송로그·집계표·요약·정답이 항상 정합.
- 캠페인을 바꾸려면 **`spec.csv`만 수정**하고 `build_dataset.py`를 다시 돌려 **데이터와 정답키를 동시 갱신**한다(생성물 수기 편집 금지). CSV 작성법은 [`answer_key/INPUT_GUIDE.md`](answer_key/INPUT_GUIDE.md).
- 생성기 책임: `spec.csv` 읽기(퍼널 단조성·zero_denom·매출↔전환 일관성 **fail-loud 검증**) → 1행=1발송 발송로그 합성 → `regroup_metrics`로 로그 재집계 → `cross_check`(재집계==spec, 반올림 경계 실재) → 제출양식·`campaign_metrics_given.xlsx`·정답키 산출. 기준일 `ASSIGN_DATE = 2026-06-28`·`random.seed(20260628)` 상수 고정(`datetime.now()` 미사용; 발송일 합성용으로만, 채점엔 미사용).
- **정답 도출 철학**: spec.csv의 숫자를 그대로 베끼지 않고, 합성한 발송로그를 **다시 그룹바이**해 지표를 계산한다 → 독립검증·결정성 성립.
