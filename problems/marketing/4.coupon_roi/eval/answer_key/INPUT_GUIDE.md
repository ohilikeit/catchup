# INPUT_GUIDE — spec.csv 채우는 법 (출제자용)

이 과제의 **모든 데이터·정답은 단일 입력 파일 `spec.csv` 하나에서 생성**된다.
`spec.csv`를 쿠폰 명세로 채우고 `build_dataset.py`를 재실행하면, GA4 주문 로그·제출
양식·`2_정리된_쿠폰성과표_참고용.xlsx`·정답키가 **항상 정합하게 함께 갱신**된다. 수기로 엑셀을
고치지 말 것.

> ⚠️ **현재 들어 있는 `spec.csv`는 이커머스 쿠폰 포트폴리오를 본뜬 샘플 겸 템플릿(44건)이다.**
> 컬럼 형식과 함정 구성(정상·할인0·미사용·반올림 경계·적자/흑자)을 그대로 보여주기 위한
> 예시이므로, 출제 시 **실제 쿠폰 수치로 행을 교체**해서 쓰면 된다. 헤더(컬럼명)는 절대 바꾸지 말 것.
> 생성기는 **spec 숫자를 직접 베끼지 않고** GA4 주문 로그를 합성한 뒤 *다시 그룹바이('결제완료'만)*해
> 정답을 도출한다 — 그래서 spec과 로그가 어긋나면 `cross_check`가 즉시 중단시킨다(fail-loud).

---

## 1. 컬럼 의미 / 형식 (헤더 순서 고정)

| 컬럼 | 의미 | 형식 / 예시 |
|------|------|------------|
| `coupon_id` | 쿠폰 고유키 | `CPN001` … (중복 금지) |
| `name` | 쿠폰명 | 자유 문자열(쉼표 포함 시 따옴표) |
| `사용건수` | '결제완료' 주문 수(쿠폰 성과 인정 대상) | 0 이상 정수. 결제완료 로그 행 수가 된다 |
| `취소건수` | '취소' 주문 수(성과에서 **제외**되는 함정 주문) | 0 이상 정수. 취소 로그 행 수가 된다 |
| `정상매출_원` | 결제완료 주문들의 매출액 합 | 0 이상 정수. 매출합계의 정답. **사용건수>0이면 양수** |
| `정상할인_원` | 결제완료 주문들의 할인액 합 | 0 이상 정수. 할인합계의 정답. 0이면 `할인0` 표시 |
| `취소매출_원` | 취소 주문들의 매출액 합 | 0 이상 정수. **취소건수=0이면 0**(취소를 잘못 포함하면 부풀려지는 함정값) |
| `취소할인_원` | 취소 주문들의 할인액 합 | 0 이상 정수. 취소건수=0이면 0 |
| `주채널` | 그 쿠폰 결제완료 매출 최다 유입채널 | `Organic Search`\|`Paid Search`\|`Email`\|`Direct`\|`Social`\|`Referral`\|`Display` (사용건수>0이면 필수, 미사용이면 빈칸) |
| `zero_type` | 0 처리 유형 | `none`\|`미사용`\|`할인0` (아래 §3) |
| `round_boundary` | 반올림 경계 쿠폰 | `Y`\|`N`. `Y`면 공헌이익(매출×0.3)이 X.5원 경계에 와야 함(자기검증). `none`에만 가능 |

> ⭐ **집계 지표 ↔ GA4 로그 컬럼 교집합(불변식).** 학생이 채울 모든 지표는 GA4 로그에
> 대응 컬럼이 있어야 계산된다:
> 사용건수↔'결제완료' **행 수** · 매출합계↔`매출액_원` 합 · 할인합계↔`할인액_원` 합 ·
> 주채널↔`유입채널`(매출 argmax) · 기여 판정↔`주문상태` · 공헌이익=매출×0.3 · 순이익=공헌−할인 ·
> ROI=순이익/할인×100 · 적자여부=순이익<0.
> **새 지표 축을 추가하려면** `spec.csv`(입력 컬럼)·`build_dataset.py`(`build_log`의 로그 컬럼과
> `regroup_metrics`의 집계)·`grade.py`(`P1_INT_FIELDS`/`P1_FLOAT_FIELDS`/`P1_STR_FIELDS`)에 짝을
> 함께 추가해야 한다(한쪽만 늘리면 집계 불가).

## 2. 금액 분배 / 공헌이익 / 주채널 (생성기 내부)

- `정상매출_원`·`정상할인_원`은 사용건수개 '결제완료' 주문에 **분배**된다(`distribute`: 몫을 깔고
  나머지를 앞에서부터 +1 → 합이 정확히 spec 값). `취소매출_원`·`취소할인_원`은 취소건수개 '취소'
  주문에 분배된다.
- **공헌이익 = 매출합계 × 0.3**(공헌이익률 30% 고정), 원 단위 round-half-up. **순이익 = 공헌이익 −
  할인합계**(음수 가능). **ROI = 순이익/할인합계×100**(소수 첫째 반올림, 할인0→0.0).
- **주채널**: 생성기는 결제완료 주문 중 다수(약 2/3)를 `주채널`에, 나머지를 다른 채널에 배치해
  `주채널`이 **매출 최다(argmax)** 가 되도록 결정적으로 깐다. `cross_check`가 로그 argmax==spec
  `주채널`이고 **동점이 아님**을 검증한다(동점이면 중단 — 결정성 위반).
- **적자**로 만들려면 `정상할인_원 > 정상매출_원 × 0.3`(할인이 공헌이익보다 큼)으로 둔다.

## 3. zero_type — 할인0 / 미사용 쿠폰

| 값 | 의미 | 제약 |
|---|---|---|
| `none` | 정상 쿠폰 | 사용건수>0 **그리고** 정상할인>0 |
| `할인0` | 할인 0 쿠폰(무료배송 등) | 사용건수>0 **그리고** 정상할인=0. 정답: ROI=0.0, 적자 아님 |
| `미사용` | 아무도 안 쓴 쿠폰(결제완료 0건) | 사용건수=0·정상매출=0·정상할인=0·주채널 빈칸. 정답: 모든 수치=0, ROI=0.0 |

- `미사용`인데 사용건수≠0, `할인0`인데 정상할인≠0(또는 사용건수=0) → `[중단]`(일관성 검증).
- 사용건수=0인데 `zero_type`이 `미사용`이 아니면 → `[중단]`. 정상할인=0(사용>0)인데 `할인0`이
  아니면 → `[중단]`.
- **미사용 쿠폰도 취소 주문은 가질 수 있다**(취소건수>0 → 취소만 있던 쿠폰). 취소건수=0·사용건수=0
  쿠폰(예: `CPN038`)은 GA4 로그에 행이 **0개**지만, 제출 양식·정답키에는 쿠폰 명부로 들어가 0으로
  채워진다(`main`이 spec 전체 순서로 보충).

## 4. round_boundary — 공헌이익 반올림 경계 트랩

`round_boundary=Y`로 둔 쿠폰은 **정상매출_원이 ...5로 끝나** `매출합계×0.3`이 **X.5원 경계**에
오도록 한다. 예: 정상매출 1,000,005 → ×0.3 = 300001.5원 → 반올림 300002 / 버림 300001 로 갈린다.

```
# 경계 판정(build_dataset.py): 매출×0.3 의 소수부가 정확히 0.5 인가
lands_on_margin(rev)  # 끝자리 5 → half-up과 truncate가 1원 차로 갈림
```

- `round_boundary=Y`인데 **공헌이익이 X.5원 경계에 오지 않으면**(정상매출 끝자리가 5가 아니면)
  `cross_check`가 `[중단]`(트랩 실재성 보장).
- 경계 쿠폰은 `none`(정상)에만 둘 수 있다(할인0/미사용엔 불가). 현재 `CPN101`~`CPN106`이 경계 케이스
  (그중 CPN103·105는 적자 경계).

## 5. 기여 규칙(취소 제외) — 이 과제의 핵심 함정

`build_log`는 쿠폰마다 사용건수개 `결제완료` 주문 + 취소건수개 `취소` 주문을 만든다. 취소 주문도
**매출액·할인액이 0이 아니다**(취소 전 금액). `regroup_metrics`는 `주문상태='결제완료'`만 집계하므로,
취소를 포함해 그룹바이하면 사용건수·매출·할인이 부풀려져 모든 파생 지표가 어긋난다. 학생이 이
규칙(‘결제완료’만 인정)을 적용하는지가 1번 변별 함정이다. 주문일은 `ASSIGN_DATE`에서 흩뿌리며
**채점엔 미사용**이다.

## 6. 재생성 → 채점 절차

```bash
# 1) spec.csv 를 실제 쿠폰 수치로 채운다 (헤더 유지, 일관성 규칙 지킴)
# 2) 데이터·정답 동시 생성
python3 eval/answer_key/build_dataset.py
#    → 데이터/1_GA4_주문기록.xlsx
#    → 데이터/1_쿠폰별_성과표_제출용.xlsx, 데이터/2_전체요약_제출용.xlsx
#    → 데이터/2_정리된_쿠폰성과표_참고용.xlsx  (Part2 입력용 정답 집계표 = 분리형)
#    → eval/answer_key/1_쿠폰별_성과표_정답.xlsx, 2_전체요약_정답.xlsx
# 3) 학생 제출물 채점 (P1 셀 비교 + P2 요약 1행)
python3 eval/grade.py \
  --part1 데이터/1_쿠폰별_성과표_제출용.xlsx \
  --part2 데이터/2_전체요약_제출용.xlsx \
  --answer-dir eval/answer_key
```

> **고정 기준일 `ASSIGN_DATE = 2026-06-28`** (build_dataset.py 상단 상수, `datetime.now()`
> 미사용)은 **주문일 합성에만** 쓰고 채점·집계에는 쓰지 않는다. `random.seed(20260628)`도
> 고정이라, `spec.csv`가 같으면 GA4 로그·양식·정답이 **언제 재생성해도 동일**하다(값 수준 재현성 확인).

현재 `spec.csv`는 쿠폰 **44건** 구성이다:
- **정상(`none`) — 40건**: 일반 쿠폰(흑자/적자 혼합. 그중 `CPN101`~`CPN106`은 `round_boundary=Y` 경계 트랩).
- **할인0(`할인0`) — 2건**: `CPN035`·`CPN036` — 무료배송 쿠폰. ROI=0.0(0 나눗셈 안 함), 적자 아님.
- **미사용(`미사용`) — 2건**: `CPN037`(취소만 있음)·`CPN038`(주문 자체 없음) — 모든 수치=0, ROI=0.0.
- **적자 쿠폰 8개**: 정상할인 > 매출×0.3 인 깊은 할인 쿠폰(예: `CPN009`·`CPN021`·`CPN031`·`CPN032`·
  `CPN103`·`CPN105` 등). 전체ROI(가중) 64.1% / 적자쿠폰수 8개.

`spec.csv`만 바꾸면 GA4 로그·함정·정답이 새 쿠폰 구성에 맞춰 재생성되므로, 출제자는
쿠폰 수치만 정확히(일관성 규칙 지켜) 입력하면 된다.
