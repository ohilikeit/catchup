# 평가 방식 (evaluation)

> 제출물 2개를 **정답키와 자동 대조**한다. 채점 스크립트는 [`grade.py`](grade.py), 정답키는 [`answer_key/`](answer_key/).
> 결과(문제 해결) 점수만 다룬다. 과정(AI 협업) 점수는 채팅 로그 기반 별도 루브릭.

## 1. 제출물 스키마 (정답이 결정되는 형식)

### Part 1 — `쿠폰별_성과표_작성용.xlsx` · 시트 `집계표`
행 단위 = **쿠폰 1건** (`GA4_주문기록.xlsx`에 등장하는 모든 `쿠폰코드` + 미사용 쿠폰 포함, 양식에 미리 제공). 정답은 모두 GA4 로그를 `쿠폰코드`로 그룹바이하되 **'결제완료'만** 세어 도출한다. 컬럼 순서: `쿠폰코드,사용건수,매출합계,할인합계,공헌이익,순이익,ROI,주채널,적자여부`.

| 컬럼 | 형식 / 허용값 | 채점유형 |
|---|---|---|
| `쿠폰코드` | `CPN001`… (키) — **양식에 미리 주어짐(채점 안 함)** | — |
| `사용건수` | 정수(그 쿠폰 '결제완료' 주문 행 수) | Exact(정수) |
| `매출합계` / `할인합계` | 정수(원, '결제완료' 주문 `매출액_원`/`할인액_원` 합) | Exact(정수) |
| `공헌이익` | 정수(원). 매출합계×0.3, 원 단위 반올림(round-half-up) | Exact(정수) |
| `순이익` | 정수(원). 공헌이익−할인합계. **음수 가능** | Exact(정수) |
| `ROI` | 순이익/할인합계×100, 소수 첫째 자리 반올림. 할인합계=0 → `0.0` | **Computed(±0.1)** |
| `주채널` | '결제완료' 매출 최다 유입채널(GA4 채널그룹). 미사용 → **빈칸** | **문자 Exact**(별칭 정규화) |
| `적자여부` | 순이익<0 → `적자`, 아니면 **빈칸** | **문자 Exact**(별칭 정규화) |

> `쿠폰코드`는 제출 양식에 **미리 채워져 제공**된다(채점 대상 아님). **미사용 쿠폰(결제완료 0건)은 건수·합계·이익=`0`, ROI=`0.0`, 주채널·적자여부 빈칸이 정답**(건수·합계는 빈칸이 아닌 `0`). **할인합계=0 쿠폰**은 ROI=`0.0`(0 나눗셈 안 함), 순이익=공헌이익≥0이라 적자 아님(적자여부 빈칸). ROI 칸은 `33.3` 같은 숫자로 적는다(`%`·콤마는 채점 시 제거). 주채널은 `Paid Search` 같은 채널명 그대로(대소문자·공백·흔한 한글 별칭은 정규화로 흡수).

### Part 2 — `전체요약_작성용.xlsx` · 시트 `전체요약`
행 단위 = **전사 요약 단 1행**. 입력은 **제공된 정답 집계표 `정리된_쿠폰성과표_참고용.xlsx`**(분리형 — Part1을 틀려도 Part2는 영향 없음). 컬럼 순서: `총사용건수,총매출,총할인,총공헌이익,총순이익,전체ROI,적자쿠폰수`.

| 컬럼 | 형식 / 허용값 | 채점유형 |
|---|---|---|
| `총사용건수` / `총매출` / `총할인` / `총공헌이익` / `총순이익` | 정수(모든 쿠폰 합) | Exact(정수) |
| `전체ROI` | **총순이익/총할인×100 (가중)**, 소수 첫째 자리 반올림. 쿠폰별 ROI의 단순평균이 아니다 | **Computed(±0.1)** |
| `적자쿠폰수` | 정수(순이익<0 쿠폰의 개수) | Exact(정수) |

> **전체ROI를 '쿠폰 ROI들의 평균'으로 내면 가중 정답과 크게 벌어져 오답**이 잡힌다(핵심 함정: 가중 64.1% vs 단순평균 ≈93%). 행 순서·여분 빈칸은 무시한다.

## 2. 채점 로직 (`grade.py` 구성요소)

```
grade.py
├─ load_sheet(path, sheet)            # openpyxl 로드 → 헤더 정규화, 빈 행 스킵
├─ norm_int(v)                        # 건수·합계·이익: 빈칸 보존(0과 구분), 콤마·공백·'원'·.0 제거 → 정수 문자열
├─ norm_float(v)                      # 율: 콤마·%·공백 제거 → float (빈칸/파싱불가 → None)
├─ norm_channel(v)/norm_deficit(v)    # 문자: 채널 별칭/적자 별칭 정규화 → 정규값 또는 ''
├─ grade_part1(sub, ans)             # 쿠폰별 집계표: 키(쿠폰코드)로 조인, 셀 단위 비교
│   • P1_INT_FIELDS(사용건수·매출합계·할인합계·공헌이익·순이익) → int_eq (정수 Exact)
│   • P1_FLOAT_FIELDS(ROI)                                  → float_eq(±0.1)
│   • P1_STR_FIELDS(주채널·적자여부)                          → str_eq(정규화 Exact)
│   • 유령 쿠폰코드(정답에 없는 키) + 제출 행 음수 금액/건수(순이익 제외) 탐지
├─ grade_part2(sub, ans)             # 전체 요약 1행: 셀 단위 비교
│   • SUM_INT_FIELDS(총사용건수·총매출·총할인·총공헌이익·총순이익·적자쿠폰수) → int_eq
│   • SUM_FLOAT_FIELDS(전체ROI)                                            → float_eq(±0.1)
└─ score(p1, p2) + report()          # 영역별 점수 산정 → JSON + 콘솔 표
```

### 채점 프리미티브
- `int_eq`(건수·합계·이익): `norm_int`로 정규화 후 **문자열 정확 일치**. 빈칸≠`0`(빈칸=미기입, 0=값 0). 천단위 콤마·`원`·`.0` 허용. **순이익은 음수도 정확 일치로 채점**(적자 쿠폰).
- `float_eq`(ROI·전체ROI, **tol=0.1**): `norm_float` 후 `round(|정답−제출|, 4) < 0.1`이면 정답. 정답은 항상 숫자(할인0이면 0.0), 제출이 비었으면 오답. **4자리 반올림으로 부동소수 잡음 제거**.
- `str_eq`(주채널·적자여부): `주채널`은 대소문자·공백 무시 + 흔한 한글 별칭(유료검색→Paid Search 등) 흡수 후 일치. `적자여부`는 `적자`/`Y`/`손해`류→`적자`, 빈칸/`흑자`/`N`→빈칸으로 정규화 후 일치(과민 채점 방지).
- 빈 행·여분 행: 모든 셀이 비면 스킵. 행 순서는 채점에 무관(키로 조인).

## 3. 배점 (결과 점수 100점 기준)

| 영역 | 배점 | 산정 |
|---|--:|---|
| Part 1 쿠폰별 집계표 | 55 | 셀 정확도 × 55 (정확 셀 / 전체 채점 셀; 8필드 × 쿠폰 수) |
| Part 2 전체 요약 | 35 | 셀 정확도 × 35 (7필드 중 정확 셀 비율) |
| 무결성 | 10 | `10 − (유령 쿠폰코드 + 음수 금액/건수) × 0.5` (최저 0) |

> **합격선(1단계 능력)**: 그룹바이로 건수·합계·이익을 일관 산출. **변별(2단계)**: 취소 제외(기여 규칙)·할인0·공헌이익 반올림 경계를 모두 통과하고, Part2 전체ROI를 **가중**으로 내 만점에 수렴.

### 흔한 실패 = 의도한 함정 적중
- '취소' 주문까지 그룹바이에 포함 → **사용건수·매출·할인이 모두 부풀려져** 공헌이익·순이익·ROI·적자여부·주채널·전사 요약까지 연쇄 오답(자기채점 100→64.7점).
- ROI를 `순이익/할인`으로 그냥 계산 → **할인 0 쿠폰에서 0 나눗셈 오류/빈칸** → ROI 셀 오답.
- 공헌이익(매출×0.3)을 버림·banker's로 처리 → **X.5원 경계 쿠폰(CPN101~106)에서 1원 차** → 공헌이익·순이익 셀 오답.
- 전체ROI를 **쿠폰 ROI들의 단순평균**으로 산출 → 가중 정답과 갈려 Part2 `전체ROI` 셀 오답.
- 그룹바이를 잘못해 정답에 없는 쿠폰코드를 만들거나 금액을 음수로 적음 → **무결성 감점**.

## 4. 정답키 생성·관리

- 정답키(`answer_key/coupon_roi_answer.xlsx`, `answer_key/summary_answer.xlsx`)와 제공 데이터(`../데이터/`)는 **단일 입력 [`answer_key/spec.csv`](answer_key/spec.csv)** 에서 같은 스크립트로 나온다 → GA4 로그·집계표·요약·정답이 항상 정합.
- 쿠폰을 바꾸려면 **`spec.csv`만 수정**하고 `build_dataset.py`를 다시 돌려 **데이터와 정답키를 동시 갱신**한다(생성물 수기 편집 금지). CSV 작성법은 [`answer_key/INPUT_GUIDE.md`](answer_key/INPUT_GUIDE.md).
- 생성기 책임: `spec.csv` 읽기(zero_type·취소 일관성·주채널·매출↔이익 **fail-loud 검증**) → 1행=1주문 GA4 로그 합성(결제완료+취소) → `regroup_metrics`로 '결제완료'만 재집계 → `cross_check`(재집계==spec, 주채널 argmax strict, 반올림 경계 실재) → 제출양식·`정리된_쿠폰성과표_참고용.xlsx`·정답키 산출. 기준일 `ASSIGN_DATE = 2026-06-28`·`random.seed(20260628)` 상수 고정(`datetime.now()` 미사용; 주문일 합성용으로만, 채점엔 미사용).
- **정답 도출 철학**: spec.csv의 숫자를 그대로 베끼지 않고, 합성한 GA4 로그를 **다시 그룹바이**해 지표를 계산한다 → 독립검증·결정성 성립.

## 5. 채점 실행

```bash
# 학생 제출물 채점
python eval/grade.py \
  --part1 데이터/쿠폰별_성과표_작성용.xlsx \
  --part2 데이터/전체요약_작성용.xlsx \
  --answer-dir eval/answer_key
# → 콘솔 표 + result.json (영역별 점수·필드별 정확도·오답 상세)

# 자기채점(정답키 자기검증, 100점 기대)
python eval/grade.py \
  --part1 eval/answer_key/coupon_roi_answer.xlsx \
  --part2 eval/answer_key/summary_answer.xlsx \
  --answer-dir eval/answer_key
```
