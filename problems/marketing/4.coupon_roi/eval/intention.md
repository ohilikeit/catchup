# 출제 의도 (intention)

> 이 문제가 **무엇을 측정**하고, **어떤 결함을 일부러 심었으며**, 학생이 **어떤 과정으로 풀기를** 기대하는지 핵심만 적는다.

## 한 줄 의도

> "수천 행짜리 GA4 주문 로그를 코드로 그룹바이해 쿠폰별 ROI·적자 성과표 + 전사 요약 한 줄로 줄인다" — **이커머스 마케터의 쿠폰 성과 집계 업무를 챗봇 붙여넣기로는 못 풀고(로그가 너무 길고 행 단위라) Claude Code 오케스트레이션으로만 풀리게** 만든 문제. 모든 데이터·정답은 단일 입력 `spec.csv`에서 주문 로그를 합성해 생성되며, 쿠폰 구성을 바꿔도 동일 구조로 재현된다.

## 측정하는 능력

| 축 | 무엇을 보는가 |
|---|---|
| **직무 능력 (마케팅 퍼포먼스)** | 쿠폰별로 매출 기여와 할인 비용을 맞춰 ROI를 정의대로 산출하고, 어떤 쿠폰이 적자인지 가려내며, 전사 성과를 올바른 가중으로 요약하는 퍼포먼스 분석 감각. "쿠폰을 많이 쓴다 ≠ 좋다"를 수치로 보이는 판단 |
| **AI 활용 능력** | ① GA4 원시 로그를 코드로 열어 그룹바이 ② 기여 규칙(취소 제외)·이익률·반올림을 규칙으로 데이터에 일관 적용 ③ 재사용 가능한 집계 파이프라인 작성 ④ 분모0·반올림 경계·합계 검산 등 결과 검증 |
| **문제 해결력** | 긴 비정형 주문 로그 → 기여 규칙 적용 → 정형 성과표로 환원하는 분해력. "취소 주문 제외", "할인 0 분모0", "공헌이익 X.5원 반올림 경계", "**가중평균 vs 단순평균**" 함정을 스스로 발견·처리. 눈대중·단순평균으로 넘겨짚지 않고 정의된 식 그대로 계산하는 판단 |

> 설계 근거: [`../../../문제유형뱅크/MKT-07-coupon-roi.md`](../../../문제유형뱅크/MKT-07-coupon-roi.md)(원본 `_6 MKT-L2-X2`, ③집계/분석)를 실제 도메인(GA4 전자상거래 export)으로 구현하고, 기여 규칙(취소 제외)·분모0·반올림 경계·가중평균(Part2) 함정을 얹어 **2단계**로 끌어올린 사례. 채점은 [`_5 §6`](../../../_5직무-바이브코딩-과제설계.md)의 결정성 원칙을 따른다. 레퍼런스 집계 엔진은 `problems/marketing/2.email_campaign_metrics`.

## 일부러 심은 결함 (함정)

학생이 **데이터를 곧이곧대로 계산하면 틀리도록** 설계했다. 이걸 발견·처리하는지가 변별점이다.

1. **기여 규칙 — 취소 주문 제외** — GA4 로그에는 `주문상태='취소'` 주문이 섞여 있고, 그 주문도 매출액·할인액이 0이 아니다(취소 전 금액). '취소'까지 포함해 그룹바이하면 사용건수·매출합계·할인합계가 모두 부풀려져, 공헌이익·순이익·ROI·적자여부·주채널·전사 요약까지 연쇄로 어긋난다. **정답은 '결제완료'만 인정.** "맞추는 게 먼저, 줄이는 건 그다음"의 핵심 함정. (검증: 취소 포함 시 자기채점 100→64.7점)
2. **할인 0 (분모0)** — 할인을 한 푼도 안 준 쿠폰(무료배송 등)이 섞여 있다. ROI를 `순이익/할인`으로 그냥 계산하면 0 나눗셈 오류가 나거나 칸을 비우게 된다. **정답은 ROI=0.0, 적자 아님**(순이익=공헌이익≥0). 아무도 안 쓴 미사용 쿠폰(결제완료 0건)은 모든 수치=0, ROI=0.0, 주채널·적자여부 빈칸.
3. **공헌이익 반올림 경계 (X.5원)** — 일부 쿠폰은 매출합계가 ...5로 끝나 **매출합계×0.3이 X.5원**(예: 300001.5원)에 온다. 반올림(round-half-up)으로 올리면 300002, 버리거나 banker's로 내리면 300001 — 공헌이익·순이익이 1원 어긋나 정수 Exact에서 오답이 잡힌다. spec의 `round_boundary=Y` 쿠폰은 `cross_check`가 **실제로 X.5원 경계에 오는지 자기검증**한다(트랩 실재성 보장).
4. **가중평균 vs 단순평균 (Part2)** — 전체 ROI를 **쿠폰별 ROI들의 평균**으로 내면 오답이다. 정답은 **총순이익 ÷ 총할인 (가중)** — 할인 규모가 큰 쿠폰이 더 큰 가중을 갖는다. 할인 규모가 들쭉날쭉하게(수천원~백만원) 설계돼 두 방식이 분명히 갈린다(가중 64.1% vs 단순평균 ≈93%). 가장 크게 갈리는 변별 함정.

> 결정성 봉쇄: 공헌이익률은 **30% 고정**, ROI 반올림은 **소수 첫째 자리 round-half-up**, 기여 인정은 **'결제완료' 단일 기준**으로 못 박아 정답이 갈릴 자유도를 0으로 만들었다. 매출×0.3이 애매하게 떨어지는 경우는 `Decimal` round-half-up으로 정확히 X.5에만 경계가 오게 합성하고, ROI 채점은 ±0.1 허용오차로 부동소수 잡음을 흡수하되 반올림을 반대로 굴린 차이는 정수 칸(공헌이익·순이익)에서 엄격히 잡는다. 모든 케이스는 명시 규칙으로 단일 정답에 매핑되며, 정답은 항상 `spec.csv` → GA4 로그 합성 → `regroup_metrics` 재집계에서 유일하게 산출된다.

## 기대하는 풀이 과정

1. **GA4 주문 로그를 코드로 연다** — `GA4_주문기록.xlsx`(1행=1주문)를 읽어 `주문상태='결제완료'`만 필터하고 `쿠폰코드`로 그룹바이한다. (손/챗봇 붙여넣기로는 수천 행을 일관 집계 불가)
2. **쿠폰별 집계표를 만든다(Part 1)** — 사용건수·매출합계·할인합계(건수·합계)를 내고, 공헌이익=매출×0.3(원 단위 반올림)·순이익·ROI(소수 첫째 반올림, 할인0→0.0)·주채널(매출 최다 채널)·적자여부(순이익<0)를 정의대로 계산한다.
3. **전체 요약을 만든다(Part 2)** — 제공된 정답 집계표(`정리된_쿠폰성과표_참고용.xlsx`)를 입력으로 총합을 내고, **전체ROI는 총순이익/총할인으로 가중** 계산(단순평균 금지), 적자쿠폰수를 센다.
4. **검증한다** — 취소 주문을 뺐는지, 쿠폰 합계가 결제완료 행 수와 맞는지, 할인0 쿠폰이 0.0으로 처리됐는지, 전체ROI가 단순평균이 아닌지 표본 점검. (검증 습관이 변별 포인트)

## 현실성 (왜 이 시나리오인가)

GA4(구글 애널리틱스 4)는 전자상거래 `purchase` 이벤트를 거래 단위로 쌓고, 쿠폰(`coupon`)·유입채널(`session_default_channel_group`)·매출(`purchase_revenue`)을 함께 기록한다. 마케터는 이 export를 쿠폰 단위로 집계해 "어떤 프로모션이 남는 장사였나"를 본다. **"GA4 주문 로그 → 쿠폰 ROI 성과표 → 전사 요약"** 은 이커머스·퍼포먼스 마케팅에서 분기마다 반복되는 실제 업무 형태이며, 특정 회사·툴에 종속되지 않은 보편 집계 과제다.

> **데이터 출처·고정성**: 쿠폰별 사용·취소·매출·할인·주채널 수치는 운영자가 단일 입력 `eval/answer_key/spec.csv`에 채운다. `build_dataset.py`가 그 spec으로 **1행=1주문 GA4 로그를 합성**(쿠폰마다 사용건수개 결제완료 + 취소건수개 취소, 매출·할인은 각 주문에 분배, 유입채널은 주채널이 매출 최다가 되도록 결정적 배치)하고, 그 로그를 **'결제완료'만 다시 그룹바이**(`regroup_metrics`)해 정답을 도출한다 — spec 숫자를 직접 베끼지 않으므로 독립검증이 성립한다. 모든 집계 지표는 GA4 로그에 대응 컬럼(사용건수↔결제완료 행 수, 매출/할인↔`매출액_원`/`할인액_원`, 주채널↔`유입채널`, 기여↔`주문상태`)이 있어야 계산된다(집계↔로그 교집합 불변식). **현재 spec.csv는 쿠폰 44개 구성 — 정상(none) 40건(그중 반올림 경계 6건 CPN101~106) + 할인0 2건(CPN035·036) + 미사용 2건(CPN037·038), 적자 쿠폰 8개.** GA4 로그·제출양식·정답키는 이 CSV **하나만 읽어** 한 번에 생성되며, 기준일 상수(`ASSIGN_DATE = 2026-06-28`, 주문일 합성용·채점 미사용)와 `random.seed(20260628)`가 고정돼 있어 **언제 재생성해도 동일**하다(값 수준 재현성 확인). 쿠폰을 추가/수정하려면 `spec.csv`만 고치고 재실행하면 데이터·정답이 함께 갱신된다.
