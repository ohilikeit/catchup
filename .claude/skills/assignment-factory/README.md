# assignment-factory — 결정성 평가 과제 생성기

AI·바이브코딩 **역량 평가 과제**를 한 벌씩 찍어내는 스킬입니다. `(테마 + 직무 + 난이도)`만 주면
**학생용 문제지(problem.md) + 데이터(엑셀·CSV) + 자동 채점기 + 정답키**를 재현 가능하게 생성합니다.

> 한 줄 요약: **"실무 업무를 자동 채점되는 시험 문제로 바꿔주는 출제 기계."**

---

## 무엇을 만들어 주나

요청 한 번에 아래 한 벌(`problems/<직무>/<번호>.<슬러그>/`)이 통째로 나옵니다.

```
problem.md                 ← 학생이 읽는 업무 브리프(쉬운 말, 비개발자용) + 폴더트리
데이터/                     ← 학생에게 주는 입력(한국어 역할명 + 문제번호 prefix N_)
│   ├── 1_<역할>_제출용.xlsx ← 1번 문제 제출 양식(학생이 채움)
│   ├── 2_회원명단.xlsx      ← 2번 문제 입력(분석할 명단/데이터)
│   ├── 2_<역할>_제출용.xlsx ← 2번 문제 제출 양식
│   └── 2_<역할>_참고용.xlsx ← (분리형) 2번 문제 입력 정답표(보고 베낌)
eval/                      ← 출제·채점 인프라(영어 식별자 유지 OK)
├── README.md / intention.md / evaluation.md   ← 출제 의도·채점 방식 문서
├── grade.py               ← 자동 채점기 (실행하면 점수)
└── answer_key/
    ├── <입력>.csv         ← 단일 진실 소스 (이 한 파일이 전체를 결정)
    ├── build_dataset.py   ← 데이터·정답 생성기
    └── <N>_<역할>_정답.xlsx ← 정답키(학생 제출용 파일명에서 _제출용→_정답)
```

**핵심 철학** — 학생이 풀이법을 *발명*하지 않고 *주어진 규칙을 적용*하게 만듭니다. 그래서
모든 채점 칸은 (제공 파일 + 명시 규칙) → **유일한 정답**으로 떨어지고, 채점이 100% 자동·결정적입니다.
일부러 심은 함정(경계값·표기 불일치·판별 불가 등)을 *검증 안 하면 점수가 깎이게* 설계합니다.

## 빠른 사용법

### 1) 슬래시 커맨드 — 유형을 알 때 (직행, 권장)

| 커맨드 | 만드는 과제 | 예시 |
|---|---|---|
| `/과제-매칭` | 타게팅·세그먼트·대상 선별 | `/과제-매칭 헬스장 휴면 회원 타게팅, 마케팅, 2단계` |
| `/과제-검증` | 대사·감사·규칙 위반 판정 | `/과제-검증 은행 거래 vs 장부 대사, 일반사무, 2단계` |
| `/과제-집계` | 집계·성과지표·대시보드 | `/과제-집계 지점별 월매출 대시보드, 일반사무, 3단계` |
| `/과제-취합` | 취합·통합·표준화·중복제거 | `/과제-취합 다출처 고객 리스트 정규화, 마케팅, 1단계` |
| `/과제-분류` | 분류·라벨링·감성/유형 판정 | `/과제-분류 SNS 멘션 감성·주제 분류, 마케팅, 2단계` |

### 2) 자연어 — 유형을 모를 때 (스킬이 알아서 라우팅)

> "신입 마케터용으로 자동 채점되는 평가 과제 하나 만들어줘"
> "이 업무를 학생 시험 문제로 바꿔줘"

스킬이 인터뷰로 **테마·직무·난이도·아키타입**을 정한 뒤 알맞은 엔진으로 생성합니다.
지원 5종(매칭·검증·집계·취합·분류)이 아니면(예: 랭킹·퍼널·초안) "미지원 + 수동 설계 가이드"를 정직하게 돌려줍니다.

### 3) 만든 과제 채점해 보기

```bash
cd problems/<직무>/<번호>.<슬러그>
# 2-part 과제(매칭·검증·집계):
python3 eval/grade.py --part1 <제출.xlsx> [--part2 <제출2.xlsx>] --answer-dir eval/answer_key
# 단일 산출 과제(취합·분류):
python3 eval/grade.py --submission <제출.xlsx> --answer-dir eval/answer_key
# → 총점(100) 100.0  (정답키로 돌리면 항상 100)
```

## 지원 유형 (엔진 5종)

각 "엔진"은 한 채점 방식에 대응합니다. 새 과제는 엔진을 새 테마로 적응시켜 찍어냅니다.

| 문제유형 | 채점 방식 | 엔진 | 커맨드 | 레퍼런스 과제 |
|---|---|---|---|---|
| 매칭·타게팅 (+추출) | 집합 + 셀 정확 | `engines/matching` | `/과제-매칭` | `marketing/1.youth_policy` |
| 검증·감사·대사 | 위반 집합 F1 | `engines/audit` | `/과제-검증` | `general/1.three_way_match` |
| 집계·분석 | 수치 ±허용오차 | `engines/aggregate` | `/과제-집계` | `marketing/2.email_campaign_metrics` |
| 취합·통합 | 행집합 + 정규화 셀 | `engines/merge` | `/과제-취합` | `general/2.order_consolidation` |
| 분류·라벨링 | 다클래스 macro-F1 | `engines/classify` | `/과제-분류` | `marketing/3.voc_classification` |

**아직 미지원**: 초안 작성(⑤)·랭킹·퍼널. 초안은 "없던 글 쓰기"라 결정성과 근본 충돌(형식 채점만 가능), 랭킹·퍼널은 엔진 추가로 확장 가능.

## 어떻게 동작하나 (파이프라인)

```
S1  인터뷰        테마·직무·난이도·축/규칙을 묻는다
S1.5 라우팅       아키타입 판정 → 엔진 선택 (지원 밖이면 정직하게 가이드만)
S2  도메인 조사    실제 도메인 사실 수집 + 특정 회사색 제거
S3  축/규칙 설계   판정 기준 ↔ 데이터 컬럼 1:1 매핑 확정
S4  단일 입력      <입력>.csv 한 파일이 전체를 결정 (재현성)
S5~7 생성·채점     엔진을 새 스키마로 적응 → 데이터·함정·채점기
S8~9 문서          eval 문서 4종 + 학생용 problem.md
S10 검증(필수)     ① 독립 재계산(생성코드 안 쓰고 정답 재확인)
                  ② 적대 리뷰  ③ 발행 체크리스트 — 셋 다 통과해야 발행
```

전 과정에서 **결정성**(유일 정답)·**단일 입력**(재현성)·**의도된 함정**(검증 역량 측정)·
**독립 검증**(자기충족 채점 방지)을 지킵니다.

## 폴더 안내 (개발자용)

| 위치 | 내용 |
|---|---|
| `SKILL.md` | 진입점 — 철학·기본값·파이프라인·참조 색인 |
| `references/*-engine-guide.md` | 엔진별 적응 절차(매칭/검증/집계/취합) |
| `references/interview.md` · `pipeline.md` · `archetypes.md` | 인터뷰 질문 · 단계표 · 아키타입 라우팅 |
| `references/doc-templates.md` · `checklist.md` · `multimodal-sourcing.md` | 문서 골격 · 발행 게이트 · 멀티모달 소싱 |
| `engines/<유형>/` | 검증된 생성기·채점기·예시 입력 (복제해서 적응) |
| `verify/` | 독립 재계산 · 적대 리뷰 방법 |

### 새 엔진을 추가하려면
`engines/<유형>/`에 같은 **엔진 계약**(단일 입력 CSV → 데이터 + 제출양식 + 정답키 + grade.py)을
구현하고, `references/<유형>-engine-guide.md`를 쓰고, `archetypes.md`·`SKILL.md` 라우팅에 등록하면 끝입니다.
인터뷰·문서·검증·결정성 게이트는 전 엔진이 공유하므로, 실제로 새로 만드는 건 **데이터 생성기 + 채점 방식**뿐입니다.
