# S10 게이트 1 — 독립 재계산 (Independent Recompute)

> 발행 전 필수 게이트. **`build_dataset.py`의 로직을 한 줄도 재사용하지 않고**, `policies.csv`(단일 입력)와 안내시트에 명시된 규칙만으로 정답 매칭을 **처음부터 다시 계산**해 생성된 `*_answer.xlsx`와 **셀 단위로 대조**한다. extra(정답에 없는데 재계산엔 있음)·missing(정답엔 있는데 재계산엔 없음)이 **둘 다 0건**이어야 통과. 하나라도 있으면 발행 차단.

## 왜 독립 구현이어야 하는가

`build_dataset.py`가 정답키를 만들고 `grade.py`가 그 정답키로 학생을 채점한다. 둘은 같은 작성자·같은 세션에서 나온 코드라 **같은 버그를 공유**할 수 있다. 예: `member_passes`의 소득 비교가 실수로 `<`(미만)인데 안내시트는 `<=`(이하)라면, 정답키도 틀리고 채점도 틀린 정답키로 매기므로 **점수는 만점이 나오면서 과제 자체가 틀린다**. 이게 "자기충족 채점(self-fulfilling grading)"의 허점이다.

`grade.py`로 정답키를 다시 채점하는 것은 검증이 **아니다**(같은 버그를 통과시킨다). 검증은 **다른 사람이 안내시트만 보고 손으로 푼 답**과 정답키를 비교하는 것과 같아야 한다. 그래서 재계산기는 build_dataset의 함수(`member_passes`·`plant_boundaries`·`region_match`·`manage` 등)를 import도 복붙도 하지 않고, **안내시트(`build_p2` guide L643–667)와 INPUT_GUIDE의 규칙 서술만 읽고 새로 구현**한다.

## 절차 (youth_policy에서 워크플로 검증 에이전트가 실제로 한 방식)

입력 두 개를 **직접 파싱**한다: `data/members.xlsx`(생성된 모집단)와 `eval/answer_key/policies.csv`(단일 진실 소스). build_dataset이 만든 회원을 그대로 받아쓰되, **자격 판정 규칙은 안내시트만 보고 재구현**한다.

1. **입력 직접 로드**
   - `policies.csv`를 DictReader로 읽는다(헤더 고정). `matchable` 컬럼을 본다.
   - `data/members.xlsx`의 `회원` 시트를 openpyxl로 읽어 회원 dict 리스트로 만든다.
   - 둘 다 build_dataset 함수 없이 표준 라이브러리/openpyxl만 사용.

2. **규칙 재구현 (안내시트 문구를 코드로)** — 각 (회원, 정책) 쌍에 대해 안내시트의 자격 판정 규칙을 **독립 함수로 새로 작성**한다:
   - **나이**: 만 나이 = 기준일 `2026-06-28` 기준, *생일이 안 지났으면 한 살 뺀다*(연도만 빼면 틀림). `age_min<=만나이<=age_max`(양끝 포함, 빈칸이면 그 방향 무시).
   - **거주지**: `전국`=모두 / 시도=그 시도 / 시도+자치구=그 자치구. 회원 주소 표기가 제각각이어도 시·도와 자치구로 판단. (정규화 로직을 직접, build의 `detect_*`를 쓰지 말고 다시 짠다.)
   - **취업**: `미취업`={미취업,단기근로} / `재직`={재직,단기근로} / 빈칸=모두.
   - **기업규모**: 값 있으면 정확히 일치 / 빈칸=모두.
   - **월소득·연소득**: 상한 있으면 `회원값 <= 상한`(같으면 통과), 빈칸=모두. **빈칸≠0** 구분.
   - **무주택**: `필요`면 주택소유여부=`아니오` / 빈칸=모두.
   - **학력**: `재학`={재학,휴학} / `졸업`={졸업} / 빈칸=모두.
   - **혼인**: `신혼부부`={기혼} / `미혼`={미혼} / 빈칸=모두.
   - **판별불가**: `matchable=N` 정책은 **누구에게도 추천 안 함**(0건).
   - **날짜**: 신청시작/마감은 **보지 않는다**(자격만).
   - 모든 조건을 AND로 통과한 (회원ID, 정책ID)만 매칭 집합에 넣는다.

3. **비교**
   - **Part2**: 재계산 매칭 집합 ↔ `eval/answer_key/targeting_answer.xlsx`의 (회원ID,추천정책ID) 집합을 set 연산으로 대조. `extra = recompute - answer`, `missing = answer - recompute`. 둘 다 비어야 PASS. 비면 어느 정책·어느 경계 표본에서 갈렸는지 출력.
   - **Part1**: 재계산이 `policies.csv`에서 직접 뽑은 자격 칸(거주/연령min/연령max/…) ↔ `policy_table_answer.xlsx`의 `정책정리` 시트를 셀 단위 대조. 불일치 셀 0건이어야 PASS. (matchable=N 정책은 **회원 데이터로 확인 불가한 자격 칸만 공백** — 모든 정책 필수 메타인 지역요건 등 브리프에서 자명한 칸은 채워질 수 있으니, 재계산 시에도 csv의 그 값을 그대로 둔다.)

4. **재현성 교차 확인**: `build_dataset.py`를 한 번 더 실행해도 `members.xlsx`·정답키가 바이트 동일(또는 매칭 집합 동일)한지 확인 → seed/기준일 고정(G10) 증거.

## 점검할 경계 표본 목록 (이 케이스들이 정확히 갈렸는지 명시 확인)

재계산이 정답과 일치해도, 아래 경계가 **실제로 양쪽에 존재하고 올바른 쪽으로 갈렸는지**를 표본 점검한다(전체 일치가 우연이 아님을 보장):

- **나이 경계**: `age_min-1`(제외)·`age_min`(포함)·`age_max`(포함)·`age_max+1`(제외) 각 1명 이상. 양끝 포함(`<=`,`>=`)이 맞는지.
- **만나이 미경과**: 7–12월생이면서 만나이=`age_max`(포함=정답)·만나이=`age_min-1`(제외=정답)인 회원 — 연도만 빼면 틀리는 함정이 올바로 갈렸는지(B2).
- **소득 경계**: 월소득=`income_max`(통과)·`income_max+1`(탈락), 연소득=`income_year_max`(통과)·`+1`(탈락). `<=`인지.
- **지역 표기**: 같은 자치구를 `서울특별시 관악구 …`/`서울 관악구`/`서울시 관악구`/`관악구 …`로 쓴 회원이 모두 동일 판정인지(B4). 같은 시도 다른 자치구는 탈락인지.
- **빈칸 vs 0**: 자격 칸이 빈 정책에서 그 축으로 아무도 탈락하지 않는지(빈칸=무관). 상한이 0인 정책이 있으면 0원 회원만 통과하는지(빈칸≠0).
- **판별불가 0건**: `matchable=N` 정책의 재계산 매칭이 정확히 0건인지. 정답표 그 행의 자격 칸이 모두 공백인지.
- **취업 예외**: 단기근로 회원이 미취업·재직 요건 양쪽에서 통과하는지(B8).
- **무주택/학력/혼인**: 요건 있는 정책에서 소유=예 회원, 졸업≠재학 회원, 미혼≠기혼 회원이 올바로 탈락하는지.
- **전국 정책**: 모든 시도 회원이 통과하는지(지역 축 무시).

## 통과 기준

- Part1 불일치 셀 0건 **그리고** Part2 extra 0건 + missing 0건.
- 위 경계 표본이 모두 존재하고 올바른 방향으로 갈림.
- 재실행 재현성 확인.

하나라도 어긋나면 **발행 차단**. 어긋난 표본이 가리키는 축의 규칙을 build_dataset·grade·안내시트 **세 곳**에서 함께 점검해 고치고(축↔컬럼 교집합 불변식), 처음부터 다시 재계산한다.
