# 분류 엔진 적응 가이드 (S5~S7) — `engines/classify/`을 새 분류 테마로 바꾸기

**목적**: 검증된 분류 엔진(`engines/classify/build_dataset.py` 395줄 · `grade.py` 228줄)을 새 라벨 집합·새 분류 규칙으로 **정확히 어디를 바꿔야 하는지** 단계별로 짚는다. 이 엔진은 **G(제너릭 골격) / S(도메인 내용)가 이미 함수 경계로 분리**돼 있어, 바꿀 곳은 좁고 명확하다. 레퍼런스 과제는 `problems/marketing/3.voc_classification`(VOC 유형·감성 2축 분류: 6유형 × 3감성).

> 근거: 엔진 계약·재사용 관계는 `engines/classify/README.md`·`references/archetypes.md`(분류 = "텍스트 → 범주 라벨"). 줄 번호는 `engines/classify/build_dataset.py`/`grade.py` 기준. 레퍼런스 입력: `engines/classify/items.example.csv`(33항목, 6유형·3감성·충돌·경계·판별불가 전부 커버).
>
> **불변 철학**(SKILL.md "관통 철학"): 결정성 1급 · 정답=규칙 재적용(의도 라벨 직접 읽기 금지) · 모호함을 규칙으로 결정화(자유판단 금지·우선순위 첫 매치) · 단일 입력 재현. 적응 중 이 중 하나라도 깨지면 그 변경은 폐기한다.
>
> **검증/감사 엔진을 안다면**: 분류 엔진은 audit의 `derive_violations`(테이블→위반) → `derive_labels`(text→라벨), `expected_from_flags`(플래그→의도) → 동명 함수, `cross_check`(derive==expected 자기검증) → **그대로 동형**으로 공유한다. 다른 점: ① 위반 *집합*이 아니라 **유일 라벨**(축마다 1개) ② Set-F1이 아니라 **다클래스 macro-F1 + 혼동행렬** ③ 조인이 아니라 **텍스트 합성**(키워드를 심고 규칙으로 되읽음) ④ Part1/Part2 분리가 없는 **단일 산출**(§4 끝·분리형 N/A).

## 0. 큰 그림 — 한 과제는 코드의 어디까지 건드리나

| 무엇 | 어디 | 바꾸나? |
|---|---|---|
| 경로·결정성·파서·`cross_check` 자기검증·어휘 disjoint 단언·엑셀 스타일·`style_header`·`write_voc`·`build_submission` 골격·`main` 흐름·grade의 `grade_axis`/`fmt_confusion`/`load_sheet`/`score`/`main` | §1 GENERIC | **그대로 둔다** |
| items.csv 시나리오 스키마·규칙북(`TYPE_ORDER`/`TYPE_KEYWORDS`/`SENTI_*`)·텍스트 어구(`TYPE_PHRASES`/`SENTI_PHRASES`/`NEUTRAL_FILLER`/`TEMPLATES`)·정답 도출(`derive_labels`)·의도(`expected_from_flags`)·라벨집합·`load_items` 검증·안내 텍스트·grade의 `TYPE_LABELS`/`SENTI_LABELS`/alias/배점 | §2 DOMAIN-SPECIFIC | **과제마다 바꾼다** |

작업 순서: **§2 체크리스트 ①~⑦을 위에서 아래로** 바꾼 뒤, §3 불변식(`derive` == `expected`, 라벨집합 4곳 동반)으로 누락을 점검하고, §4(채점 프리미티브) 확인, §5(모호함의 결정화) 원칙 점검, §6 워크스루, §7 재생성·자기채점·독립검증 루프로 닫는다.

## 1. 그대로 두는 GENERIC (건드리지 말 것)

아래는 테마가 바뀌어도 **메커니즘이 동일**하다. 값(상수)만 §2에서 갈아끼우고, 함수 몸통은 보존한다.

- **경로 스캐폴드** — `ROOT/DATA/ANS` + `mkdir`(L59–64). `ROOT = parents[2]`라 과제 폴더 위치가 바뀌어도 동작. `CSV_PATH = ANS/"items.csv"`(L62)가 단일 입력. **운영자가 배치하는 원본은 코드가 만들거나 지우지 않는다**(매칭·audit 엔진과 동일 규칙).
- **결정성 2종** — ① `ASSIGN_DATE = date(2026,6,28)`(L66, 참고 상수·채점 미사용, `datetime.now()`/`today()` 금지) ② `random.seed(20260628)`(L67). **값만 §2⑥에서 바꾸고 패턴은 보존.** (어구 선택이 `_seq` 기반 결정적이라 사실상 시드 비의존이지만 계약상 유지 — 매칭의 clear+reseed는 전역 누적상태가 있을 때만 필요하고, 분류는 모든 합성이 지역 리스트라 불필요.)
- **입력 파서** — `s(v)`(L122–123, None/공백 정규화). 모든 CSV 셀에 재사용.
- **`load_items` 골격**(L129–192) — `DictReader`(utf-8-sig) + 빈 행 무시(L141) + **item_id 중복 차단**(L143–144) + fail-loud 검증 루프 + 빈 입력 차단(L190–191). **루프 구조·중복 차단·fail-loud 메커니즘은 G**, 허용 라벨/충돌/경계값과 모순 가드(L153–185)는 S(§2①).
- **`cross_check` 자기검증**(L259–268) — `derive_labels`(text→라벨) == `expected_from_flags`(의도 라벨)를 항목마다 대조, 불일치 시 즉시 `sys.exit`. **이것이 분류 엔진의 fail-loud 핵심**(어휘 누수·우선순위·충돌 설정 오류를 발행 전에 잡음). 두 함수의 내용은 S지만 **대조 메커니즘 자체는 절대 건드리지 않는다**(audit `cross_check`와 동형).
- **`_assert_vocab_disjoint`**(L109–116) — 유형 키워드 ∩ 감성 키워드 = ∅ 단언. **두 축이 서로의 어휘로 오염되면 `derive_labels`가 독립 도출을 못 한다**(예: 유형 키워드에 "최악"이 끼면 감성과 누수). **메커니즘은 G** — `main` 진입 즉시 호출(L358). 두 축 외 다른 축을 더하면(§6) 이 단언도 그 축 쌍으로 확장.
- **`_pick`(L198–199) + `build_text` 골격**(L202–229) — `_pick(lst, seq)`는 `lst[seq % len(lst)]`라 **시드 무관 결정적 선택**. `build_text`의 **슬롯 구조**(경계=판별불가 분기 / 유형 어구 슬롯 + 유형충돌 추가 슬롯 / 감성 어구 슬롯 + 감성충돌 추가 슬롯 / 템플릿 포맷)는 **G**. 채워지는 어구 풀(`TYPE_PHRASES` 등)은 S(§2②).
- **엑셀 스타일·`style_header`·`write_voc`**(L274–301) — `HDR`/`HDRFILL`/`GUIDE` 스타일, 헤더 채색, freeze, 열너비. 그대로. `VOC_COLS=["item_id","text"]`(L278)는 학생 입력 스키마라 구조(라벨 없음 — 학생이 채울 것).
- **`build_submission`의 `answer` 분기 패턴**(L304–351) — `answer=False`면 라벨 빈칸(L348), `True`면 도출 라벨 채움(L345–346). **한 함수로 빈양식·정답을 동시에 찍는** 비대칭 차단 패턴(L381–382). 안내시트(`guide=[...]` L309–330)·`SUBMIT_COLS`(L279)는 S(§2⑤), 분기 패턴·스타일은 G.
- **`main` 파이프라인**(L357–391) — disjoint 단언→로드→텍스트 합성→cross_check→정답 도출(규칙 재적용 L373–377)→엑셀 3개 산출(L380–382)→분포 요약 print. **흐름은 G**(파일명·시트명만 따라옴).
- **`grade.py` 거의 전부** — `norm_str`(L34–37)·`load_sheet`(L78–90)·**`grade_axis` macro-F1+혼동행렬 핵심 루프**(L94–140)·`fmt_confusion`(L143–151)·`main`/CLI/result.json(L169–225). **바꾸는 건 §2⑦의 `TYPE_LABELS`/`SENTI_LABELS`·alias dict·`score` 배점·축 개수뿐**, 채점 프리미티브 몸통은 그대로 쓴다(§4).

## 2. 과제마다 바꾸는 DOMAIN-SPECIFIC (체크리스트 ①~⑦)

순서대로 바꾼다. 각 항목은 **"어느 상수/함수의 어디를 어떻게"** 까지 짚는다.

### ① `items.csv` 헤더 = 시나리오 스키마 (단일 진실 소스)
- **어디**: CSV 1행 헤더 + `load_items`(L139–189)의 `dict(...)` 키 + fail-loud 검증(L147–185).
- **무엇**: 한 항목(행) = **키 + 의도 라벨(축마다 1개) + 함정 노브**. VOC 헤더(L13 docstring · items.example.csv L1):
  `item_id,템플릿,유형,감성,충돌주입,충돌상대,경계케이스`
  - **키** = `item_id`(고유, 중복 금지 L143–144).
  - **표시용 노브** = `템플릿`(T1~T4/auto, 문장 조립 힌트 — **채점·도출과 무관**, 가독성만 L187).
  - **의도 라벨** = `유형`(6클래스 ∈ `TYPE_ORDER`)·`감성`(3클래스 ∈ `SENTI_LABELS`). **충돌 해소 후의 최종 라벨**을 적는다(우선순위 높은 쪽).
  - **충돌 함정 노브** = `충돌주입`(none/유형충돌/감성충돌)·`충돌상대`(유형충돌일 때 함께 심을 하위 우선순위 유형).
  - **경계 함정 노브** = `경계케이스`(none/판별불가/약한신호).
- **어떻게**: 새 테마의 **축 개수·라벨·함정 종류**로 컬럼을 교체한다. `item_id`·`템플릿`은 **구조 컬럼**이라 유지. 의도 라벨 컬럼은 축마다 1개(2축이면 2컬럼). 함정 노브(충돌/경계)는 그대로 재사용 가능(테마 무관 메커니즘).
- **fail-loud 추가**: 새 라벨/노브의 허용값 가드(L153–160)와 **자기모순 가드**를 복제한다. VOC가 강제하는 모순 가드(반드시 새 테마에도 복제):
  - 유형충돌인데 `유형=기타`(키워드 없어 충돌 해소 불가) 차단(L164–165).
  - 충돌상대가 유효 유형이 아니거나 `유형`보다 **우선순위가 높거나 같음** 차단(L166–171) — 규칙이 유형을 못 고르면 무의미.
  - 감성충돌인데 `감성≠부정`(부정>긍정 규칙상 최종은 부정) 차단(L172–173).
  - 판별불가인데 `유형≠기타 or 감성≠중립`(L174–176) / 판별불가에 충돌주입(L177–178) 차단.
  - 약한신호인데 `감성≠중립`(L179–181) / `유형=기타`(L182–183) / 충돌주입(L184–185) 차단.

### ② 규칙북 상수 — `TYPE_ORDER`/`TYPE_KEYWORDS` + `SENTI_NEG`/`SENTI_POS`
- **어디**: `TYPE_ORDER`(L71) · `TYPE_KEYWORDS`(L72–79) · `SENTI_NEG`/`SENTI_POS`(L81–82) · `SENTI_LABELS`(L84).
- **무엇**: **정답의 유일 근거**(자유판단 금지·규칙으로 결정화 §5). `TYPE_ORDER`는 **우선순위 순서**(위에서부터 첫 매치) — 마지막 `기타`는 fallback(키워드 없음). `TYPE_KEYWORDS`는 `{라벨: [키워드…]}`. 감성은 `부정 > 긍정 > 중립`(부정어 우선).
- **어떻게**: 새 테마 라벨로 교체한다(예: 티켓 우선순위면 `["긴급","높음","보통","낮음"]`, 토픽이면 `["가격","품질","배송","UX","기타"]`). 핵심 제약:
  - **`TYPE_ORDER`는 우선순위 = 다중 키워드 충돌 시 첫 매치 라벨**(L239–244). 순서가 곧 규칙이다.
  - **fallback 라벨**(`기타` 자리) 1개 = 키워드 없음. 모든 텍스트가 유일 라벨로 떨어지게 보장.
  - **어휘 disjoint**: 유형 키워드 ∩ 감성 키워드 = ∅(`_assert_vocab_disjoint`가 강제 L109–116). 한 단어가 두 축에 걸치면 안 된다.
  - 키워드는 substring 매치(`kw in text` L242)라 **부분 문자열 누수** 주의(짧은 키워드가 다른 어구에 우연히 포함되지 않게).

### ③ 텍스트 합성 어구 — `TYPE_PHRASES`/`SENTI_PHRASES`/`NEUTRAL_FILLER`/`TEMPLATES`
- **어디**: `TYPE_PHRASES`(L87–98) · `SENTI_PHRASES`(L99–102) · `NEUTRAL_FILLER`(L104–105) · `TEMPLATES`(L106) · `build_text`(L202–229).
- **무엇**: items.csv 의도 라벨을 읽어 **그 라벨의 키워드를 포함한 자연어 어구**를 슬롯에 채운다. **각 어구는 자기 축의 키워드만 포함**(다른 축 키워드 누수 금지 — 그래야 `derive_labels`가 독립 도출). 핵심 규칙:
  - 판별불가: `NEUTRAL_FILLER`만(어떤 키워드도 없음, L207–209).
  - 유형=기타(비판별불가): `NEUTRAL_FILLER`만(유형 키워드 없이 감성/필러, L212–214).
  - 일반: `TYPE_PHRASES[유형]` 어구(L216) + 유형충돌이면 `TYPE_PHRASES[충돌상대]` 추가(L217–219).
  - 감성≠중립이면 `SENTI_PHRASES[감성]` 추가(L222–223) + 감성충돌이면 `SENTI_PHRASES["긍정"]` 추가(L224–226, 부정>긍정 규칙이 부정을 골라야).
  - `TEMPLATES`로 문장 포장(L106·L229: `{body}` 슬롯).
- **어떻게**: 새 테마 라벨마다 `TYPE_PHRASES`에 어구 리스트(각 어구는 그 라벨 키워드 1개+ 포함). **어구의 키워드가 `TYPE_KEYWORDS`에 정확히 등장**해야 `derive_labels`가 되읽는다 — 어구와 키워드를 같이 편집. FP 함정(누수)이 없게 어구를 짧고 명확히. `NEUTRAL_FILLER`는 **모든 키워드를 포함하지 않는** 순수 중립 문장(판별불가·기타용).

### ④ 정답 도출 `derive_labels` + 자기검증 `expected_from_flags`
- **어디**: `derive_labels`(L235–251) · `expected_from_flags`(L254–256). **이 한 쌍이 분류 엔진의 심장**(audit `derive_violations`/`expected_from_flags`와 동형).
- **무엇**:
  - **`derive_labels(text)`**(L235–251): 합성된 text에 **규칙북을 다시 적용**해 (유형, 감성) 도출. 유형 = `TYPE_ORDER` 우선순위 순회하며 **첫 매치**(L239–244, 기타는 skip 후 fallback). 감성 = 부정어 있으면 부정, 없고 긍정어 있으면 긍정, 둘 다 없으면 중립(L245–250). **items.csv 의도 라벨을 직접 읽지 않는다**(L43–45 철학) — 이게 독립검증·결정성의 근거.
  - **`expected_from_flags(c)`**(L254–256): items.csv 의도 라벨 `(유형, 감성)`을 그대로 반환(자기검증/fail-loud 전용).
- **어떻게**: 라벨 축 1개 = 도출 로직 1블록. 유형류(우선순위 첫 매치)는 `TYPE_ORDER` 순회 패턴 복제, 감성류(우선순위 카테고리)는 부정>긍정 패턴 복제. **`derive_labels`와 의도 라벨이 모든 항목에서 일치해야** `cross_check`(L259–268)를 통과 — 불일치 = 생성기 버그 발행 차단. **부등호/우선순위/충돌 해소 방향을 규칙북(§2②)·어구(§2③)·derive 세 곳에서 일관**되게(틀리면 cross_check가 잡는다).

### ⑤ 출력 스키마 `SUBMIT_COLS` + 안내 텍스트
- **어디**: `SUBMIT_COLS`(L279) · `build_submission` 안내(`guide=[...]` L309–330).
- **무엇**: 제출/정답 시트 칸 = `item_id` + 축마다 1칸(VOC: `["item_id","문의유형","감성"]`). 안내시트는 **규칙북을 비개발자에게 명문화**(problem.md 아님 — 여기가 규칙의 단일 거처).
- **어떻게**:
  - `SUBMIT_COLS`를 `["item_id"] + [축1, 축2, …]`로 교체. `build_submission`의 `answers[item_id]` 언패킹(L345)을 축 개수에 맞춤.
  - **안내시트 고정 구성**(반드시 유지·번역):
    - **축별 허용값 명시**(L314–315): "이 N개만".
    - **우선순위 규칙 블록**(L316–322): 각 라벨의 트리거 키워드 + "여러 키워드 동시면 번호 작은(위) 라벨".

    - **★우선순위**(L326): "환불·배송 같이 있으면 환불취소. 부정·긍정 같이 있으면 부정".
    - **★판별불가=기타/중립**(L327): "키워드 하나도 안 걸리면 무리하게 추측 말고 fallback 라벨".
    - **★축 독립**(L328): "유형(무엇을)과 감성(긍/부/중)은 별개 축 — 칭찬이라고 무조건 긍정 아님, 감성어만 본다".
    - **행 순서 무관**(L329, item_id로 대조).

### ⑥ 고정 기준일·시드
- **어디**: `ASSIGN_DATE`(L66) · `random.seed`(L67).
- **무엇/어떻게**: 새 과제도 **고정값**을 둔다(`datetime.now()` 금지). 분류는 날짜 파생 함정이 없어 `ASSIGN_DATE`는 참고 상수(채점 미사용)지만 계약상 유지. 시드는 임의 고정값 1개.

### ⑦ `grade.py` — `TYPE_LABELS`/`SENTI_LABELS` · alias dict · 배점
- **어디**: `TYPE_LABELS`(L28) · `SENTI_LABELS`(L29) · `INVALID`(L30) · `TYPE_ALIAS`(L40–49) · `SENTI_ALIAS`(L50–54) · `norm_type`(L57–63) · `norm_senti`(L66–75) · `score`(L156–166) · `main` 축 배선(L182–191).
- **무엇/어떻게**:
  - **`TYPE_LABELS`/`SENTI_LABELS`**(L28–29): build의 `TYPE_ORDER`/`SENTI_LABELS`와 **같은 집합**(라벨 화이트리스트 — 라벨집합 외 값은 `INVALID` 센티넬로 오답, §3 불변식의 grade 끝).
  - **alias dict**(L40–54): 학생 표기 관용 흡수(`환불`≡`환불취소`, `positive`≡`긍정`, `+`≡`긍정` 등). 새 라벨의 동치 표기를 여기서 처리. `norm_type`/`norm_senti`가 alias→정규라벨→화이트리스트 검사(L57–75), 미해당은 `INVALID`.
  - **배점**(`score` L156–166): 유형 macro-F1 45 / 감성 macro-F1 45 / 무결성 10. 축 개수가 바뀌면 가중치 재분배하되 **차원 분리(축별 macro-F1 + 무결성)는 유지**. 무결성 = `max(0, 10 - (라벨집합외+유령ID)*0.5)`(L159–160).
  - **`main` 축 배선**(L182–191): `A_type`/`A_senti`/`S_type`/`S_senti` 추출 + `grade_axis(...)` 호출이 축마다 1쌍. 축을 더하면 `grade_axis` 호출과 print 블록(L196–214)을 복제.
  - **유령 ID**(L188): 정답에 없는 item_id를 무결성 위반으로 잡음(`valid_ids` 집합 — 구조라 유지).

## 2.5 라벨 축 타입 쿡북 (테마별 복제 패턴)

VOC는 두 타입(우선순위 첫 매치 / 카테고리 우선순위)만 보여줘서, 새 테마에서 자주 막힌다. `TYPE_KEYWORDS`·`derive_labels`·`expected_from_flags`를 **타입별로** 이렇게 복제하라.

| 타입 | 예 | 규칙북 | derive(text→라벨) | expected(의도) | 함정 |
|---|---|---|---|---|---|
| **우선순위 첫 매치** | VOC 문의유형 | `TYPE_ORDER` 순서 = 우선순위 | 순회하며 첫 키워드 매치(L239–244) | `c["유형"]` | 충돌상대가 더 높은 우선순위면 무의미(L166–171) |
| **카테고리 우선순위** | VOC 감성(부정>긍정) | `SENTI_NEG`/`SENTI_POS` | 부정어 먼저 검사, 없으면 긍정, 없으면 중립(L245–250) | `c["감성"]` | 감성충돌은 의도=부정 강제(L172–173) |
| **단일 다클래스(비우선)** | 토픽 분류(상호배타) | 라벨당 키워드, 충돌 없게 disjoint | 첫 매치(우선순위가 곧 tie-break) | `c["토픽"]` | 두 토픽 키워드 동시면 우선순위로 결정 — 순서 명시 필수 |
| **순서형(ordinal)** | 우선순위/평점(긴급>높음>…) | 강도 순 키워드, 강한 것 먼저 | 강한 라벨부터 첫 매치 | `c["우선순위"]` | "긴급+보통" 동시면 긴급(강한 쪽) — 순서가 규칙 |
| **fallback(판별불가)** | 기타/중립 | 키워드 없음 | 아무것도 안 걸림 → fallback(L238 초기값) | `기타`/`중립` | 무리한 추측 금지 — 어구는 `NEUTRAL_FILLER`만 |

**테마 전환에서 실제로 막히는 5함정 — 반드시 점검:**
1. **derive/expected 비대칭** — 한쪽만 고치면 `cross_check`가 막는다(이게 안전장치). 우선순위 순서·키워드를 `TYPE_ORDER`(규칙)·`TYPE_PHRASES`(합성)·`derive_labels`(도출) 세 곳에서 일관되게.
2. **어휘 누수(축 오염)** — 유형 어구가 감성어를 포함하거나 그 반대면 `_assert_vocab_disjoint`(L109–116)가 막는다. 어구는 자기 축 키워드만.
3. **충돌상대 우선순위 역전** — 유형충돌의 충돌상대는 `유형`보다 **낮은 우선순위**여야 규칙이 `유형`을 고른다(L166–171 가드 복제).
4. **fallback 라벨 support=0** — 모든 클래스가 gold에 등장해야 macro-F1 분모가 정상(§7 ④). items.csv 분포에서 fallback(기타)·소수 클래스도 1건 이상 심어라.
5. **substring 우연 매치** — 짧은 키워드(`방법`·`도착`)가 다른 어구에 우연히 포함되면 오도출. 키워드를 충분히 구별되게 잡고 cross_check로 검증.

> 핵심: VOC 골격(`build_text`·`derive_labels`·`cross_check` 구조)은 0줄 수정으로 재사용되지만, **새 라벨 축은 위 패턴으로 규칙북/어구/derive/grade 라벨집합을 명시 복제**해야 한다.

## 3. 정답=규칙북 불변식 (절대 깨지 않게)

> **라벨 1개를 더하거나 바꾸면, 반드시 네 곳을 동반 수정한다. 하나라도 빠지면 채점이 조용히 틀린다.**

| # | 파일·함수 | 무엇을 |
|---|---|---|
| 1 | `items.csv` 헤더 + `load_items`(L139–189) | 의도 라벨/함정 노브 = CSV 컬럼 + 허용값·모순 가드 (§2①) |
| 2 | `build_dataset.py` — **규칙북**(`TYPE_ORDER`/`TYPE_KEYWORDS`/`SENTI_*` L71–84) + **합성**(`TYPE_PHRASES`/`SENTI_PHRASES` L87–106) + **도출**(`derive_labels` L235–251) + **의도**(`expected_from_flags` L254–256) | 라벨 = 규칙 + 어구 + 규칙도출 + 의도 (§2②③④) |
| 3 | `build_dataset.py` — 출력(`SUBMIT_COLS` L279, 안내 L309–330) | 라벨 = 제출 칸 + 규칙 명문화 (§2⑤) |
| 4 | `grade.py` — `TYPE_LABELS`/`SENTI_LABELS`(L28–29) + alias(L40–54) + `score`/`main` 축 배선(L156–191) | 라벨 = 채점 화이트리스트 + 동치 + macro-F1 축 (§2⑦) |

**왜**: 규칙북에 키워드만 더하고 `derive_labels`/어구를 안 맞추면 그 라벨은 정답에 안 잡히거나(변별 0), `derive`만 고치고 `expected_from_flags`(의도 라벨)와 어긋나면 `cross_check`가 막거나(발행 차단) — 더 나쁘게 둘 다 같은 방향으로 틀리면 자기충족 버그가 통과한다(§7 독립검증이 이걸 잡음). `TYPE_LABELS` 화이트리스트를 grade와 안 맞추면 정답 라벨이 `INVALID`로 오인돼 macro-F1이 무너진다. 넷이 한 몸이다.

> **derive ↔ expected 이중 정의가 핵심**(audit 엔진과 공유): 정답은 **규칙 도출(`derive_labels`)과 의도 라벨(`expected_from_flags`)을 따로 정의하고 `cross_check`로 대조**한다 — 이 이중 정의 자체가 "정답이 곧 규칙"을 강제하는 장치다. 의도 라벨을 직접 베껴 정답을 만들면(=`derive`를 건너뛰면) 독립검증·결정성 근거가 무너진다(L43–45).

## 4. 채점 프리미티브 — 다클래스 macro-F1 · 혼동행렬 · 라벨 norm (§1 GENERIC의 심장)

분류 엔진의 채점은 audit/매칭의 **Set-F1이 아니다**. 축마다 유일 라벨이라 **다클래스 분류 지표**를 쓴다. `grade.py`의 이 세 프리미티브는 **그대로 재사용**(§2⑦의 라벨집합·alias·배점만 갈아끼움).

- **`grade_axis`(L94–140) — 다클래스 macro-F1 + 혼동행렬**:
  - 정답 item_id 전체(`item_ids` L107)를 순회하며 gold/sub 라벨을 `norm_fn`으로 정규화(L108–109). gold는 항상 유효, 제출은 빈칸/오타 → `INVALID`.
  - 클래스별 `tp/fp/fn/support/pred` 집계(L116–122) → 클래스별 정밀도·재현율·F1(L125–131).
  - **macro = 클래스별 F1의 단순 평균**, 분모는 **gold에 등장(support>0)하거나 제출된(pred>0) 클래스**(L132–134). **단순 정확도가 아니라 macro라 '다수 클래스로 다 찍기'를 처벌** — 소수 클래스 F1이 0이면 평균이 급락(README L18, grade docstring L17–18).
  - 반환: `{macro_f1, per_class, confusion, invalid_count}`(L135–140).
- **혼동행렬 `confusion`/`fmt_confusion`(L99·L143–151)** — `confusion[gold][pred]` 카운트(행=정답, 열=제출, L99·L117). `fmt_confusion`이 라벨 4자 축약으로 표 출력(L143–151). **어느 클래스를 어디로 틀렸는지** 진단(우선순위 충돌을 학생이 어떻게 오인하는지가 여기 드러남).
- **라벨 norm(L34–75)** — `norm_str`(공백 제거 L34–37) → alias dict(동의어 흡수) → 화이트리스트 검사 → 미해당은 `INVALID`(L30). **빈칸·라벨집합 외 값은 오답**(audit/매칭의 빈칸≠0과 동형: 분류는 빈칸≠유효라벨). `INVALID` 카운트가 무결성 감점(L159).

> **왜 Set-F1이 아닌가**: audit/매칭은 "위반 *집합*"·"추천 *집합*"이라 집합 F1이지만, 분류는 **항목마다 축당 유일 라벨**(상호배타 다클래스)이다. macro-F1 + 혼동행렬이 "클래스 불균형에서 소수 클래스를 무시하는" 단순 정확도의 함정을 막는 정확한 도구다. 이 선택은 분류 아키타입의 정의적 특징이다(README L15).

> **분리형(decouple) N/A**: 2축 분류는 한 시트에 유형·감성을 동시 산출하는 **단일 산출**이라 Part1→Part2 전이 차단이 무의미하다(audit/매칭의 §4 분리형이 여기선 없음). 한 제출 파일(`classification_template.xlsx`, '분류' 시트)에 모든 축을 채운다(README L76). 축이 늘어도 단일 시트·다칸 유지.

## 5. 설계 원칙 — "모호함을 규칙으로 결정화" (분류 아키타입의 존재 이유)

분류는 본질적으로 **"이게 뭐냐"가 모호**해 결정성(자동 채점)과 충돌한다. 사람 라벨러도 의견이 갈린다. 이 엔진은 그 충돌을 **규칙으로 모호함을 죽여** 해소한다 — 이 원칙을 어기면 분류 과제는 결정적으로 채점할 수 없다.

1. **자유 판단 금지 → 규칙북이 유일 근거**. 학생도 정답키도 "느낌"으로 라벨링하지 않는다. `TYPE_KEYWORDS`/`SENTI_*`(L71–84)가 **명시 규칙**이고, 안내시트(L309–330)·INPUT_GUIDE에 그대로 노출된다. 학생은 발명이 아니라 **규칙 적용**만 한다(SKILL 철학).
2. **우선순위 첫 매치로 다중 매치 모호를 제거**. 한 텍스트에 여러 유형 키워드가 걸리면? `TYPE_ORDER` **순서대로 첫 매치**(L239–244)가 유일 라벨을 강제한다. "환불+배송"은 항상 환불취소. 감성은 "부정+긍정"이면 항상 부정(부정>긍정 L245–250). **순서가 곧 결정 규칙** — 모든 텍스트가 유일 라벨로 떨어진다.
3. **판별불가 → fallback(기타/중립), 무리한 추측 금지**. 어떤 키워드도 안 걸리면 추측하지 않고 `기타`·`중립`(L238 초기값·L250). 안내 ★문구(L327)가 "무리하게 추측 말라"를 명시. **억지 라벨링이 FP를 만든다** — 모르면 fallback이 정답.
4. **약한신호 → 축 독립(한 축 신호로 다른 축 추론 금지)**. 유형 키워드만 있고 감성 신호 없으면 감성=중립(L179–181 가드). "칭찬감사라고 무조건 긍정" 아님 — 감성어만 본다(안내 ★L328). `_assert_vocab_disjoint`(L109–116)가 두 축 어휘 분리를 코드로 강제.
5. **충돌 케이스를 의도적으로 심어 규칙 적용력을 변별**. `충돌주입`(유형충돌/감성충돌)이 **규칙이 없으면 틀릴** 함정을 모집단에 심는다 — 규칙을 정확히 적용하는 학생만 통과. 이게 "규칙 적용 역량"을 측정하는 장치(매칭의 경계회원·audit의 FP함정과 동형).

> 한 줄 요약: **모호한 분류를 결정적으로 채점하려면, 정답을 "사람의 판단"이 아니라 "공개된 우선순위 규칙북의 기계적 재적용"으로 정의**해야 한다(`derive_labels`). 학생·정답키·채점이 모두 같은 규칙을 본다 → 결정성·독립검증·공정성이 동시에 성립한다.

## 6. 새 분류 테마로 적응 — 워크스루 2종

### 워크스루 A — 지원 티켓 우선순위 분류 (`CS-L1-X`, 단일 축 · 순서형)
"고객 티켓을 긴급/높음/보통/낮음으로 분류". 단일 축(`우선순위`), 순서형(강도 순).

- **① items.csv**: `item_id,템플릿,우선순위,충돌주입,충돌상대,경계케이스` — 감성 컬럼 제거(단일 축), 충돌/경계 노브는 재사용.
- **② 규칙북**: `TYPE_ORDER = ["긴급","높음","보통","낮음"]`(강도 순 = 우선순위). `TYPE_KEYWORDS = {긴급:[장애,먹통,결제 안,접속 불가], 높음:[지연,오류,느림], 보통:[문의,확인 요청], 낮음:[건의,제안]}`. 감성 축 제거(`SENTI_*`·disjoint 단언을 단일 축으로 축소).
- **③ 어구**: `TYPE_PHRASES`를 티켓 자연어로(각 어구는 그 우선순위 키워드만). 감성 어구 슬롯 제거(build_text의 L221–226 블록 삭제).
- **④ derive/expected**: `derive_labels`를 단일 라벨 반환으로(유형 첫 매치만, 감성 블록 제거). `expected_from_flags`는 `c["우선순위"]` 단일.
- **⑤ 출력**: `SUBMIT_COLS = ["item_id","우선순위"]`. 안내에 "긴급+지연 같이 있으면 긴급(강한 쪽)".
- **⑦ grade**: `TYPE_LABELS` 교체, `SENTI_*` 제거, `score`를 단일 축 macro-F1 80 + 무결성 20으로, `main` 축 배선을 1축으로.
- **공유 그대로**: macro-F1·혼동행렬·라벨 norm·무결성·결정성·안내 골격·cross_check.

### 워크스루 B — 리뷰 토픽 × 감성 2축 (`MKT-L2-X`, 2축 · VOC와 동형)
"상품 리뷰를 토픽(가격/품질/배송/UX/기타) × 감성(긍/부/중)으로". **VOC와 구조 동일** — 라벨·키워드·어구만 교체.

- **① items.csv**: `item_id,템플릿,토픽,감성,충돌주입,충돌상대,경계케이스`(VOC와 동형, `유형`→`토픽`).
- **② 규칙북**: `TYPE_ORDER = ["가격","품질","배송","UX","기타"]` + 토픽별 키워드. `SENTI_*`는 VOC 그대로 재사용 가능(도메인 중립).
- **③ 어구**: `TYPE_PHRASES`만 리뷰 토픽 자연어로. `SENTI_PHRASES`/`NEUTRAL_FILLER`/`TEMPLATES` 재사용 가능.
- **④⑤⑦**: 라벨집합만 교체, 구조 0줄 수정(VOC가 그대로 2축 골격).
- **주의**: 토픽 우선순위(가격>품질>…)를 명확히 정하고 충돌상대 가드(L166–171)가 그 순서를 따르는지 확인. fallback(기타) support>0 보장.

> 두 워크스루 모두 **§1 GENERIC은 0줄 수정**(A는 단일 축으로 축소하며 감성 블록만 제거), §2 체크리스트 ①~⑦만 바꾼다. 핵심 불변식(§3): 규칙북·어구·`derive`·grade 라벨집합 네 곳 동반 + `cross_check` 통과 + 독립 재계산 일치.

## 7. 재생성 · 자기채점 · 독립검증 루프 (바꾼 뒤 반드시)

라벨/축을 바꿨으면 아래를 순서대로 돌려 닫는다. 하나라도 실패하면 발행 금지(S10 게이트).

```bash
# 1) 재생성 — items.csv(새 라벨/함정) → voc_데이터 + 양식 + 정답키 산출.
#    _assert_vocab_disjoint + cross_check(derive==expected)가 검사하므로,
#    어휘 누수/우선순위 오류면 여기서 중단된다(1차 자기검증).
python eval/answer_key/build_dataset.py
#   콘솔: 항목 N건 / 유형·감성 분포 / 충돌·경계·판별불가 건수 (자기검증 통과)

# 2) 자기채점 — 정답키로 정답 양식을 채워 채점하면 100점이어야 한다(정합성 2차 확인)
python eval/grade.py \
  --submission eval/answer_key/classification_answer.xlsx \
  --answer-dir eval/answer_key
#   → 총점(100) 100.0 / 유형 macro-F1 100% / 감성 macro-F1 100% 가 아니면
#     TYPE_LABELS↔TYPE_ORDER 불일치(§3-4) 또는 alias/norm 오배정(§2⑦) 의심.

# 3) 독립 재계산 — build_dataset 로직을 '재사용하지 않고' items.csv+규칙북만으로
#    라벨을 다시 도출해 classification_answer.xlsx와 항목 단위 대조. 불일치 = 발행 차단.
python verify/independent_recompute.py         # verify/ 참조
```

- **disjoint 단언이 막으면**(1단계 즉시 중단): 유형 키워드 ∩ 감성 키워드 ≠ ∅(§2②) — 한 단어가 두 축에 걸침. 키워드/어구를 분리.
- **cross_check가 막으면**(1단계 중단): `derive_labels` ↔ 의도 라벨 비대칭(§2④) — 우선순위 순서·키워드 매칭·충돌 해소 중 하나가 규칙북과 derive에서 다르다. text를 콘솔에서 보고 어느 키워드가 누락/누수됐는지 확인(L266–268이 text를 출력).
- **자기채점 100이 안 나오면**: 거의 항상 **§3 불변식 누락**(`TYPE_LABELS` 화이트리스트 불일치, 또는 alias 누락으로 정답 라벨이 `INVALID`, 또는 `score`/`main` 축 배선 누락).
- **자기채점 100인데 독립 재계산이 불일치하면**: 생성·채점 양쪽에 **같은 버그**가 있는 것(예: `derive_labels`와 `expected_from_flags`에 동일한 우선순위 오류 — `cross_check`는 둘이 *서로* 같으면 통과하므로 못 잡는다). **독립 재계산이 이 자기충족 허점을 잡는 게이트**다.
- **macro-F1 분모 점검**: 모든 클래스가 gold에 등장(support>0)하는지 확인(§2.5 함정4) — fallback·소수 클래스가 items.csv에 1건도 없으면 그 클래스가 macro 평균에서 빠져 변별이 안 된다.
- 마지막으로 `verify/adversarial_prompts.md`로 적대 리뷰(다중 키워드를 우선순위로 풀었나? 판별불가를 억지 라벨링했나? 한 축으로 다른 축을 추론했나? 어휘 누수? fallback support=0? seed 누락?)를 돌리고, `references/checklist.md` G1~G10 발행 게이트를 통과시킨다.
