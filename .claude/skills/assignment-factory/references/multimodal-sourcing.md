# multimodal-sourcing — 멀티모달 입력(포스터·공문) 소싱 가이드 (운영자 배치)

이 스킬이 만드는 매칭 과제는 학생이 **실제 정책 포스터/공문(PDF·이미지)** 을 읽어 자격요건을
추출하는 **멀티모달 과제**다. 이 문서는 그 멀티모달 파일을 **무엇을·어디서·어떤 검색어로** 가져와
**어떻게 배치/검증**하는지를 출제자(운영자)에게 구체적으로 안내한다.

> 검증된 사례: `problems/marketing/1.youth_policy/`. 그 과제의 `eval/answer_key/policies.csv`
> `poster_file` 컬럼 9개 값이 `data/policies/`의 실제 파일명과 1:1로 맞춰져 있다.
> 이 문서의 모든 절차는 그 사례를 일반화한 것이다. (`<source>` = 그 과제의 입력 엔티티 폴더명.
> youth_policy에서는 `policies`.)

---

## 0. 대원칙 — 멀티모달 파일은 코드가 만들지 않는다 (환각 금지)

- ⭐ **포스터/공문 등 실제 멀티모달 파일은 `build_dataset.py`가 생성하지 않는다.** 운영자가
  실제 출처에서 받아 `data/<source>/`에 **직접(수동) 배치**한다. 코드가 그럴듯한 포스터를
  지어내면 **자격 수치가 환각**돼 결정성이 깨진다 — 절대 금지.
- ⭐ **`poster_file` 컬럼 값 = `data/<source>/`의 실제 파일명과 글자 그대로 정확히 일치**해야
  한다(확장자·공백·괄호·한글·특수문자 포함). 불일치하면 학생이 그 포스터를 찾지 못한다.
- **빌드는 이 파일을 만들지도 읽지도 않는다.** `poster_file`이 비어 있어도 데이터 생성·채점은
  동작한다. 그러나 포스터는 **학생의 유일한 입력 소스**이므로(자격을 여기서 읽어낸다) 발행
  과제에는 **반드시** 실제 파일이 있어야 한다 — 빌드가 통과한다고 "완료"가 아니다.
- 즉 책임 분리: **csv = 채점 기준값(정답)** / **포스터 = 학생이 읽을 실제 입력**. 둘은 같은
  자격을 담되, csv는 코드가 쓰고 포스터는 사람이 배치한다.

## 1. 소싱 절차 체크리스트 (정책/엔티티 1건당)

CSV의 행(엔티티) 하나마다 아래를 순서대로 수행한다. 한 건이라도 빠지면 그 행은 발행 불가.

1. **무엇이 포스터에 보여야 하는지 먼저 적는다.** 해당 행에서 **빈칸이 아닌 자격 축**을 모은다.
   예: `YP05 중랑구 자격증 응시료` → `region=서울특별시 중랑구`, `age 19~39`, `employment=미취업`.
   → "이 세 자격이 한 장에서 읽혀야 한다"가 그 행의 **소싱 목표**다.
2. **실제 출처에서 1~2페이지 홍보물을 우선 확보한다.** 우선순위:
   **① 1장짜리 홍보 포스터(JPG/PNG) → ② 카드뉴스 1~2컷 → ③ 모집 공고문 PDF(1~2p)**.
   ❌ **긴 공고문·사업 안내 책자(3페이지 이상)는 지양**한다 — 학생의 추출 부담이 과해지고
   자격이 여러 장에 흩어져 OCR/판독 난이도가 채점 의도와 무관하게 폭발한다.
3. **자격이 "한 장 안에" 다 보이는지 확인한다.** 1번에서 적은 자격 축이 한 이미지/한 페이지에
   모두 명시돼 있어야 한다. 흩어져 있으면 → 더 압축된 홍보물(포스터/카드뉴스)로 교체하거나,
   자격이 다 보이는 그 한 페이지만 잘라 1p로 만든다.
4. **`poster_file` 이름과 일치시켜 배치한다.** 파일을 `data/<source>/`에 넣고, 파일명을 CSV
   `poster_file` 값과 **정확히** 맞춘다(또는 CSV 값을 실제 파일명으로 맞춘다). 한쪽을 기준으로
   양쪽을 통일한다. 가능하면 `YP01_청년수당.png`처럼 **`<policy_id>_<짧은이름>.<ext>`** 규칙이
   관리에 편하지만, youth_policy처럼 출처 원본 파일명을 그대로 써도 무방하다 — **일치만이 규칙**.
5. **가독성(OCR 가능) 확인.** 자격 수치(나이·소득·지역 등)가 사람 눈에 또렷이 읽혀야 한다.
   저해상도·과한 압축·워터마크로 가려진 이미지는 교체한다(§4 검증).

## 2. 검색 쿼리 가이드 (도메인별 템플릿)

youth_policy에서 실제로 통한 패턴을 일반화한 템플릿이다. `<...>`를 도메인 값으로 치환해 쓴다.
**공식 도메인(go.kr·기관 포털) 우선 / 1~2p 포스터·카드뉴스 우선 / 책자 지양**이 전 템플릿 공통.

### 2.1 범용 템플릿 (어느 도메인이나)

| 의도 | 쿼리 템플릿 | 예 |
|---|---|---|
| 포스터 직격 | `<정책명> 모집 공고 포스터` | `서울시 청년수당 모집 공고 포스터` |
| 자격 안내 이미지 | `<정책명> 신청 자격 안내 jpg` | `청년미래적금 신청 자격 안내 jpg` |
| 기관+사업 | `<기관> <사업명> 홍보 포스터` | `서울시 희망두배 청년통장 홍보 포스터` |
| 공식도메인 한정 PDF | `site:<공식도메인> <사업명> 공고문 pdf` | `site:youth.seoul.go.kr 청년수당 공고문 pdf` |
| 카드뉴스 | `<주제> 카드뉴스` | `중소기업 취업청년 소득세 감면 카드뉴스` |
| 이미지 검색 보강 | `<정책명> 포스터` 를 **이미지 검색 탭**에서 + 큰 해상도 필터 | — |

### 2.2 공식 도메인 우선순위 (한국 공공정책 예)

- 정부24 / 부처 `*.go.kr`, 지자체 `*.seoul.go.kr`·`*.gg.go.kr` 등, 공공기관 포털.
- 사업 전용 포털(예: 청년정책은 `youth.seoul.go.kr`, `2030.seoul.go.kr`, `온라인청년센터`).
- ❌ 블로그·언론 캡처·중고 재배포본은 **자격 수치가 옛 회차일 수 있어** 출처로 부적합 →
  반드시 공식 원본의 최신 회차로 교차 확인(§5 주의).

### 2.3 도메인 전이 시 (youth_policy → 다른 테마)

테마가 바뀌면 `<정책명>` 자리에 그 도메인의 엔티티를 넣고, "모집 공고/신청 자격/홍보/카드뉴스"
키워드는 그대로 재사용한다. 예: 채용 도메인 → `<공고명> 채용 공고 이미지`,
복지 도메인 → `<사업명> 지원 대상 안내 포스터`, 교육 도메인 → `<과정명> 모집 요강 카드뉴스`.

## 3. 받아도 되는 파일 형식

- **직접 다운로드되는** 다음만 사용한다:
  - **PDF** — 텍스트 추출 가능(스캔 이미지 PDF가 아닌, 실제 텍스트 레이어가 있는) 1~2p.
  - **PNG / JPG** — 자격 수치가 또렷이 읽히는 가독 이미지.
- ❌ 웹페이지 링크(HTML), 로그인/뷰어 안에서만 보이는 파일, hwp/한글 전용 포맷은 그대로 쓰지
  않는다 → 화면을 1p 포스터 이미지로 캡처하거나 PDF로 내보내 가독 파일로 변환한 뒤 배치.
- 스캔 이미지 PDF(텍스트 레이어 없음)는 **가독 이미지로 충분하면** 허용한다 — 학생은 결국
  눈/OCR로 읽기 때문. 단 해상도·선명도가 §4 기준을 넘어야 한다.

## 4. 다운로드 검증법 (youth_policy 방식)

배치 직후 파일마다 짧게 검증한다. 깨진 링크·HTML 오류페이지·0바이트 파일을 걸러낸다.

```bash
# (1) 실제 무슨 파일인지 — content-type 확인 (HTML 오류페이지/리다이렉트 적발)
curl -sIL "<URL>" | grep -i content-type
#   → application/pdf | image/png | image/jpeg 가 나와야 정상.
#     text/html 이면 그건 파일이 아니라 웹페이지다 → 다시 받는다.

# (2) 받은 파일 형식·크기 로컬 확인
file   data/<source>/<poster_file>      # PDF document / PNG image / JPEG image 인지
ls -lh data/<source>/<poster_file>      # 수십 KB 미만이면 깨졌을 가능성 — 열어 확인

# (3) PDF 페이지 수 확인 (3p 이상이면 지양 — §1-2)
pdfinfo data/<source>/<poster_file> | grep -i pages     # poppler-utils
#   대안: python3 -c "import pypdf,sys; print(len(pypdf.PdfReader(sys.argv[1]).pages))" <file>

# (4) PDF 텍스트 추출 가능 여부(권장) — 비면 스캔본 → 이미지 가독성으로 판단
pdftotext data/<source>/<poster_file> - | head
```

마지막으로 **사람이 직접 열어** 1번에서 적은 자격 축이 한 화면에서 또렷이 읽히는지 눈으로
확인한다(자동 검증으로 대체 불가 — 가독성은 최종적으로 사람이 판정).

## 5. 함정 설계와의 연결 (난이도 ↔ 결정성 분리)

이 과제의 함정·변별력은 **회원 데이터(생성기)** 에서 만들고, 포스터는 **'진짜 자격을 담은
입력'일 뿐**이다. 이 분리를 흐리지 말 것.

- **자격 경계값·표기 불일치 함정 = 회원 측**: 나이 경계(만 34세 0일/만 35세), 소득 경계,
  지역 자치구 한정 등 함정 회원은 `build_dataset.py`가 csv 자격 기준으로 심는다. 포스터는
  단지 그 기준값을 사람이 읽도록 보여줄 뿐 함정을 추가하지 않는다.
- **포스터에 없는 자격은 csv에서 비운다**(빈칸 = 무관). 포스터에 명시되지 않은 축을 csv에
  채우면, 학생이 포스터만으로는 도출할 수 없는 정답이 되어 결정성이 깨진다. **포스터 ↔ csv의
  비어있지-않은 자격 축은 일치**해야 한다(포스터가 자격의 단일 출처).
- **멀티모달 OCR 자체가 '난이도'다.** 흐릿한 표·이미지에서 수치를 읽어내는 것은 학생 역량
  측정 대상이지만, **채점은 OCR 결과가 아니라 csv 기준값과 학생 제출 셀을 대조**한다(`grade.py`).
  즉 **난이도(읽기 어려움)와 결정성(정답은 csv가 유일 정의)을 분리**한다 — 포스터가 좀 흐려도
  정답은 흔들리지 않고, 학생의 추출 정확도만 점수에 반영된다.
- **`matchable=N` 정책의 포스터**: 회원 명단으로 판별 불가한 정책(가구중위소득·자녀 수 등)도
  포스터는 배치하되, csv에서 판별 불가 자격 칸은 **빈칸**으로 둔다(INPUT_GUIDE §matchable).
  학생이 "데이터로 확인 불가 → 추천 0건"이라는 현업적 신중함을 판단하게 하는 입력이다.

## 6. 저작권·실데이터 주의

- **공공기관 공식 홍보물 위주**로 받는다(정부·지자체·공공기관 발행 포스터/공고). 출처가
  명확한 공적 자료를 우선하고, 상업 이미지·개인 제작물·재배포 캡처는 피한다.
- **개인정보가 없는 자료**만 사용한다(담당자 연락처·실명·서명 이미지 등이 박힌 내부 문서 금지).
- ⭐ **실제 자격 수치는 사람이 재확인한다.** 이 스킬·검색은 자격값의 정확성을 보장하지 않는다.
  포스터를 받은 뒤 **최신 회차 공식 원본**과 나이·소득·지역·기간 수치를 교차 확인하고, 그
  확인된 값으로 csv를 채운다(옛 회차/언론 캡처의 낡은 수치 주의).
- 외부 배포가 목적이라면 각 기관의 홍보물 이용 약관을 확인한다. 내부 평가용이라도 출처 메모를
  남겨 두면(파일명 또는 별도 메모) 후속 검증이 쉽다.

## 7. 발행 전 빠른 점검 (이 문서 기준 게이트)

`references/checklist.md` 발행 게이트와 함께, 멀티모달 측면은 아래를 모두 만족해야 발행한다.

- [ ] `poster_file`이 비어있지 않은 모든 행에 `data/<source>/`의 **실제 파일이 존재**한다.
- [ ] 파일명이 `poster_file` 값과 **글자 그대로 일치**한다(공백·괄호·확장자 포함).
- [ ] 각 파일이 **1~2페이지** 포스터/카드뉴스/공고이고, **3p 이상 책자가 아니다**.
- [ ] 각 행의 **비어있지-않은 자격 축이 그 포스터 한 장에서 모두 읽힌다**(사람 눈 확인).
- [ ] 포스터 ↔ csv의 자격이 **일치**한다(포스터에 없는 자격은 csv에서 비움).
- [ ] 모든 파일이 가독 가능(`curl` content-type / `file` / 사람 판독)하다.
- [ ] 자격 수치를 **최신 공식 원본과 교차 확인**했고 개인정보가 없다.
