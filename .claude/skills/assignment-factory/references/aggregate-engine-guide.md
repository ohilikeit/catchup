# 집계/분석 엔진 적응 가이드 (S5~S7) — `engines/aggregate/`을 새 집계 테마로 바꾸기

**목적**: 검증된 집계/분석 엔진(`engines/aggregate/build_dataset.py` 471줄 · `grade.py` 230줄)을 새 로그·새 집계 지표로 **정확히 어디를 바꿔야 하는지** 단계별로 짚는다. 이 엔진은 **G(제너릭 골격) / S(도메인 내용)가 이미 함수 경계로 분리**돼 있어, 바꿀 곳은 좁고 명확하다. 레퍼런스 과제는 `problems/marketing/2.email_campaign_metrics`(이메일 캠페인 성과 집계: 발송로그 → 캠페인별 성과표 + 전사 요약 1행).

> 근거: 엔진 계약은 `references/archetypes.md` §6, 미지원→지원 전환 근거는 §5(집계는 매칭의 `member_passes`·검증의 `derive_violations`처럼 "불리언→집합"이 아니라 **GROUP BY 합산**, 채점은 집합 F1이 아니라 **수치 ±ε**). 줄 번호는 `engines/aggregate/build_dataset.py`/`grade.py` 기준. 레퍼런스 입력: `engines/aggregate/spec.example.csv`(40캠페인, 분모0·반올림경계·가중함정 전부 커버).
>
> **불변 철학**(SKILL.md "관통 철학"): 결정성 1급 · 정답=로그 재집계(spec 숫자 직접 베끼기 금지) · 빈 셀 ≠ 0 · 단일 입력 재현. 적응 중 이 중 하나라도 깨지면 그 변경은 폐기한다.
>
> **매칭·검증 엔진을 안다면**: 집계 엔진은 매칭의 `member_passes`(축별 AND 필터) / 검증의 `derive_violations`(규칙 재적용) → **`regroup_metrics`(발송로그 GROUP BY 합산)**, 매칭의 `plant_boundaries`(경계 회원 심기) / 검증의 `cases.csv`(운영자 결함 명세) → **`spec.csv` 노브(분모0·반올림경계·퍼널 카운트)**, **집합 F1 채점(`grade_part2`)** → **셀 단위 Computed ±ε(`float_eq`)**로 치환된다. **무결성 센티넬·`cross_check` 자기검증·안내시트 골격·결정성·빈칸≠0 `norm_int`·엑셀 스타일·분리형은 그대로 공유**한다. 가장 큰 차이는 **채점 프리미티브(§4)** — 집합이 아니라 수치 허용오차다.

## 0. 큰 그림 — 한 과제는 코드의 어디까지 건드리나

| 무엇 | 어디 | 바꾸나? |
|---|---|---|
| 경로·결정성·파서·반올림 프리미티브·`cross_check` 자기검증·엑셀 스타일·`write_table`·`build_metrics`/`build_summary` 골격·`main` 흐름·grade 거의 전부 | §1 GENERIC | **그대로 둔다** |
| spec.csv 시나리오 스키마·결함 노브(분모0/반올림경계/퍼널)·로그 합성(`build_log`)·집계 규칙(`regroup_metrics`/`summarize`)·자기검증 의도(`cross_check`)·집계 칸(`P1_COLS`/`SUM_COLS`)·grade의 INT/FLOAT 필드·`FLOAT_TOL`·배점 | §2 DOMAIN-SPECIFIC | **과제마다 바꾼다** |

작업 순서: **§2 체크리스트 ①~⑦을 위에서 아래로** 바꾼 뒤, §3 불변식(`regroup` == `spec` via `cross_check`, 칸↔채점필드 1:1)으로 누락을 점검하고, §4 채점 프리미티브로 지표 타입↔norm을 맞추고, §5 새 테마 적응을 따라가, §6 재생성·자기채점·독립검증 루프로 닫는다.

## 1. 그대로 두는 GENERIC (건드리지 말 것)

아래는 테마가 바뀌어도 **메커니즘이 동일**하다. 값(상수)만 §2에서 갈아끼우고, 함수 몸통은 보존한다.

- **경로 스캐폴드** — `ROOT/DATA/ANS/CSV_PATH` + `mkdir`(L57–62). `ROOT = parents[2]`라 과제 폴더 위치가 바뀌어도 동작. **운영자 배치 원본(`data/`의 포스터 등)은 코드가 만들거나 지우지 않는다**(매칭·검증 엔진과 동일 규칙).
- **결정성 2종** — ① `ASSIGN_DATE = date(2026,6,28)`(L64, 발송일 합성용 기준일 상수, **채점엔 미사용**, `datetime.now()`/`today()` 금지) ② `random.seed(20260628)`(L65). **값(날짜·시드)만 §2⑥에서 바꾸고 패턴은 보존.** (매칭의 clear+reseed는 전역 누적 상태가 있을 때만 필요 — 집계 엔진은 모든 합성이 `build_log`의 지역 리스트라 불필요.)
- **입력 파서** — `int_or_none`(L79–85, 빈칸→None·콤마/공백 제거 정수)·`yn`(L88–90, Y/N 정규화·빈칸→default). 모든 수치/플래그 열에 재사용.
- **★반올림 프리미티브**(L94–116) — `rate1`(율 = num/den×100, 소수 첫째 자리 round-half-up, den==0→0.0, L94–99)·`arpu1`(평균 = rev/den, 동일 반올림, L102–107)·`lands_on_boundary`(X.X5 반올림 경계 판정, L110–116). **이 3함수가 집계 엔진의 채점 결정성을 떠받친다** — `Decimal` + `ROUND_HALF_UP`으로 부동소수 비결정성을 제거한다(§4). **반올림 자릿수/규칙이 바뀌지 않는 한 그대로**, 새 지표는 이 함수를 재사용한다.
- **`load_spec` 골격**(L122–187) — `DictReader`(utf-8-sig) + 빈 행 무시(L135–136) + **캠페인 키 중복 차단**(L139–141) + fail-loud 검증 루프. **루프 구조·중복 차단·fail-loud 메커니즘은 G**, 컬럼 스키마·허용값·일관성 가드(퍼널 단조성 L156–159, zero_denom 일관성 L161–170, 매출↔전환 일관성 L172–176)는 S(§2①).
- **`cross_check` 자기검증**(L282–304) — ① `regroup_metrics`(로그 재집계) == spec 숫자(L285–290, 합성 무결성) ② 발송>0 캠페인이 로그에 실재(L292–294) ③ `round_boundary=Y`면 실제로 어떤 율이 X.X5 경계에 옴(L296–304, 트랩 실재성). **이것이 집계 엔진의 fail-loud 핵심**(합성/입력 모순을 발행 전에 잡음). 검사 내용은 S지만 **대조 메커니즘 자체는 절대 건드리지 않는다** — 검증 엔진의 `cross_check`(derive==expected)와 동형이다.
- **엑셀 스타일·`style_header`·`write_table`**(L310–334) — `HDR`/`HDRFILL`/`GUIDE` 스타일, 헤더 채색, freeze, `LOG_COLS`. 그대로.
- **`metric_row`의 `answer` 분기 패턴**(L337–342) — `answer=False`면 식별칸(`campaign_id`)만, `True`면 지표 채움. **한 함수로 빈양식·정답·given을 동시에 찍는** 비대칭 차단 패턴(L451–454). 칸 내용은 S, 분기 패턴은 G.
- **`build_metrics`/`build_summary` 골격**(L345–380 / L383–417) — '안내' 시트(항목/설명 2열) + 데이터 시트 + 스타일·freeze. **골격은 G**, 안내 텍스트(`guide=[...]` L349–364 / L387–398)·컬럼 리스트는 S(§2⑤).
- **`main` 파이프라인**(L423–467) — load→`build_log`→`regroup_metrics`→`cross_check`→`summarize`→발송0 보충(L442–450)→엑셀 산출(template/answer/given L451–454, summary L456–458)→요약 print. **흐름은 G**(파일명·시트명만 따라옴). **발송0 빈 캠페인 보충 로직(L442–450: 로그 행이 없으니 0/0.0으로 채워 집계표엔 등장)은 분모0 처리의 G 부분**이라 유지.
- **`grade.py` 거의 전부** — `norm_str/int/float`(L38–63)·`int_eq`/`float_eq`(L66–79)·`load_sheet`(L82–94)·`grade_part1` 키별 셀 Exact+±ε 루프(L102–151)·`grade_part2` 요약 1행(L155–178)·`main`/CLI/result.json(L192–227). **바꾸는 건 §2⑦의 INT/FLOAT 필드 목록·`FLOAT_TOL`·시트명·배점뿐**, 나머지는 채점 엔진으로 그대로 쓴다.

## 2. 과제마다 바꾸는 DOMAIN-SPECIFIC (체크리스트 ①~⑦)

순서대로 바꾼다. 각 항목은 **"어느 상수/함수의 어디를 어떻게"** 까지 짚는다.

### ① `spec.csv` 헤더 = 시나리오 스키마 (단일 진실 소스)
- **어디**: CSV 1행 헤더 + `load_spec`(L132–184)의 `dict(...)` 키 + fail-loud 검증(L137–178).
- **무엇**: 한 행 = **그룹 키 + 그 그룹의 집계 입력 수치 + 결함 노브**. 이메일 캠페인 헤더(L10 docstring):
  `campaign_id,name,발송수,오픈수,클릭수,전환수,매출합계_원,zero_denom,round_boundary`
  - **그룹 키** = `campaign_id`(L133, GROUP BY 단위). 유일해야 함(L139–141).
  - **집계 입력 수치** = `발송수·오픈수·클릭수·전환수·매출합계_원`(로그 합성의 원천이자 자기검증 기준).
  - **결함 노브 1 — 분모0** = `zero_denom`(none|발송0|오픈0, L161–170). 율 계산의 0-나눗셈 트랩.
  - **결함 노브 2 — 반올림 경계** = `round_boundary`(Y/N, L177–178). Y면 어떤 율이 X.X5 경계에 오도록 설계(±ε 트랩 실재).
- **어떻게**: 새 테마의 **그룹 단위·집계 입력·결함 종류**로 컬럼을 교체한다. `campaign_id`·`name`은 **구조 컬럼**이라 유지. 집계 입력 수치는 "퍼널 부분집합"이면 단조성 가드를(L156–159), 합/분배 관계면 일관성 가드를(매출↔전환 L172–176) 새 관계로 복제한다.
- **fail-loud 추가**: 새 노브의 허용값·음수 차단(L151–154)·**자기모순 가드**를 새 결함 조합에 복제한다. "발송0인데 zero_denom≠발송0"(L169–170), "전환0인데 매출≠0"(L173–174) 같은 **무의미한 입력**을 차단해야 `cross_check`가 성립한다.

### ② 로그 합성 `build_log` + 분배 헬퍼 + `LOG_COLS`
- **어디**: `build_log`(L203–228) · `distribute_revenue`(L193–200) · `LOG_COLS`(L313–314).
- **무엇**: spec 수치를 읽어 **raw 로그(1행=1이벤트)**를 합성한다. 정답은 이 로그를 *다시 그룹바이*해서 나오므로(§3), 로그가 spec 수치를 정확히 재현해야 한다.
  - 퍼널 부분집합: 앞쪽 `conv`행=전환⊆클릭⊆오픈⊆발송(L210–217). 행 인덱스로 Y/N 결정.
  - 금액 분배: `distribute_revenue`(L193–200)가 매출합계를 전환 행에 분배(몫 깔고 나머지 앞에서 +1) → **합 = 매출합계** 보존.
  - 날짜 합성: `발송일 = ASSIGN_DATE - timedelta(day_jitter)`(L212·L218, 결정적, 채점 미사용).
- **어떻게**: 새 로그의 컬럼·이벤트 구조로 교체한다. **`build_log`의 출력 튜플이 `regroup_metrics`의 입력**이므로, 집계에 필요한 모든 플래그/수치를 행에 담는다. `LOG_COLS`를 새 로그 헤더로 바꾸고, 합/분배가 보존돼야 하는 수치는 `distribute_revenue` 패턴으로 분배한다.

### ③ 집계 규칙 `regroup_metrics` + 전사 요약 `summarize`
- **어디**: `regroup_metrics`(L234–263) · `summarize`(L266–276). **이 한 쌍이 집계 엔진의 심장 — 정답의 단일 출처**.
- **무엇**:
  - **`regroup_metrics(log_rows)`**(L234–263): 로그를 그룹 키로 묶어 **건수/합계를 카운트**(L243–250)하고 **율·평균을 반올림 프리미티브로 도출**(L258–261: `rate1`/`arpu1`). **spec 숫자를 직접 베끼지 않는다**(L36 철학) — 이게 독립검증·결정성의 근거.
  - **`summarize(order, metrics)`**(L266–276): 전사 1행. **★가중 지표**가 핵심 — `전체전환율 = 총전환/총발송`(L275, *캠페인 전환율의 단순평균이 아님*), `전체ARPU = 총매출/총발송`. 합계는 캠페인 합계의 합(L269–272).
- **어떻게**: 지표 1개 = `regroup_metrics`에 **1줄**(건수면 카운트 분기 L244–249, 율이면 `rate1(분자, 분모)`, 평균이면 `arpu1`). **새 가중 지표는 반드시 `summarize`에서 "총분자/총분모"로 재계산**(개별 행 지표의 평균이 아님 — §4 가중평균 함정). 분모가 0일 수 있으면 `rate1`/`arpu1`이 0.0을 반환하므로(L95·L103) 별도 분기 불필요.

### ④ 자기검증 `cross_check` (트랩 실재성)
- **어디**: `cross_check`(L282–304).
- **무엇**: ① 로그 재집계 == spec(L285–290) ② 발송>0 로그 실재(L292–294) ③ `round_boundary=Y` → 실제 X.X5 경계 도달(L296–304, `lands_on_boundary`). **검증 엔진의 derive==expected 대조와 동형** — 합성·입력·트랩이 모두 의도대로인지 발행 전에 확인.
- **어떻게**: 새 집계 입력마다 ①에 일치 검사 필드를 추가(L288 루프 필드 목록). 새 결함 노브가 **트랩의 실재**를 보장해야 하면(반올림 경계처럼) ③ 패턴을 복제한다 — "노브=Y인데 실제 트랩이 데이터에 없으면 `sys.exit`". 이게 빠지면 spec에 Y를 적어도 트랩이 안 심겨 변별이 0이 된다.

### ⑤ 출력 칸 `P1_COLS`/`SUM_COLS`/`metric_row` + 안내 텍스트
- **어디**: `P1_COLS`(L71–72) · `SUM_COLS`(L73) · `metric_row`(L337–342) · `build_metrics` 안내(L349–364) · `build_summary` 안내(L387–398).
- **무엇**: Part1(캠페인별 집계표) 칸 = 그룹별 지표. Part2(전사 요약) 칸 = 가중/합계 지표 1행.
- **어떻게**:
  - `P1_COLS`/`SUM_COLS`를 새 지표 칸으로 교체하고, `metric_row`의 `answer=True` 분기를 새 칸 순서에 맞춘다(L341–342). `answer=False` 식별칸 외 빈칸 수(L340)를 새 칸 수에 맞춰 조정.
  - **안내시트 고정 문구 4종**(반드시 유지 — 판정·계산 규칙은 안내시트에 산다, problem.md 아님):
    - **반올림 규칙**(L360): "소수 첫째 자리 round-half-up. 0.5는 올린다(33.25→33.3). 채점 허용오차 ±0.1".
    - **분모 0 규칙**(L361): "발송수=0 캠페인은 모든 율=0.0, ARPU=0 (0으로 나누지 않음)".
    - **건수·합계는 정수 정확**(L362): "허용오차 없음".
    - **★가중평균 함정**(L393·L397): "전체전환율은 총전환/총발송(가중) — 캠페인 전환율들의 단순평균으로 내면 오답".

### ⑥ 고정 기준일·시드
- **어디**: `ASSIGN_DATE`(L64) · `random.seed`(L65).
- **무엇/어떻게**: 새 과제도 **고정값**을 둔다(`datetime.now()` 금지). 날짜가 채점 지표면(예: 일자별 집계) `ASSIGN_DATE`를 기준일로 역산해 로그 날짜를 심는다(매칭 가이드 §2.5 날짜 파생 스니펫과 동형). 시드는 임의 고정값 1개. **집계 엔진은 날짜를 기본적으로 "채점 미사용 합성용"으로 둔다**(L41) — 날짜가 지표가 되면 그 가정을 깬다는 점을 명시.

### ⑦ `grade.py` — INT/FLOAT 필드 · `FLOAT_TOL` · 시트명 · 배점
- **어디**: `P1_INT_FIELDS`/`P1_FLOAT_FIELDS`(L30–31) · `SUM_INT_FIELDS`/`SUM_FLOAT_FIELDS`(L32–33) · `FLOAT_TOL`(L34) · 시트명(L200–203) · `score`(L183–189).
- **무엇/어떻게**:
  - **INT vs FLOAT 분류**(L30–33): **§2⑤ 출력 칸을 지표 타입대로 두 묶음으로 나눈다** — 합계·건수는 `*_INT_FIELDS`(정수 Exact, `int_eq`), 율·평균은 `*_FLOAT_FIELDS`(Computed ±ε, `float_eq`). **이 분류가 §3 불변식의 grade 쪽 끝**이다. INT 칸을 FLOAT로 넣으면 트랩 변별이 죽고, FLOAT 칸을 INT로 넣으면 정답도 오답 처리된다(§4).
  - **`FLOAT_TOL`**(L34): 허용오차(기본 0.1). 반올림 자릿수가 바뀌면 같이 조정(소수 둘째 자리면 0.01 등). **반올림 경계(X.X5) 트랩이 동작하려면 tol < 반올림 단위**여야 한다(§4).
  - **시트명**(L200–203): `"집계표"`/`"전체요약"`을 `build_metrics`/`build_summary`의 시트명과 일치시킨다.
  - **배점**(`score` L183–189): Part1 집계표 55 / Part2 요약 35 / 무결성 10(집계가 핵심이라 Part1 비중이 큼). 비율은 과제 가중치에 맞게 조정하되 **차원 분리(정확도/형식/무결성)는 유지**.
  - **무결성**: 유령 캠페인(정답에 없는 키, L129–130)·제출 행의 퍼널 단조성 위반(L131–143)을 FP로 감점(L186 `viol*0.5`). `valid` 키 집합(L129)은 구조라 유지 — 새 테마의 무결성 규칙(예: 합계>0인데 율이 음수)으로 교체 가능.

## 2.5 집계 지표 타입 쿡북 (테마별 복제 패턴)

이메일 캠페인은 일부 타입만 보여줘서, 새 테마(주문 집계·트래픽 집계 등)에서 자주 막힌다. `regroup_metrics`·`summarize`·`build_log`·grade 필드를 **타입별로** 이렇게 복제하라.

| 타입 | 예 | build_log 합성 | regroup(로그→지표) | grade 필드 | 채점 |
|---|---|---|---|---|---|
| 건수(count) | 발송수·오픈수 | 행/플래그로 생성 | 행 수 / `Y` 행 수 카운트 | `*_INT_FIELDS` | 정수 Exact |
| 합계(sum) | 매출합계 | 분배(`distribute_revenue`) | 금액 누적 합 | `*_INT_FIELDS` | 정수 Exact |
| 율(rate %) | 오픈율=오픈/발송 | — (count에서 파생) | `rate1(분자, 분모)` | `*_FLOAT_FIELDS` | **±ε(tol=0.1)** |
| 평균(mean) | ARPU=매출/발송 | — | `arpu1(합, 분모)` | `*_FLOAT_FIELDS` | **±ε** |
| **★가중 전사(weighted)** | 전체전환율=총전환/총발송 | — | `summarize`에서 총분자/총분모 | `SUM_FLOAT_FIELDS` | **±ε** |
| **분모0(zero-denom)** | 발송0/오픈0 | spec 노브 | `rate1`/`arpu1`이 0.0 반환 | INT는 0, FLOAT는 0.0 | Exact/±ε |
| **반올림 경계(±ε 트랩)** | 율이 X.X5 | `round_boundary=Y` 카운트 설계 | `rate1` round-half-up | FLOAT | **±ε(경계 반대로 굴리면 오답)** |

**테마 전환에서 실제로 막히는 5함정 — 반드시 점검:**
1. **가중 vs 단순평균** — 전사 비율/평균은 **반드시 `summarize`에서 "총분자/총분모"로 재계산**(L275). 개별 그룹 지표의 평균은 오답(발송수 큰 그룹이 더 큰 가중을 가져야 함). 이게 집계 엔진의 1번 변별 트랩(§4).
2. **분모 0** — 율/평균은 `rate1`/`arpu1`이 den==0→0.0을 반환하므로(L95·L103) 안전하지만, **새 지표에서 직접 나눗셈을 쓰면 ZeroDivision**. 항상 이 두 프리미티브를 경유하라. 빈 그룹(발송0)은 로그 행이 0이라 `main`의 보충 로직(L442–450)이 0/0.0으로 집계표에 등장시킨다.
3. **반올림 비결정성** — `round()` 내장이나 `f-string` 포맷이 아니라 **`Decimal`+`ROUND_HALF_UP`**(L98·L106)으로 계산해야 결정적. `round_boundary=Y` 트랩이 동작하려면 `lands_on_boundary`로 실재를 `cross_check`가 보장해야 한다(L296–304).
4. **INT/FLOAT 오분류** — 건수·합계를 `FLOAT_FIELDS`에 넣으면 ±ε이 변별을 죽이고(정수에 허용오차는 무의미), 율·평균을 `INT_FIELDS`에 넣으면 정답도 Exact 불일치로 오답. §2⑦에서 지표 타입대로 정확히 나눠라.
5. **spec 숫자 직접 베끼기** — `regroup_metrics`가 로그를 *다시* 집계해야 한다(L36). spec 숫자를 정답으로 바로 쓰면 독립검증·결정성 근거가 무너지고, 로그 합성 버그를 `cross_check`가 못 잡는다.

> 핵심: 이메일 골격(`build_log`·`regroup_metrics`·`summarize`·`cross_check` 구조)은 0줄 수정으로 재사용되지만, **새 지표는 위 패턴으로 regroup(+summarize 가중) 한 곳에 명시 복제**하고, grade에서 INT/FLOAT를 정확히 분류해야 한다.

## 3. 정답=계산/규칙 불변식 (절대 깨지 않게)

> **지표 1개를 더하거나 바꾸면, 반드시 네 곳을 동반 수정한다. 하나라도 빠지면 채점이 조용히 틀린다.**

| # | 파일·함수 | 무엇을 |
|---|---|---|
| 1 | `spec.csv` 헤더 + `load_spec`(L132–184) | 집계 입력·결함 노브 = CSV 컬럼 (§2①) |
| 2 | `build_dataset.py` — **합성**(`build_log` L203–228) + **집계**(`regroup_metrics` L234–263) + **전사**(`summarize` L266–276) + **자기검증**(`cross_check` L282–304) | 지표 = 로그합성 + 그룹집계 + 가중요약 + 트랩실재 (§2②③④) |
| 3 | `build_dataset.py` — 출력(`P1_COLS`/`SUM_COLS` L71–73, `metric_row` L337–342) | 지표 = 집계표 칸 + 요약 칸 (§2⑤) |
| 4 | `grade.py` — INT/FLOAT 필드(L30–33) + `FLOAT_TOL`(L34) | 칸 = 채점 필드(타입별 norm) + 허용오차 (§2⑦) |

**왜**: 집계 입력만 추가하고 `regroup_metrics`에 카운트/합산을 안 넣으면 그 지표는 정답에 안 잡히고(변별 0), `regroup`만 넣고 출력 칸(`P1_COLS`)을 안 맞추면 양식에 칸이 없어 채점 누락, 출력 칸만 넣고 grade의 INT/FLOAT에 안 넣으면 그 칸이 채점 안 됨. **가중 지표를 `summarize`에서 단순평균으로 내면** 자기채점은 100이 나와도(자기충족) 실제 정답이 틀리고 — §6 독립 재계산이 이걸 잡는다. 넷이 한 몸이다.

> **정답=로그 재집계가 핵심**: 매칭은 정답을 `member_passes`에서, 검증은 `derive_violations`에서 계산하지만, 집계는 **`regroup_metrics`가 로그를 다시 GROUP BY**해 정답을 만든다(spec 직접 베끼기 금지, L36). `cross_check`(L285–290)가 "로그재집계 == spec"을 대조해 합성 무결성을 강제하는 것이, 검증 엔진의 derive==expected 이중 정의에 대응하는 집계 엔진의 안전장치다.

### ★ 분리형(decouple)은 기본 내장
이 엔진은 분리형이 기본이다. `main`(L451–454)이 `build_metrics(..., answer=True)`를 재사용해 **Part2 입력용 정답 집계표** `data/campaign_metrics_given.xlsx`를 따로 저장한다. `build_summary` 안내(L390)가 "이걸 입력으로 쓰라 — 1단계 집계를 틀려도 2단계는 영향 없음"을 명시. 빈 양식(`campaign_metrics_template.xlsx`)은 Part1 제출용, `given`은 Part2 입력 전용. **채점은 독립**(`grade.py`가 Part1/Part2를 따로 채점, L200–207)이라 분리는 학생 입력 경로만 바꾸지 정답 계산을 바꾸지 않는다. 결합형(가혹)을 원하면 `given` 생성(L454)을 빼고 `build_summary` 안내를 "Part1에서 만든 집계표를 쓰라"로 바꾼다.

## 4. 채점 프리미티브 (이 엔진 고유 — Computed ±ε · norm_float · 가중평균 · 분모0)

집계 엔진은 매칭·검증의 **집합 F1**이 아니라 **셀 단위 수치 비교**로 채점한다. 두 종류의 비교가 있고, 칸을 둘 중 하나로 분류하는 것(§2⑦)이 채점 정확성의 전부다.

### (1) 정수 Exact — 합계·건수 (`int_eq` L66–67 · `norm_int` L44–52)
- 발송수·오픈수·매출합계 등 **건수·합계는 허용오차 없음**. `norm_int`가 콤마·공백·`원`·`.0`을 제거해 정수 문자열로 정규화 후 문자열 비교.
- **★빈칸 ≠ 0 보존**(L45): `norm_int(빈칸)=""`, `norm_int(0)="0"` — 미제출과 "0건"을 구분한다(매칭·검증 엔진의 G6과 동일 불변). FLOAT로 넘기면 이 구분이 깨진다.

### (2) Computed ±ε — 율·평균 (`float_eq` L70–79 · `norm_float` L55–63)
- 오픈율·ARPU·전체전환율 등 **율·평균은 `|정답 - 제출| < FLOAT_TOL`(기본 0.1)이면 정답**(L79). `norm_float`가 콤마·`%`·공백을 제거해 float로 파싱(빈칸/파싱불가→None, L62).
- **부동소수 잡음 제거**(L72·L79): `round(abs(a - s), 4) < tol` — 4자리 반올림으로 잡음을 없앤 뒤 엄격 비교. 그래서 **반올림 경계(X.X5)를 반대 방향으로 굴리면 정답과 정확히 0.1 차 → 오답**으로 트랩이 동작한다.
- **정답은 항상 숫자, 제출이 비면 오답**(L74–78): `a is None → 0.0`(정답 0.0 보정), `s is None → False`(미제출은 틀림).

### (3) 가중평균 — 전사 요약의 본질 트랩 (`summarize` L266–276)
- `전체전환율 = 총전환/총발송`(L275)은 **캠페인별 전환율의 단순평균이 아니다**. 발송수가 큰 캠페인이 더 큰 가중을 갖는다. 학생이 `mean(캠페인 전환율들)`로 내면 오답이 되도록 spec.example.csv가 설계됐고(40캠페인 발송수 분포가 의도적으로 치우침), 안내시트(L393·L397)가 이 함정을 명시 경고한다.
- 새 전사 지표는 반드시 **총분자/총분모**로 재계산하라 — 개별 행 지표를 평균하면 자기채점은 통과해도(생성·정답 둘 다 같은 식이면) 의도한 변별이 사라진다. §6 독립 재계산이 가중↔단순평균 혼동을 잡는 최종 게이트다.

### (4) 분모 0 — 0-나눗셈 안전 (`rate1`/`arpu1` L94–107)
- `zero_denom`(발송0/오픈0) 캠페인은 **모든 율=0.0, ARPU=0**. `rate1`/`arpu1`이 `den==0 → return 0.0`(L95·L103)으로 처리하므로 모든 율/평균 계산은 이 프리미티브를 경유해야 한다(직접 나눗셈 금지). 발송0 빈 캠페인은 로그 행이 0이라 `main`(L442–450)이 0/0.0으로 보충해 집계표에 등장시킨다 — **분모0도 "존재하는 정답 행"**이라 채점 대상이다(빈칸이 아니라 0.0).

> 요약: **칸을 INT/FLOAT로 정확히 분류**(§2⑦)하면 채점은 자동이다. 율·평균은 항상 `rate1`/`arpu1`(Decimal round-half-up)로 만들고 `float_eq`(±0.1)로 채점, 합계·건수는 `int_eq`(빈칸≠0)로 채점, 전사 지표는 `summarize`에서 가중(총분자/총분모)으로 재계산한다.

## 5. 새 집계 테마로 적응 — 워크스루 2종

### 워크스루 A — 주문/매출 일별 집계 (`GEN-L2-X3` 류, 단일 로그 · 그룹=일자)
"주문로그를 날짜별로 집계해 일매출·객단가·취소율 표 + 월 요약 내줘".

- **① spec.csv**: `date,주문수,취소수,매출합계_원,zero_denom,round_boundary` — 그룹 키를 날짜로, 결함 노브는 그대로(주문0일=분모0, 취소율 X.X5=반올림경계).
- **② build_log**: `order_rows`(1행=1주문: 주문ID·date·취소여부·금액). 취소수만큼 앞쪽을 취소=Y, 매출은 비취소 행에 `distribute_revenue`로 분배.
- **③ regroup/summarize**: `주문수`=행수, `취소수`=Y 행수, `취소율=rate1(취소수, 주문수)`, `객단가=arpu1(매출합계, 주문수-취소수)`. **월 요약 `전체취소율 = 총취소/총주문`(가중, summarize)**.
- **④ cross_check**: 로그재집계 == spec, round_boundary=Y면 취소율이 X.X5 실재.
- **⑤ 출력**: `P1_COLS=[date,주문수,취소수,취소율,매출합계,객단가]`, 안내에 분모0·반올림·가중 4문구.
- **⑦ grade**: INT=`[주문수,취소수,매출합계]`, FLOAT=`[취소율,객단가]`, SUM도 동형.
- **공유 그대로**: Computed ±ε·무결성·분리형·결정성·반올림 프리미티브.

### 워크스루 B — 채널별 트래픽 퍼널 집계 (`MKT-L2-X2` 류, 로그 · 그룹=채널)
"세션로그를 채널별로 집계해 유입→가입→결제 전환율 + 전사 요약".

- **① spec.csv**: `channel,세션수,가입수,결제수,결제액_원,zero_denom,round_boundary` — 퍼널 단조성 가드(결제≤가입≤세션, L156–159 복제).
- **② build_log**: `session_rows`(1행=1세션: 세션ID·channel·가입여부·결제여부·결제액). 퍼널 부분집합 패턴(L210–217) 그대로.
- **③ regroup/summarize**: `가입율=rate1(가입수,세션수)`, `결제전환율=rate1(결제수,세션수)`, `세션당매출=arpu1(결제액,세션수)`. **전사 `전체결제전환율=총결제/총세션`(가중)**.
- **④ cross_check**: ① 동형, ③ round_boundary=Y면 어떤 전환율이 X.X5 실재.
- **⑤ 출력/⑦ grade**: INT=count/sum 칸, FLOAT=율/평균 칸.
- **주의**: 세션0 채널(zero_denom=발송0→세션0으로 의미 이전)이면 모든 율=0.0. 퍼널 단조성 무결성(grade L131–143)을 결제≤가입≤세션으로 교체.

> 두 워크스루 모두 **§1 GENERIC은 0줄 수정**, §2 체크리스트 ①~⑦만 바꾼다. 핵심 불변식(§3): `build_log`·`regroup_metrics`(+`summarize` 가중)·출력 칸·grade INT/FLOAT 네 곳 동반 + `cross_check` 통과 + 독립 재계산 일치.

## 6. 재생성 · 자기채점 · 독립검증 루프 (바꾼 뒤 반드시)

지표/로그를 바꿨으면 아래를 순서대로 돌려 닫는다. 하나라도 실패하면 발행 금지(S10 게이트).

```bash
# 1) 재생성 — spec.csv(새 집계 입력·결함 노브) → 로그·양식·정답키 산출.
#    cross_check가 '로그재집계 == spec' + '트랩 실재'를 검사하므로, 통과 못 하면 여기서 중단된다(1차 자기검증).
python eval/answer_key/build_dataset.py
#   콘솔: 캠페인 N개 / 발송로그 행수 / 발송0 수 / 전체전환율(가중)·전체ARPU (자기검증 통과)

# 2) 자기채점 — 정답키로 정답 양식을 채워 채점하면 100점이어야 한다(정합성 2차 확인)
python eval/grade.py \
  --part1 eval/answer_key/campaign_metrics_answer.xlsx \
  --part2 eval/answer_key/summary_answer.xlsx \
  --answer-dir eval/answer_key
#   → 총점(100) 100.0 / Part1 셀정확도 100% / Part2 셀정확도 100% 가 아니면
#     INT/FLOAT 필드↔출력 칸 불일치(§3-4) 또는 norm 함수 오배정(§2⑦)을 의심.

# 3) 독립 재계산 — build_dataset 로직을 '재사용하지 않고' spec.csv+rulebook만으로
#    지표를 다시 계산해 *_answer.xlsx와 셀 단위(±ε) 대조. 불일치 = 발행 차단.
python verify/independent_recompute.py         # verify/ 참조
```

- **cross_check가 막으면**(1단계 중단): ① 로그재집계≠spec(`build_log` 합성 버그 — 퍼널 부분집합·분배 깨짐) ② 발송>0인데 로그 없음 ③ round_boundary=Y인데 어떤 율도 X.X5에 안 옴(카운트 조정 필요, L296–304).
- **자기채점 100이 안 나오면**: 거의 항상 **§3 불변식 누락**(INT/FLOAT 필드에 새 칸을 안 넣음, 또는 출력 칸 순서 불일치, 또는 시트명 불일치).
- **자기채점 100인데 독립 재계산이 불일치하면**: 생성·채점 양쪽에 **같은 버그**가 있는 것 — 집계 엔진에서 가장 흔한 건 **가중평균↔단순평균 혼동**(`summarize`가 단순평균인데 독립 재계산은 가중)이나 **반올림 규칙 불일치**(round-half-up vs banker's). `cross_check`는 로그↔spec만 보지 지표 계산식의 옳음은 못 보므로, **독립 재계산이 이 자기충족 허점을 잡는 게이트**다.
- 마지막으로 `verify/adversarial_prompts.md`로 적대 리뷰(전사 지표를 단순평균으로 냈나? 분모0에서 ZeroDivision/빈칸? 반올림 경계를 truncate로 냈나? 건수를 ±ε로 채점하나? 빈칸≠0 깨졌나? seed/ASSIGN_DATE 누락? 퍼널 단조성 가드 빠졌나?)를 돌리고, `references/checklist.md` G1~G10 발행 게이트를 통과시킨다.
