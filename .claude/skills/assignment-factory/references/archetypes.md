# 아키타입 라우팅 (S1.5) — 직무×업무형태 → 엔진 선택

**목적**: 인터뷰(S1)의 **Q2(직무×업무형태)** + **Q4(아키타입)** 가 들어오면, 그 한 쌍으로 **아키타입을 판정**해 엔진을 고른다. 판정 결과는 세 갈래다.

- **매칭 계열로 판정** → `engines/matching/`로 진행(S2~S10). 적응 방법은 `matching-engine-guide.md`.
- **검증/감사/대사 계열로 판정** → `engines/audit/`로 진행(S2~S10). 적응 방법은 `audit-engine-guide.md`. ("데이터+규칙→위반 판정", Set-F1+셀 Exact.)
- **집계/분석 계열로 판정** → `engines/aggregate/`로 진행(S2~S10). 적응 방법은 `aggregate-engine-guide.md`. ("로그→그룹 집계 + 가중 전사요약", 수치 Computed ±ε.)
- **취합/통합 계열로 판정** → `engines/merge/`로 진행(S2~S10). 적응 방법은 `merge-engine-guide.md`. ("제각각 양식 다수→정형 하나", 행집합 Set-F1 + 셀 Exact.)
- **분류/라벨링 계열로 판정** → `engines/classify/`로 진행(S2~S10). 적응 방법은 `classify-engine-guide.md`. ("텍스트→범주 라벨, 축마다 유일 라벨", 다클래스 macro-F1 + 혼동행렬. **모호함을 규칙으로 결정화** — 자유판단 금지·우선순위 첫 매치.)
- **그 외(랭킹·퍼널·초안)로 판정** → **"미지원 + 수동 설계 가이드"를 정직하게 반환하고 종료**. 거짓 자동화를 시도하지 않는다.

> 근거: `_과제생성기_skill_설계계획.md` §7(연동 레시피)·§1(전이 범위)·§10(로드맵). 카탈로그: `_6일반범용-마케팅-산업범용-업무형태-보강.md`(GEN 12종·MKT 분야/[분석]형 TOP12·확장 뱅크 24개).
> **핵심 가치**: 스킬이 "재사용 불가"를 정확히 선언하는 것 자체가 산출물이다. 지원 엔진(매칭·검증·집계·취합·분류)이 아닌 과제를 억지로 찍으면 결정성이 깨진다(§ 왜 재사용 못 하나).
> **현재 지원 엔진 5종**: `engines/matching/`(다축 매칭·타게팅) + `engines/audit/`(검증·감사·대사) + `engines/aggregate/`(집계·분석) + `engines/merge/`(취합·통합) + `engines/classify/`(분류·라벨링). 나머지(랭킹·퍼널·초안)는 미지원 + 수동 가이드(초안은 생성형이라 결정성과 근본 충돌 — 형식 채점만).

## 1. 매핑 절차 (Q2 → 업무형태 → 채점유형 → 아키타입 → 축)

```
직무(Q2) → _6 카탈로그 업무형태 후보 (GEN G1~G12 / MKT M1~M12 · 분야 10종 / 확장 -X 뱅크)
         → _6의 '채점유형'으로 아키타입 클러스터링 (아래 §2 표)
            Exact / Set 매칭형      → 다축 매칭 엔진   (MKT-L2-X1/X6, M8)               ← engines/matching ✅
            Exact / Set 대사·감사   → 검증/감사 엔진   (GEN-L2-X1/X2, G1, MKT-L1-X4/M11) ← engines/audit ✅
            Exact 정규화 / 취합·디둑 → 취합/통합 엔진   (GEN-L1-X4, MKT-L1-X1, M5)       ← engines/merge ✅
            Computed 집계            → 집계/분석 엔진   (MKT-L1-X2, GEN-L3-X2, M1/M3/M12) ← engines/aggregate ✅
            Set 텍스트→범주 라벨 분류 → 분류/라벨링 엔진 (GEN-L2-X5, MKT-L2-X4, G2/G9, M10) ← engines/classify ✅
            Computed Rank / 매트릭스 / 생성형 초안 → weighted_rank / cohort-funnel / (없음) (MKT-L3-X1/X4, GEN-L2-X3, M6/M7, M11카피) ← 미지원
         → 매칭이면 '축↔컬럼' 스키마 규정 → AXES 표 → engines/matching 적응(S3~, matching-engine-guide.md)
         → 검증/감사면 '결함노브↔위반유형' 규정 → cases.csv 시나리오 → engines/audit 적응(S3~, audit-engine-guide.md)
         → 집계면 '집계입력↔결함노브' 규정 → spec.csv 시나리오 → engines/aggregate 적응(S3~, aggregate-engine-guide.md)
         → 취합이면 'canonical↔소스분배' 규정 → orders.csv 시나리오 → engines/merge 적응(S3~, merge-engine-guide.md)
         → 분류면 '라벨집합↔규칙북(키워드·우선순위)' 규정 → items.csv 시나리오 → engines/classify 적응(S3~, classify-engine-guide.md)
         → 다섯 다 아니면(랭킹·퍼널·초안) §4 수동 설계 가이드 반환 후 종료
회사색 제거: _6 §0 진단 + §5 입력 다양성 레버. 소재는 (직무 × 업무형태)에서 추출하고 회사 종속 금지.
```

**판정의 결정 신호**: `_6` 카탈로그 표의 **채점유형 칸**이 1차 신호다.
- `Exact` / `Set` 이고 정답이 **(엔티티 × 기준)의 자격 통과 집합**이면 → **매칭**(`engines/matching`).
- `Exact` / `Set` 이고 정답이 **(데이터에 규칙 적용 → 위반/예외 집합)**이면 → **검증/감사**(`engines/audit`). 신호: 여러 소스 키 조인 + 불일치/누락 분류, 또는 단일 소스 규칙 위반 검사(길이·중복·누락).
- `Exact` 이고 정답이 **(제각각 양식의 여러 소스 → dedup·정규화·우선순위된 정형표 1장)**이면 → **취합/통합**(`engines/merge`). 신호: 양식이 다른 다수 소스를 표준 한 장으로, 같은 키 중복 행 합치기 + 컬럼명/표기 표준화 + 값 충돌 우선순위.
- `Computed` 이고 정답이 **(로그·원장 → 그룹별 집계 수치 + 가중 전사요약)**이면 → **집계/분석**(`engines/aggregate`). 신호: GROUP BY 건수·합계·율·평균, 분모0·반올림 경계 트랩.
- `Set`/`Exact` 이고 정답이 **(비정형 텍스트 → 축마다 유일 범주 라벨)**이면 → **분류/라벨링**(`engines/classify`). 신호: 유형·감성·토픽·우선순위 등 닫힌 라벨 집합을 규칙(키워드·우선순위)으로 판정, 다중 키워드 충돌·판별불가·약한신호 트랩. 정답은 집합이 아니라 **항목별 단일 라벨**이라 채점이 다클래스 macro-F1.
- `Rank`(가중 순서)·매트릭스(코호트/퍼널)·**생성형 초안**(카피·보도자료)이면 → **미지원**. 랭킹·퍼널은 신규 엔진으로 가능하나, **초안은 "없던 글 쓰기"라 유일 정답이 없어 결정성과 근본 충돌**(형식·루브릭 채점만, 메인 채점 제외 — `_6 §생성형`).

> **다섯 지원 엔진 구분**: 매칭은 "엔티티가 기준을 *통과하느냐*"(자격, `member_passes` AND 필터), 검증은 "소스들이 규칙에 *어긋나느냐*"(위반, `derive_violations` 재적용), 취합은 "제각각 소스를 *하나로 합치느냐*"(통합, `consolidate` dedup·우선순위), 집계는 "로그를 *그룹으로 묶어 수치를 내느냐*"(`regroup_metrics` GROUP BY + `summarize` 가중), 분류는 "텍스트가 *어느 범주냐*"(라벨, `derive_labels` 규칙 재적용 → 축마다 유일 라벨). 매칭·검증·취합은 Set 계열 채점(취합은 행집합 F1+셀 Exact), 집계는 수치 Computed ±ε, 분류는 **다클래스 macro-F1 + 혼동행렬**(항목별 유일 라벨이라 집합도 ±ε도 아님)이다.

Q4를 사용자가 명시 override하지 않으면 Q2에서 위 신호로 자동 판정한다(인터뷰 진행 규칙과 동일).

## 2. 아키타입별 엔진 재사용성 표 (채점유형으로 클러스터링)

| 아키타입 | `_6` 형태 예 | 정답 형태 | 채점 | 지원 엔진 | 상태 |
|---|---|---|---|---|---|
| **A. 다축 매칭/타게팅(CRM)** | M8, MKT-L2-X1/X6 | (엔티티 × 기준) 통과 집합 | 집합 F1 | ✅ `engines/matching/`(`matching-engine-guide.md`) | **지원** |
| **B. 검증/감사/대사(reconcile·audit)** | G1, GEN-L2-X1/X2, MKT-L1-X4/M11 | (데이터 + 규칙) → 위반/예외 집합 | Set-F1 + 셀 Exact | ✅ `engines/audit/`(`audit-engine-guide.md`) | **지원** |
| **C. 취합/통합(merge·consolidate)** | GEN-L1-X4 주문표준화, MKT-L1-X1 리스트정규화, M5 | 제각각 양식 다수 → dedup·정규화·우선순위된 정형표 1장 | 행집합 Set-F1 + 셀 Exact | ✅ `engines/merge/`(`merge-engine-guide.md`) | **지원** |
| **D. 집계/분석(aggregate)** | MKT-L1-X2 캠페인성과, GEN-L3-X2 대시보드, M1/M3/M12 | 그룹별 집계표 + 가중 전사요약 1행 | 수치 Computed ±ε (INT Exact + FLOAT ±0.1) | ✅ `engines/aggregate/`(`aggregate-engine-guide.md`) | **지원** |
| **E. 분류/라벨링(classify)** | GEN-L2-X5 VOC 유형·감성, MKT-L2-X4 멘션 감성·주제, G2/G9, M10 | 비정형 텍스트 → 축마다 유일 범주 라벨 | 다클래스 macro-F1 + 혼동행렬 (라벨 norm·INVALID 센티넬) | ✅ `engines/classify/`(`classify-engine-guide.md`) | **지원** |
| F. Rank 가중 랭킹 | M9, GEN-L2-X3 견적 | 순서 리스트 + 점수식 | 순위상관/NDCG·동점규칙 | ❌ 집합 F1·셀 ±ε·macro-F1 모두 순서 무시 | 미지원(신규 엔진 가능) |
| G. 퍼널/코호트 | M6/M7, MKT-L3-X1 | 코호트×단계 매트릭스 | 단계 수치 비교 | ❌ 2축 매트릭스(집계의 1축 그룹 밖) | 미지원(신규 엔진 가능) |
| H. 생성형 초안(draft) | M11 카피·보도자료, _6 [생성]형 | 자유 생성 텍스트(유일 정답 없음) | 형식/루브릭(주관) | ❌ "없던 글 쓰기"라 결정성과 근본 충돌 | 미지원(근본 — 메인 채점 제외) |

> **매칭이 즉시 재사용되는 이유**: 매칭은 정답이 **순서무관 집합**(회원 × 정책)이라 `grade_part2`(matching grade.py L101–133)의 **집합 F1**이 자연스럽고, `plant_boundaries`(build L395–473)가 각 축에 경계 엔티티를 심어 다축 변별을 자동 주입한다.
> **검증/감사가 같은 채점을 쓰는 이유**: 검증도 정답이 **순서무관 집합**(발주번호, 품목코드, 위반유형)이라 동일 Set-F1을 키만 바꿔 재사용한다(`engines/audit/grade.py` `grade_part2` L124–142). 차이는 정답 *도출* — 매칭의 `member_passes`(AND 통과) 대신 `derive_violations`(audit build L236–257)가 소스 테이블에 허용오차 규칙을 **재적용**해 위반을 뽑고, `plant_boundaries`(경계 회원 심기) 대신 **cases.csv가 운영자 결함 명세**로 결함을 직접 주입한다.
> **취합이 지원으로 이동한 이유**: 취합도 정답이 **순서무관 행집합**(dedup·통합된 통합표)이라 `grade_part1`이 **행집합 F1 + 셀 Exact**를 쓰되 정밀도 분모를 제출 행 전체로 잡아 **dedup 실패를 처벌**하고(`engines/merge/grade.py`), `plant_boundaries` 대신 **orders.csv가 canonical↔소스분배 명세**로 양식차·중복·값충돌을 주입한다(`build_sources`가 1행을 제각각 양식의 여러 소스로 흩뿌림).
> **집계가 지원으로 이동한 이유**: 집계만은 채점 모델이 집합이 아니라 **셀 단위 수치 Computed ±ε**다. `regroup_metrics`(로그 GROUP BY 재집계)로 정답을 만들고(spec 숫자 직접 베끼기 금지), `summarize`가 전사 가중지표를 총분자/총분모로 재계산하며, `spec.csv` 노브(분모0·반올림경계)로 변별을 심는다(`engines/aggregate/`).
> **분류가 지원으로 이동한 이유**: 분류는 검증/감사 엔진과 **derive↔expected 이중정의 + cross_check 자기검증**을 공유한다 — `derive_violations`(테이블→위반)를 `derive_labels`(텍스트→라벨)로 치환하면 그대로 동형이다. 다른 점 셋: ① 위반 *집합*이 아니라 **축마다 유일 라벨**(상호배타 다클래스)이라 채점이 Set-F1이 아닌 **macro-F1 + 혼동행렬**(소수 클래스를 무시하는 단순 정확도의 함정 차단) ② 조인이 아니라 **텍스트 합성**(키워드를 심고 규칙으로 되읽음, `_assert_vocab_disjoint`로 축 어휘 분리 강제) ③ 정답은 **공개 규칙북(키워드·우선순위)의 기계적 재적용**으로 정의해 "모호함을 규칙으로 결정화"(자유판단 금지·다중 매치는 우선순위 첫 매치·판별불가는 fallback) — 학생·정답키·채점이 같은 규칙을 본다. `items.csv` 노브(충돌주입·판별불가·약한신호)가 변별을 심는다(`engines/classify/`).
> 남은 랭킹·퍼널·초안은 이 메커니즘이 **여전히 의미를 잃는다**(아래 §왜). 특히 초안은 신규 엔진으로도 결정성이 안 서는 **근본 미지원**이다.

## 3. 라우팅 규칙 (S1.5 분기 — 이대로 실행)

1. **입력**: 인터뷰의 Q2(직무×업무형태) + Q4(아키타입, 없으면 Q2 자동 판정값).
2. **판정**: §1 신호 + §2 표로 아키타입 1개를 고른다.
3. **분기**:
   - **매칭** → "✅ 매칭 아키타입 확정. `engines/matching/`로 진행" 선언 → S2(도메인 그라운딩) → S3(축↔컬럼 표) → `matching-engine-guide.md`로 적응.
   - **검증/감사/대사** → "✅ 검증/감사 아키타입 확정. `engines/audit/`로 진행" 선언 → S2(도메인 그라운딩) → S3(결함노브↔위반유형 표) → `audit-engine-guide.md`로 적응. cases.csv가 단일 입력.
   - **집계/분석** → "✅ 집계 아키타입 확정. `engines/aggregate/`로 진행" 선언 → S2(도메인 그라운딩) → S3(집계입력↔결함노브 표) → `aggregate-engine-guide.md`로 적응. spec.csv가 단일 입력.

## 4. 미지원 반환 형식 (지원 엔진 밖일 때 — 정직하게 1~2문단)

매칭·검증/감사·집계·취합·분류 어디에도 안 맞는(랭킹·퍼널·초안) 것으로 판정되면 자동 생성을 멈추고, **아래 4요소만** 담은 짧은 가이드를 반환한다(과제를 손으로 만들 출제자용 길잡이). 코드는 만들지 않는다.

1. **판정 결과**: "이 과제는 **<아키타입>**(예: 가중 랭킹)으로, 현재 지원 엔진(매칭·검증/감사·집계·취합·분류)의 범위 밖입니다."
2. **필요한 엔진**: 어떤 신규 엔진이 있어야 하는지 1줄(weighted_rank / cohort-funnel 중). *(대사·감사는 `engines/audit/`, 집계·분석은 `engines/aggregate/`, 취합·통합은 `engines/merge/`, 분류·라벨링은 `engines/classify/`로 이미 지원 — 여기로 오지 않는다.)* **초안(생성형)은 예외 — 신규 엔진으로도 결정성이 안 서므로 "결과 메인 채점 불가, 형식·과정 채점만"을 명시한다.**
3. **무엇이 결함(트랩)이 되는가**: 그 아키타입에서 변별을 만드는 의도된 결함 — 매칭의 "경계 회원 ±1", 검증의 "허용오차 경계 ±1", 분류의 "충돌 키워드·판별불가"에 대응하는 것. 예: 랭킹형 = **가중치 경계·동점 처리 규칙**; 퍼널형 = **단계 정의·중복 이벤트**; 초안형 = (결정적 결함 주입 불가 — 그래서 결과 채점 자체가 안 선다).
4. **결정성 확보 방향**: 정답이 유일해지려면 무엇을 통제값으로 줘야 하는지(예: 랭킹은 가중치·동점규칙을 PDF로 제공) — `_6 §4(A~D)`를 인용. **초안은 통제값으로도 유일 정답이 안 나오므로(자유 생성), 닫힌 라벨 집합으로 환원되면 그건 이미 분류(`engines/classify/`)다.**

> 예시 반환문(견적 비교 랭킹):
> "이 과제는 **Rank(가중 랭킹)** 형태로 지원 엔진(매칭·검증·집계·취합·분류) 밖입니다. 정답이 '가중 점수 순위'라 순서무관 집합(매칭·검증·취합)도, 셀 ±ε(집계)도, 항목별 단일 라벨(분류)도 순서를 보존하지 못합니다. 손으로 설계한다면 **weighted_rank 엔진**이 필요합니다 — 결함은 '가중치 경계·동점 처리 규칙'에 심고, 정답 결정성은 가중치표와 동점 타이브레이크를 PDF로 **제공**해(`_6 §4-A`) 확보하세요. 자동 생성은 이 엔진이 `engines/weighted_rank/`로 추가될 때 가능합니다."

## 5. 왜 남은 미지원(랭킹·퍼널·초안)은 지원 엔진을 재사용 못 하나 (결정성 근거)

지원 엔진 5종은 세 가지 채점 모델을 쓴다 — 매칭·검증·취합은 **순서무관 집합 + Set-F1**(취합은 행집합 F1 + 셀 Exact), 집계는 **셀 단위 수치 Computed ±ε**, 분류는 **항목별 유일 라벨 + 다클래스 macro-F1**. 남은 미지원 3종(랭킹·퍼널·초안)은 이 세 채점 모델 **어느 쪽도** 안 맞는다.

- **랭킹은 불리언 판정도, GROUP BY 합산도, 단일 라벨 분류도 아닌 연속 점수 정렬**이다. 집합 채점도, 집계의 셀 ±ε도, 분류의 macro-F1도 "순서가 곧 정답"인 랭킹을 못 잰다(순위상관·NDCG·동점규칙이 필요).
- **퍼널/코호트는 1축 그룹 집계가 아니라 코호트×단계 매트릭스**다. 집계 엔진의 `regroup_metrics`는 단일 키 GROUP BY라 2축 잔존 매트릭스·단계 중복 이벤트를 못 만든다.
- **초안(생성형)은 유일 정답이 없다**. 분류처럼 보여도(텍스트 산출) 정답이 "닫힌 라벨 집합에서 규칙으로 고르는 것"이 아니라 "없던 글을 새로 쓰는 것"이라, `derive_labels` 같은 규칙 재적용이 성립하지 않는다 — **결정성과 근본 충돌**이다. 닫힌 라벨로 환원되면 그건 이미 분류다. 그래서 초안은 결과 메인 채점에서 빠지고 형식·과정 채점만 남는다(`_5 §6.2` [생성]형 처리).
- **결함 주입**: 랭킹은 "가중치 경계·동점", 퍼널은 "단계 정의·중복 이벤트"가 트랩이라, 매칭의 `plant_boundaries`·검증의 `cases.csv`·집계의 `spec.csv`·취합의 `orders.csv`·분류의 `items.csv` 노브 중 **어느 주입 모델과도 1:1 대응하지 않는다**. 초안은 아예 **결정적 결함을 심을 자리가 없다**(유일 정답이 없으니).

> **검증·집계·취합·분류가 미지원에서 빠진 길**: 넷 다 한때 "데카르트 곱이라 집합을 못 쓴다"(대사)·"디둑/Computed"(취합·집계)·"모호한 주관 라벨링"(분류)으로 묶여 미지원이었으나, 실제로는 각자의 정답이 **결정적으로 재계산 가능**했다 — 대사는 "위반/예외의 순서무관 집합"(`derive_violations`, `engines/audit/`), 취합은 "소스 재파싱→dedup·우선순위"(`consolidate`, `engines/merge/`), 집계는 "로그 GROUP BY 재집계 + 가중요약"(`regroup_metrics`/`summarize`, `engines/aggregate/`), 분류는 "공개 규칙북의 기계적 재적용 → 축마다 유일 라벨"(`derive_labels`, `engines/classify/`)으로. 각자 **자기 결함 주입기**(cases.csv·orders.csv·spec.csv·items.csv)와 **자기 정답계산기**를 구현해 §2 B·C·D·E행으로 이동했다. 분류의 열쇠는 "모호함을 규칙으로 결정화"(우선순위 첫 매치·판별불가 fallback)였다.

→ 그래서 남은 미지원 중 **랭킹·퍼널**은 **자기 결함 주입기 + 자기 정답계산기**를 새로 구현하면 된다(§6 엔진 계약). 인터뷰·eval 4문서·결정성 게이트·이중 검증은 공유한다(검증·집계·취합·분류 엔진이 이미 그 상속을 입증했다). **초안만은 예외 — 유일 정답이 없어 어떤 정답계산기로도 환원되지 않으므로 근본적으로 결과 자동 채점 밖이다.**

## 6. 엔진 계약 (새 아키타입 엔진이 지켜야 할 인터페이스)

새 엔진을 추가할 땐 `engines/<archetype>/`에 구현하고 **이 계약을 지키며**, 위 §2 라우팅 표에 한 줄 등록한다. 매칭 엔진이 레퍼런스 구현이다.

### 계약 (필수 6조)

1. **단일 입력 CSV → 1벌**: 하나의 진실 소스 CSV(`<input>.csv`)만 바꿔 재실행하면 **데이터 + 제출 양식 + 정답키 + grade 입력**이 항상 정합하게 재생성된다(build_dataset의 `load_policies`→`synthesize`→`build_p1/p2` 흐름과 동형).
2. **4산출물 동시 생성**: ① 합성 데이터(`data/*.xlsx`) ② Part별 **빈 제출 양식**(+ '안내' 시트) ③ **정답키**(`eval/answer_key/*_answer.xlsx`) ④ 그 정답키를 읽는 **채점기**(`eval/grade.py`). 빈 양식과 정답은 **같은 함수의 `answer` 플래그**로 한 번에 찍는다(p1_row L577–594 패턴 — 양식·정답 비대칭 버그 차단).
3. **결정성 3종 고정**: ① `ASSIGN_DATE`(기준일 상수, `datetime.now()` 금지) ② `random.seed(<고정값>)` ③ 합성 진입부에서 **clear + reseed**(synthesize_members L478–480) — 같은 프로세스 재호출에도 동일 시퀀스. 같은 입력 = 항상 같은 데이터·정답.
4. **fail-loud 입력 검증**: CSV 로더는 빈 필수값·허용 외 값·자기모순을 **조용히 통과시키지 말고 즉시 중단**한다(load_policies L186–198: 빈 region 차단, employment 허용값, `matchable=N`인데 소득값 채움 차단).
5. **안내시트 자기설명**: 각 제출 양식에 '안내' 시트(항목/설명 2열 + 빈칸 규칙 + 판정 규칙)를 동봉해, `problem.md` 없이도 양식만으로 채점 규칙이 닫힌다(build_p1/build_p2 L597–686 골격).
6. **독립 검증 가능**: 정답 계산 로직이 build 코드와 **분리 재구현 가능**해야 한다 — `verify/independent_recompute`가 CSV+규칙만으로 정답키를 다시 계산해 셀 단위로 대조한다(자기충족 채점 허점 차단).

### 채점기 계약

- **차원 분리 배점**: 정확도/형식/무결성을 분리 집계(grade.py `score` L138–145: Part1 추출 50 / Part2 채점 40 / 무결성 10). 가중치는 아키타입별로 조정하되 **분리**는 유지.
- **정규화 관용**: 동치 표기를 흡수하는 `norm_*` 헬퍼(grade.py L19–55)를 축 타입별로 둔다(빈칸≠0 보존: `norm_int` L33).
- **무결성 센티넬**: "추천 불가/유령 ID/판별불가 정책" 같은 위반을 별도 탐지(grade_part2 L118–125).

### 공유 자산 (모든 엔진이 함께 씀)

`references/interview.md`(Q1~Q11) · eval 4문서 골격(`doc-templates.md`) · 발행 게이트(`checklist.md` G1~G10) · 이중 검증(`verify/`). 새 엔진은 **자기 결함 주입기 + 자기 정답계산기 + 자기 채점 트리**만 구현하고 나머지는 상속한다.

> **향후 방향**: 매칭 엔진의 파라미터화 표면을 `AXES` 스펙 1개(`{축명, 컬럼, 타입, 통과값생성기, 경계생성기, 정규화}`)로, 검증 엔진을 `RULES` 스펙(`{위반유형, 결함노브, 임계/허용오차, derive식, 정규화}`)으로, 집계 엔진을 `METRICS` 스펙(`{그룹키, 지표타입(건수/합계/율/평균/가중), 허용오차, 결함노브(분모0/반올림경계)}`)으로, 취합 엔진을 `SOURCES` 스펙(`{소스양식, 형식렌더↔파서, 통합규칙(dedup/우선순위/집계), 정규화}`)으로, 분류 엔진을 `LABELS` 스펙(`{축명, 라벨집합, 우선순위순서, 키워드, 어구생성기, derive식, alias, 결함노브(충돌/판별불가/약한신호)}`)으로 추출하면, 남은 미지원 엔진도 각자의 스펙(랭킹=가중치/동점, 퍼널=단계/이벤트)으로 같은 계약을 채울 수 있다(설계계획 §6.2). 지금은 **매칭·검증·집계·취합·분류 5종**이 구현돼 있다(`engines/matching/`·`engines/audit/`·`engines/aggregate/`·`engines/merge/`·`engines/classify/`). (초안은 유일 정답이 없어 이 계약 자체가 성립하지 않는다.)
