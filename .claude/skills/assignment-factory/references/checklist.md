# 발행 전 통과 게이트 (Publish Gate Checklist)

> S10에서 강제하는 **발행 차단 체크리스트**다. 여기 5개 군(5.1~5.4) 중 **하나라도 통과 못 하면 — 단계 불문 — 발행 금지**다.
> 근거: `_5직무-바이브코딩-과제설계.md` §6(결과 채점 가능성·제1법칙·5유형·6.6 공통 규격), `_과제생성기_skill_설계계획.md` §5.
> 각 항목의 *근거*는 레퍼런스 구현 `problems/marketing/1.youth_policy/`의 코드 위치다(엔진 원본: `engines/matching/build_dataset.py`·`grade.py`).
> 검증자(verifier) 에이전트는 이 파일을 항목별로 점검하고, FAIL이 0건일 때만 통과 처리한다.

사용법: 새 과제 패키지를 빌드한 뒤 아래를 순서대로 점검한다. 각 체크박스에 **PASS/FAIL + 근거 1줄**을 채운다. FAIL이 하나라도 있으면 그 자리에서 멈추고 결함을 고친 뒤 처음부터 다시 돈다.

## 5.1 결정성 / 채점 가능성 (G1~G10) — `_5 §6` 출제 게이트

각 칸이 (제공 파일 + 명시 규칙) → 유일 정답으로 환원되는지. 괄호는 youth_policy 구현 근거(엔진 라인 = `build_dataset.py`/`grade.py` 기준).

- [ ] **G1 단일 정답 환원** — 모든 채점 칸 = (제공 파일 + 명시 규칙) → 유일값. 학생이 정답을 추론할 자유도 0.
  - 근거: 모든 정답이 `policies.csv` → `build_dataset.py`에서 유일 산출(Part1=`p1_row` answer=True L577–594, Part2=`member_passes`×데카르트곱 L702–705). 같은 입력=같은 정답.
- [ ] **G2 발명 → 적용 전환** — 학생이 *발명할* 기준 0개. 모든 판정 규칙을 안내시트로 제공.
  - 근거: 9축 자격 판정 규칙을 `build_p2` 안내시트(L643–667)에 명문화, `build_p1` 안내시트(L601–620)가 칸 형식 명시. problem.md는 규칙을 안 담고 "안내시트대로"만 가리킨다.
- [ ] **G3 구조화 슬롯** — 제출물 = 구조화 엑셀(정해진 칸/시트), 자유문서 0. "리포트 써라" 금지.
  - 근거: Part1=`P1COLS` 13칸(L553), Part2=`회원ID,추천정책ID` 2칸 집합(L678). 둘 다 `submission_template.xlsx` 형식.
- [ ] **G4 생성형 제거** — 산문/카피 품질을 결과 채점하지 않음. 생성물은 과정 채점 또는 근거결속 슬롯으로만.
  - 근거: youth_policy는 매칭 리스트만 채점(생성물 슬롯 없음). 생성 슬롯이 있는 과제는 Format/Grounding(수치 인용·길이·개수)만 채점하고 문장력은 제외(`_5 §6.5`).
- [ ] **G5 폐쇄화(모호성 봉쇄)** — 정답이 갈릴 경계 모호 항목을 입력 설계 단계에서 배제.
  - 근거: 만나이 6/28 당일 생일을 회피하고(생성월을 1–5월/7–12월만, `birth_for_age` L235·`birth_unpassed` L241), 당일 생일자를 모집단에 만들지 않음 → 모호 케이스 0.
- [ ] **G6 빈칸 = 제약 없음, 빈칸 ≠ 0** — 미명시 자격을 닫힌 의미로 고정. 0과 빈칸을 절대 혼동 안 함.
  - 근거: 4중 고정 — problem.md/안내시트(L616 "0과 빈칸은 다르다") · INPUT_GUIDE · `int_or_none`(빈칸→None, L90–97) · `norm_int`(빈칸 보존, grade L33–37). `member_passes`가 `is not None`으로만 조건 적용(L514–539).
- [ ] **G7 정답키 + 자동 채점 스크립트 동반** — `grade.py` 존재하고 실제로 작동.
  - 근거: Part1 셀 Exact(`grade_part1` L76–98) + Part2 집합 F1(`grade_part2` L101–133) + 무결성. 스크립트를 못 짜는 사례는 출제하지 않는다(`_5 §6.6-2`).
- [ ] **G8 부분점수 차원 분리** — 정확도/형식/누락을 분리 집계.
  - 근거: 배점 50(P1 셀정확도)/40(P2 F1)/10(무결성), `score` L138–145. FP·FN을 분리 출력(L129), 필드별 정확도 분해(L96).
- [ ] **G9 채점 관용(정규화)** — 동치 표기를 흡수(과민 채점 금지).
  - 근거: `norm_constraint`(무관≡없음≡빈칸 L45–49) · `norm_int`(콤마·공백 제거 L33) · `norm_house`(필요≡Y≡예≡O≡무주택 L51–55) · `norm_str`(공백 제거 L19–21). 지역은 표기 변형을 `detect_sido`/`detect_gu`로 흡수(L113–139).
- [ ] **G10 재현성** — seed·기준일 고정, `datetime.now()` 금지.
  - 근거: `ASSIGN_DATE=date(2026,6,28)`(L56) · `random.seed(20260628)`(L57) · `synthesize_members`가 호출마다 `_members.clear()`+`_mid[0]=1`+`random.seed` 재설정(L478–480) → 재호출 안전.

## 5.2 매칭 아키타입 구조 불변식

- [ ] **축 ↔ 데이터 컬럼 교집합 불변식** — 판정에 쓰는 모든 축에 회원·엔티티 데이터의 1:1 대응 컬럼이 존재. 축을 추가하면 **CSV 헤더 · `build_dataset.py`(plant/passes/columns) · `grade.py`(`P1_FIELDS`) 세 곳을 동반 수정**.
  - 근거: 9축 각각이 회원 컬럼과 짝(나이↔생년월일, 소득↔월소득_원, 연소득↔연소득_원, 지역↔거주지, 취업↔취업상태, 기업규모↔기업규모, 무주택↔주택소유여부, 학력↔재학상태, 혼인↔혼인여부). `member_passes`(L509–540)·`P1_FIELDS`(grade L70–75)·`P1COLS`(L553)가 같은 축 집합을 공유. 짝 없는 축은 거부(S3에서 reject).
- [ ] **판별불가 = 추천 안 함 0건 닫힘** — `matchable=N` 정책(예 YP09 꿈나래통장)은 9축과 분리된 운영 플래그로 매칭 0건이 강제됨. 정답표의 그 정책 자격 칸 중 **회원 데이터로 확인 불가한 칸은 비어 있어야 함**. (브리프에서 자명하게 도출되는 칸 — 예: 지역요건이 모든 정책 필수 메타면 그 칸 — 은 채워져도 무방. 핵심 불변식은 "명단으로 못 재는 자격을 억지로 채우지 않음"이지 "모든 칸 공백"이 아니다. CRM 도그푸드에서 C07의 거주지요건='전국'은 이 완화로 정상 처리.)
  - 근거: `member_passes` 첫 줄 `if p["matchable"]=="N": return False`(L511), `synthesize_members`가 N 정책엔 경계 회원도 안 심음(L482–483), `main`의 targets에서 제외(L700). `load_policies`가 `matchable=N`인데 소득값이 채워졌으면 **fail-loud**(L195–198, 자기모순 차단). grade는 N 정책 추천을 무결성 위반으로 탐지(L120–125,163–172).
- [ ] **통제불가 함정은 통제값 우회 불가 시 폐기** — `datetime.now()`에 의존하는 함정(예 신청 마감 N주 필터)은 G10과 모순 → 매칭에서 완전 제거. "신청 날짜는 보지 않는다 — 자격만 본다"를 6문서·코드·안내시트에 일관 선언.
  - 근거: `apply_start`/`apply_end`는 CSV에 남되 매칭/채점에 미사용(docstring L27–29), ASSIGN_DATE는 오직 만나이 계산에만 사용. 안내시트 "★날짜 안 봄"(L605). 옛 '마감 2주 필터' 폐기, 그 배점을 Part1 추출 50으로 흡수(grade L136).

## 5.3 의도된 결함 카탈로그 (B1~B8) — 각 함정 = 측정 의도 + 결정성 유지법

함정을 심되, 각 함정이 (a) 무엇을 변별하는지와 (b) 그래도 정답이 단일하게 유지되는 이유를 함께 명시한다. 비매칭 도메인이면 해당 함정을 같은 구조로 치환(예 소득→금액, 지역→코드 계층).

- [ ] **B1 경계값(나이) ±1** — `age_min-1 / min / max / max+1` 자동 삽입(`plant_boundaries` A, L417–426).
  - 측정: 양끝 포함(`<=`,`>=`) 정확 처리. / 결정성: 정수 나이라 한 칸씩만 갈리고 모호 없음(`member_passes` L514–517).
- [ ] **B2 만나이 미경과** — 7–12월생을 만나이=target으로 생성(`birth_unpassed` L241–245, plant A' L428–434).
  - 측정: "출생연도 빼기"로 풀면 ±1 오답(미경과 생일 누락/오발송). / 결정성: 6/28 당일 생일 배제로 모호 0, `manage`(L227–232)가 유일 정답.
- [ ] **B3 소득 경계** — `income_max` / `income_max+1`(월), `income_year_max` / `+1`(연), `<=` 규칙(plant B L436–439·H L464–467).
  - 측정: 상한 같으면 통과(`<=`) 정확 처리 + 빈칸=무관 vs 0=상한0원 구분. / 결정성: `is not None` 가드로 미지정 축은 미적용(L526·528).
- [ ] **B4 지역 표기 불일치** — `서울특별시 관악구 봉천동`/`서울 관악구`/`서울시 관악구`/`관악구 신림동` 변형(`seoul_addr` L254–262).
  - 측정: 정규화 후 시도∧자치구 포함관계 판정. / 결정성: `detect_sido`(비서울 우선) → `detect_gu` 우선순위가 결정적(L113–166), 전국/시도/시도+구 3형식만 허용.
- [ ] **B5 빈 자격 칸 = 무관** — 임의 기본값 주입(0·"무관" 글자)을 처벌.
  - 측정: 빈칸을 0이나 "해당없음"으로 채우면 오답. / 결정성: `norm_constraint`가 동치 흡수하되 빈칸≠0은 `norm_int`로 보존(grade L33·45).
- [ ] **B6 판별불가(`matchable=N`)** — 자격 맞아 보여도 명단으로 확인 불가하면 추천 금지.
  - 측정: 현업의 신중함(무리한 오발송 억제). / 결정성: 운영 플래그로 0건 강제(5.2 두번째 항목과 동일 근거), 정답은 "아무에게도 추천 안 함"으로 유일.
- [ ] **B7 멀티모달 OCR** — 실제 포스터 PDF/PNG는 운영자가 `data/policies/`에 배치(코드 미생성, build L15–16·L49).
  - 측정: 이미지에서 자격값 일관 추출. / 결정성: 추출 대상값이 전부 `policies.csv`에 있어 채점은 OCR이 아닌 csv 기준값 대조 → **난이도(추출)와 결정성(채점) 분리**.
- [ ] **B8 취업 예외조항** — "미취업만, 단 단기근로 허용" / "재직, 단기근로 허용" 같은 예외 포함 규칙.
  - 측정: 예외 조항을 빠뜨리지 않고 코딩. / 결정성: `member_passes`가 예외를 명시 집합으로 처리(미취업→{미취업,단기근로}, 재직→{재직,단기근로}, L520–523).

> 비매칭 아키타입(대사/집계/랭킹/퍼널)이면 B1~B8을 그 채점유형의 함정으로 치환한다: 경계(임계 ±1)·표기 불일치(키 정규화)·결측/중복(조인)·동점 규칙(랭킹)·허용오차 ε(집계). 단 "통제불가 함정은 폐기"(5.2-3) 원칙은 그대로.

## 5.4 이중 채점 분리 + 독립 재계산 + 적대 리뷰

- [ ] **이중 채점 분리** — 과정(채팅 로그 5역량 = 도메인 무관 공통 루브릭, 본 스킬 범위 밖)과 결과(제출 xlsx = 도메인별 결정적)를 분리. `evaluation.md`는 결과만 다룬다. B1~B8 함정을 *검증 안 하면 결과 점수가 떨어지게* 심어 과정·결과가 상호 강화되게 한다.
  - 근거: `_5 §6.1`(두 점수 구조), grade.py는 결과만 채점.
- [ ] **독립 재계산 통과** — `verify/independent_recompute.md` 절차로 `build_dataset.py` 로직을 **재사용하지 않고** `policies.csv`+명시 규칙만으로 정답을 재산출 → `*_answer.xlsx`와 셀 단위 대조(extra/missing 0건). 불일치 = 발행 차단.
  - 이유: 같은 버그가 생성·채점 양쪽에 있으면 자기충족 채점이 못 잡는다 → 독립 구현 필수.
- [ ] **적대 리뷰 결함 0** — `verify/adversarial_prompts.md`를 `/codex` 또는 `code-reviewer`에 던져(빈 region 무음 통과? matchable=N에 소득값? seed/기준일 누락? fail-loud 빠짐? 축↔컬럼 누락? 결함과 채점 모순? 입력원≠정답? problem.md 정답 누설?) 지적된 결함을 0으로 만들고 수정 라운드를 완료.
  - 근거: `load_policies`의 fail-loud 가드들(L186–198)이 이 라운드의 산물.

## 발행 판정

위 5.1~5.4의 모든 체크박스가 PASS여야 발행한다. **하나라도 FAIL이면 발행 금지** — 결함을 고치고 5.1부터 다시 돈다. 저작과 검토는 분리한다(자기승인 금지): 빌드한 컨텍스트가 아닌 별도 컨텍스트/`code-reviewer`/`/codex`가 5.4의 독립 재계산·적대 리뷰를 수행한다.
